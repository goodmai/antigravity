Урок 4: Навыки Агента (Agent Skills)

Открытый стандарт для упаковки знаний и инструкций, которые агент Antigravity подгружает на лету. Скилл — это директория с одним обязательным файлом SKILL.md и опциональными скриптами, шаблонами и примерами.

1. Зачем нужны скиллы

Без скиллов агент использует только встроенные эвристики и контекст текущего диалога. Каждый раз вам приходится:

  • повторно объяснять конвенции проекта;
  • копировать длинные инструкции;
  • держать в голове последовательность шагов сложного процесса.

Скилл решает эту проблему: один раз описанный «способ работы» становится переиспользуемым активом — как функция в коде.

Без скилла Со скиллом
Длинный системный промпт в каждом диалоге Короткое описание + автоматическая активация
Знание живёт у одного разработчика Знание лежит в репозитории и версионируется
Нет тестируемости Скилл можно проверить через qa-skill-tester (урок 7)

2. Анатомия скилла

2.1. Где лежат скиллы

Расположение Область действия
<workspace>/.agent/skills/<name>/ Локально для проекта (коммитится в репозиторий команды)
~/.gemini/antigravity/skills/<name>/ Глобально для пользователя
skills/<name>/ в корне Antigravity Поставляются «из коробки» (см. урок 5)

2.2. Минимальная структура

.agent/skills/my-skill/
├── SKILL.md          # обязательный файл с инструкциями
├── scripts/          # вспомогательные исполняемые скрипты
├── examples/         # эталонные примеры результата
└── resources/        # шаблоны, JSON-схемы, ассеты

2.3. Frontmatter (YAML-заголовок)

---
name: pr-review
description: Делает структурированный ревью pull request по чек-листу команды. Применяется, когда пользователь просит «проверить PR», «сделать ревью» или передаёт ссылку на GitHub PR.
---
Поле Обязательно Назначение
name нет (по умолчанию — имя папки) Уникальный идентификатор kebab-case
description да Триггер для агента: что делает скилл и когда его применять

Important

Описание читается агентом первым. Если оно расплывчатое — скилл не активируется. Хорошее описание содержит: глагол действия, объект, ключевые слова-триггеры на языке пользователя.

3. Прогрессивное раскрытие

Агент работает по трёхфазной модели:

  1. Discovery — видит только имена и description всех скиллов.
  2. Activation — если описание совпадает с задачей, загружается полный SKILL.md.
  3. Execution — агент следует инструкциям, при необходимости подгружая файлы из scripts/ и resources/.

Это экономит контекстное окно: нерелевантные скиллы не занимают токены.

4. Дизайн качественного скилла

4.1. Один скилл — одна ответственность

Плохо Хорошо
dev-helper (всё подряд) pr-review, release-notes, migration-writer

4.2. Дерево решений внутри скилла

Если у скилла несколько режимов работы, добавьте секцию «Когда что делать»:

## Decision tree

- Пользователь просит «отревьюй» → запустить полный чек-лист.
- Пользователь прислал diff → анализировать только изменённые файлы.
- Пользователь указал риск-зону (security, perf) → углубить соответствующий раздел.

4.3. Скрипты как чёрные ящики

Если скилл содержит scripts/foo.py, в SKILL.md пишите:

Запусти `python scripts/foo.py --help` чтобы увидеть аргументы.
Не читай исходник целиком — он длинный.

Так агент экономит контекст.

4.4. Якоря на примеры

Ссылайтесь на файлы в examples/ через относительные пути — агент дочитает их при необходимости:

Используй формат из `examples/release-notes-2026-Q1.md`.

5. Пример: скилл pr-review

.agent/skills/pr-review/
├── SKILL.md
├── scripts/
│   └── extract_diff.py
├── examples/
│   ├── good-review.md
│   └── bad-review.md
└── resources/
    └── checklist.yaml

SKILL.md:

---
name: pr-review
description: Делает структурированный ревью pull request. Используется когда пользователь просит «проверить PR», «сделать review», передаёт ссылку на GitHub PR или прикладывает diff.
---

# PR Review

## Когда использовать
- Запросы вида: «отревьюй PR #123», «глянь мои изменения», ссылка на GitHub PR.

## Алгоритм
1. Получи diff: `python scripts/extract_diff.py --pr <url>`.
2. Прогони его по чек-листу из `resources/checklist.yaml`.
3. Сформируй отчёт по шаблону из `examples/good-review.md`.

## Что НЕ делать
- Не комментируй стилистические правки, если в проекте есть форматтер.
- Не предлагай рефакторинг вне scope PR.

6. Жизненный цикл скилла

draft → test → publish → maintain → deprecate
  • draft — лежит локально в .agent/skills/, описание помечено [WIP].
  • test — проверен через qa-skill-tester (урок 7) на 3+ кейсах.
  • publish — описание финализировано, PR в репозиторий команды.
  • maintain — версия и changelog в комментарии SKILL.md.
  • deprecate — в description добавлено [DEPRECATED — use X instead].

7. Анти-паттерны

Анти-паттерн Симптом Что делать
God-skill SKILL.md > 500 строк, описывает 10 разных задач Разбить на 3–5 узких скиллов
Magic-skill Описание «помогает с кодом» — слишком общее Указать триггеры и предметную область
Stale-skill Ссылается на удалённые файлы/команды Добавить smoke-test в CI
Silent-skill Не активируется, потому что описание на английском, а пользователь пишет на русском Перечислить триггеры на обоих языках

8. Практические задания

Каждое задание выполняется в репозитории-песочнице. После выполнения сделайте коммит с префиксом lesson-4: task-N.

Задание 1 — Hello-skill

Создайте скилл hello-author в .agent/skills/hello-author/. Frontmatter: name, description («Здоровается с автором проекта, используя имя из package.json поля author»). Тело — 3 шага алгоритма. Проверка: запросите у агента «поприветствуй меня» — он должен прочитать package.json и обратиться по имени.

Задание 2 — Decision tree

Расширьте hello-author: добавьте секцию «Decision tree» с тремя ветками — если автор не указан, если указана организация, если указан email. Проверка: уберите поле author из package.json — агент должен пойти по соответствующей ветке.

Задание 3 — Скрипт как чёрный ящик

Добавьте scripts/whoami.py, который выводит имя автора в stdout. В SKILL.md укажите: «не читай исходник, запусти python scripts/whoami.py --help». Реализуйте флаг --help. Проверка: попросите агента «расскажи, что делает scripts/whoami.py» — он должен ответить по --help, а не процитировать код.

Задание 4 — Описание-триггер

Создайте второй скилл release-notes-ru с описанием на русском, содержащим триггеры: «релиз-ноуты», «changelog», «что нового». В одном диалоге попросите «составь changelog по последним коммитам» — должен активироваться именно этот скилл, а не общий помощник.

Задание 5 — Examples-якорь

Создайте release-notes-ru/examples/v1.2.0.md с эталонным форматом (Added / Changed / Fixed). В SKILL.md сошлитесь на него фразой «используй формат из examples/v1.2.0.md». Проверка: сгенерированные релиз-ноуты должны повторять структуру эталона.

Задание 6 — Глобальный vs локальный

Скопируйте hello-author в ~/.gemini/antigravity/skills/hello-author/ (глобально) и оставьте версию в .agent/skills/ (локально). В локальной версии измените приветствие. Проверка: в проекте агент должен использовать локальную версию (она имеет приоритет), в другом проекте — глобальную.

Задание 7 — Анти-паттерн → рефакторинг

Намеренно создайте «god-skill» dev-helper с описанием «помогает разработчику с любыми задачами». Запросите у агента три разных задачи (форматирование, ревью, документация). Зафиксируйте, что скилл активируется хаотично. Разбейте его на три узких скилла с конкретными триггерами. Опишите в index.html песочницы: что изменилось в поведении агента и почему.
