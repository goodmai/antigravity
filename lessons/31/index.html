🔒 Rootless Docker

Безопасность

По умолчанию Docker-демон работает с правами root. Если злоумышленник вырывается из контейнера — он получает root на хосте. Rootless-режим запускает демон внутри пространства имён пользователя: компрометация контейнера не даёт доступ к системе. 

# Установить rootless-инструменты
dockerd-rootless-setuptool.sh install

# Добавить в ~/.bashrc
export DOCKER_HOST=unix://${XDG_RUNTIME_DIR}/docker.sock

# Проверить
docker info | grep -i rootless   # rootless: true
ФункцияОбычный DockerRootless
Публикация порта < 1024✅❌ (нужен sysctl)
overlay2 storage driver✅✅ (ядро ≥ 5.11)
Docker-in-Docker✅⚠️
GPU passthrough✅✅ (через --device)
💡 В rootless-режиме обязательно добавьте USER nonroot в Dockerfile — процесс внутри контейнера также не будет root.

📦 Multi-stage builds и минимальный образ

Используйте многоступенчатую сборку: первый stage компилирует, второй содержит только рантайм. Distroless-образ не имеет shell — attack surface минимален. 

# Stage 1: сборка
FROM golang:1.22-alpine AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o server .

# Stage 2: только бинарник
FROM gcr.io/distroless/static-debian12
COPY --from=builder /app/server /server
USER nonroot:nonroot
ENTRYPOINT ["/server"]

🐳 Публикация в Docker Hub

Реестр 
# Аутентификация через Access Token (не пароль!)
docker login -u <username>

# Тегирование
docker tag myapp:1.0.0 myusername/myapp:1.0.0
docker tag myapp:1.0.0 myusername/myapp:latest

# Пуш
docker push myusername/myapp:1.0.0
docker push myusername/myapp:latest
⚠️ Никогда не используйте только тег latest. Без версионного тега невозможно откатиться к предыдущему образу.

🐙 GitHub Container Registry (GHCR)

Реестр

GHCR хранит образы рядом с кодом на GitHub. Поддерживает гранулярные права (read, write, admin) на уровне пакета. 

# Аутентификация — GITHUB_TOKEN генерируется автоматически в Actions
echo $GITHUB_TOKEN | docker login ghcr.io -u $GITHUB_ACTOR --password-stdin

# Формат тега: ghcr.io/<owner>/<repo>:<tag>
docker build -t ghcr.io/myorg/myapp:1.0.0 .
docker push ghcr.io/myorg/myapp:1.0.0

🏗️ Мультиархитектурные образы (buildx)

Multi-arch

Один тег — для linux/amd64 и linux/arm64. Образ работает и на x86-сервере, и на Apple M-чипах, и на Raspberry Pi. 

# Создать builder с поддержкой эмуляции
docker buildx create --name multiarch --driver docker-container --use
docker buildx inspect --bootstrap

# Собрать и сразу запушить для двух платформ
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  --tag ghcr.io/myorg/myapp:1.0.0 \
  --push \
  .

# Проверить манифест
docker buildx imagetools inspect ghcr.io/myorg/myapp:1.0.0

⚙️ GitHub Actions — полный пайплайн

CI/CD 
# .github/workflows/docker.yml
name: Docker Build & Push

on:
  push:
    branches: [main]
    tags: ["v*"]

permissions:
  contents: read
  packages: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Extract metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ghcr.io/${{ github.repository }}
          tags: |
            type=semver,pattern={{version}}
            type=sha,prefix=sha-

      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          context: .
          platforms: linux/amd64,linux/arm64
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

      - name: Scan with Trivy
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: ghcr.io/${{ github.repository }}:${{ steps.meta.outputs.version }}
          format: sarif
          output: trivy-results.sarif
          severity: CRITICAL,HIGH

      - name: Upload SARIF to Security tab
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: trivy-results.sarif

🔑 BuildKit secrets — без утечки токенов

Безопасность 
# Dockerfile
# syntax=docker/dockerfile:1
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./

# Секрет доступен только во время RUN, не попадает в образ
RUN --mount=type=secret,id=npmrc,target=/root/.npmrc \
    npm ci

COPY . .
CMD ["node", "server.js"]
# Сборка с секретом
docker build --secret id=npmrc,src=$HOME/.npmrc -t myapp .
⚠️ Никогда не передавайте секреты через ARG или ENV — они видны в docker history и в слоях образа.

📝 Практические задания

Артефакты — в artifacts/lesson-31/.
  1. Rootless setup — включите rootless Docker. Убедитесь, что docker run hello-world работает без sudo. Зафиксируйте вывод docker info | grep -A5 Security.
  2. Multi-stage Dockerfile — напишите multi-stage Dockerfile для своего приложения на distroless или alpine. Измерьте разницу в размере (docker images).
  3. Docker Hub push — запушите образ с тегами v1.0.0 и latest. Убедитесь, что он доступен публично.
  4. GHCR через GitHub Actions — создайте workflow docker.yml, который при пуше в main собирает образ и пушит в GHCR.
  5. Multiarch — добавьте поддержку linux/amd64,linux/arm64. Проверьте через imagetools inspect.
  6. Сканирование — добавьте шаг Trivy в pipeline. Загрузите SARIF-отчёт в Security → Code scanning.
  7. BuildKit secrets — перепишите зависимость с приватным токеном через --mount=type=secret. Убедитесь, что docker history не содержит токена.

Definition of Done

  • Rootless-режим включён, docker info показывает rootless: true.
  • Образ собран через multi-stage и запушен в Docker Hub с тегом v1.0.0.
  • Тот же образ запушен в GHCR через GitHub Actions.
  • Multiarch-манифест содержит linux/amd64 и linux/arm64.
  • Trivy не нашёл CRITICAL CVE в образе.
  • Dockerfile использует USER nonroot и не хранит секреты в слоях.
