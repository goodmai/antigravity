# Урок 12: Автоматизация тестирования с Playwright

Antigravity поднимает QA на новый уровень, позволяя агентам не только запускать, но и **писать** и **чинить** E2E тесты. См. [Урок 9](../9/README.md) про использование браузера агентом.

---

## 🎭 Playwright + AI

Вам больше не нужно вручную искать селекторы элементов.
Агент:

1.  Сканирует страницу.
2.  Генерирует код на TypeScript/JS.
3.  Запускает Playwright (headless или с UI).

---

## 🩹 Self-Healing Tests (Самовосстановление)

Это "киллер-фича" Antigravity.
Если тест упал (Red Build):

1.  Агент читает лог ошибки.
2.  Агент видит скриншот падения.
3.  Агент **автоматически правит код теста** (например, обновляет изменившийся селектор) и перезапускает его.

Цикл повторяется, пока тест не станет зеленым.

## 🏗️ Экспорт сценариев

Тесты, созданные агентом, не исчезают. Вы можете экспортировать их в кодовую базу.
Агент оформит их по стандарту:

- Page Object Model.
- Фикстуры.
- Комментарии.

## 📝 Задание

1.  Создайте файл `tests/example.spec.ts`.
2.  Попросите агента: _"Напиши тест для google.com, который проверяет, что при поиске 'Antigravity' в выдаче есть ссылка на официальный сайт"_.
3.  Запустите тест и попросите агента "сломать" его (изменить ожидаемый текст), а затем "починить".


## 🔬 Как это работает глубже

Цикл self-healing — это замкнутая петля обратной связи:

```
запуск теста → 🔴 падение
   ├─ читает лог (ошибка, стек)
   ├─ читает скриншот/trace момента падения
   ├─ ставит диагноз (селектор изменился? тайминг? текст?)
   ├─ правит код теста
   └─ перезапуск ──▶ 🟢 / повтор (лимит N попыток)
```

Ключевой нюанс: **лимит попыток обязателен**. Без него агент может
зациклиться, «чиня» тест под сломанное приложение. Правильная цель —
отличить дефект теста (обновился селектор) от дефекта продукта
(сломалась логика): второе чинить в коде, а не в тесте.

Экспортируемые тесты оформляются по **Page Object Model**: локаторы и
действия страницы вынесены из спеки, что делает self-healing точечным —
правка происходит в одном Page Object, а не в десятке спек.

## ⚠️ Типичные ошибки

- **Self-healing маскирует баг продукта.** Если тест «чинится» под
  изменившееся поведение — это регресс, а не флака.
- **Нет лимита итераций** → бесконечный цикл правок.
- **Хрупкие локаторы** (`div > div:nth-child(3)`) ломаются от любой правки;
  используй роли/тексты/`data-testid`.
- **Игнор trace.** Playwright trace показывает точный момент падения —
  это быстрее, чем гадать по логу.

## 🧠 Ключевые концепции

- **Self-healing** — авто-диагностика и починка по логу+скриншоту.
- **Page Object Model** — изоляция логики страницы от спек.
- **Trace/artifacts** — воспроизводимая диагностика падения.
- **Дефект теста vs дефект продукта** — разные стратегии починки.
