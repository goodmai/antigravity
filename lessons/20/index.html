Промпт-инжиниринг для агентов Antigravity

Качество результата агента напрямую зависит от того, насколько точно и структурированно сформулирована задача. В этом уроке разбираем техники, которые работают именно в контексте Antigravity: от фреймворков для одного запроса до шаблонов целых Workflows.

CO-STAR: Структурированный промпт

Фреймворк CO-STAR устраняет неоднозначность, разбивая запрос на шесть чётких компонентов:

Компонент Описание Пример
Context Фоновая информация «FastAPI-сервис с JWT, PostgreSQL»
Objective Точная задача «Напиши unit-тест для /auth/refresh»
Style Стиль реализации «pytest fixtures, без unittest.mock»
Tone Тональность вывода «Только код, без объяснений»
Audience Целевая аудитория «Senior Python developer»
Response Формат ответа «Один файл test_auth.py»

Применение в SKILL.md

CO-STAR особенно эффективен в описании навыков — он становится постоянной инструкцией для каждого вызова:

---
name: api-test-generator
description: >
  Контекст: проект на FastAPI, Pydantic V2, async/await, PostgreSQL.
  Задача: генерировать pytest-тесты для указанных endpoints.
  Стиль: fixtures в conftest.py, AAA-паттерн (Arrange/Act/Assert).
  Формат: только код теста, без комментариев.
---

Chain-of-Thought: Пошаговое рассуждение

Явная просьба «думать вслух» повышает качество на сложных задачах:

Задача: спроектируй схему БД для мессенджера.

Рассуждай пошагово:
1. Определи основные сущности (User, Message, Chat, Media)
2. Выяви связи и кардинальность
3. Подумай об индексах для частых запросов
4. Учти масштабирование до 1M пользователей
5. Только после этого выдай SQL DDL

В Antigravity это встраивается в Workflow через явные паузы с артефактом на ревью между шагами.

Few-Shot: Пример как стандарт

Один пример в начале инструкции задаёт точный формат вывода:

## Пример входа:
def get_user(id: int): ...

## Пример выхода:
async def test_get_user_success(client, db_session):
    user = await create_test_user(db_session)
    response = await client.get(f"/users/{user.id}")
    assert response.status_code == 200
    assert response.json()["id"] == user.id

## Теперь сгенерируй тест для:
def delete_order(order_id: int, user_id: int): ...

Агент извлекает паттерн из примера: async, create_test_*, assert status + body.

Role Prompting: Специализация агента

Явная роль сужает пространство поведений модели и активирует нужный стиль мышления:

Ты — Senior Security Engineer с 10 годами опыта в pentesting.
Проведи code review на предмет OWASP Top 10.
Формат: таблица [Уязвимость | Строка | Severity | Рекомендация].

В Antigravity роли прописываются в .agent/rules/ для постоянной активации без повторного указания:

<!-- .agent/rules/security-reviewer.md -->
---
trigger: always
---
При каждом code review проверяй: SQL-инъекции, XSS, IDOR, небезопасные зависимости (OWASP Top 10).

Мета-промптинг: Агент пишет промпты для себя

Antigravity умеет генерировать собственные SKILL.md — используй это для создания новых навыков:

Создай SKILL.md для навыка, который:
- Генерирует OpenAPI 3.0 спецификацию из FastAPI кода
- Учитывает JWT security schemes и Pydantic V2 схемы
- Выдаёт YAML без лишних объяснений

Используй CO-STAR структуру в поле description.

Управление фокусом через промпт

Явно ограничивай область внимания агента — это дешевле полного .antigravityignore:

Работай только с файлами в src/api/.
Игнорируй tests/, docs/, migrations/.
При ссылках на модели используй только src/models/schemas.py.

Шаблон промпта для Workflow

// workflow: feature-implementation

## Контекст
@/src/api/routes.py
@/.agent/rules/coding-standards.md

## Задача
Реализуй: {FEATURE_DESCRIPTION}

## Критерии готовности
- [ ] Unit-тесты: happy path + edge cases
- [ ] Нет изменений в несвязанных файлах
- [ ] Pydantic V2 для всех входных данных

## Шаги
1. Проанализируй @/src/api/ → артефакт с планом на ревью
2. После апрува — реализуй
3. Напиши тесты
4. Проверь критерии

Типичные ошибки

Ошибка Плохо Хорошо
Размытая задача «Улучши код» «Перепиши X используя async/await»
Нет формата «Объясни архитектуру» «Нарисуй Mermaid C4-диаграмму»
Перегруженность 10 задач в одном промпте 1 задача → артефакт → следующая
Нет контекста «Добавь кеширование» «Добавь Redis кеш для GET /products, TTL 5 мин»
Нет критериев «Сделай хорошо» «Done when: тесты зелёные, coverage > 80%»

Практика

Возьми любой Workflow из .agent/workflows/ и улучши его:

  1. Добавь CO-STAR структуру в заголовок
  2. Добавь few-shot пример ожидаемого результата
  3. Пропиши явные критерии готовности
  4. Назначь роль агенту через trigger: always правило
