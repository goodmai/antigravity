## 🔬 Как это работает глубже

В App Router компоненты по умолчанию **серверные** (Server Components):
рендерятся на сервере, не тащат JS на клиент, имеют прямой доступ к данным.
`"use client"` нужен только там, где есть состояние/эффекты/обработчики.

**Hydration error** возникает, когда серверный HTML не совпадает с первым
клиентским рендером:

```
сервер: <span>—</span>      клиент: <span>14:32</span>   → mismatch
причина: Date.now()/random/локаль в рендере без защиты
фикс: useEffect для клиент-специфичного, либо suppressHydrationWarning
```

Понимание границы server/client — главный навык для Next.js: лишний
`"use client"` раздувает бандл, его отсутствие ломает интерактив.

## ⚠️ Типичные ошибки

- **`"use client"` на всё подряд** — теряется выгода серверных компонентов.
- **`Date.now()`/`Math.random()` в рендере** — hydration mismatch.
- **Фетч на клиенте там, где можно на сервере** — лишний водопад запросов.
- **Нет `loading.tsx`/`error.tsx`** — пустой экран при загрузке/ошибке.

## 🧠 Ключевые концепции

- **Server vs Client Components** — где исполняется код.
- **Hydration** — согласование серверного и клиентского рендера.
- **App Router** — файловая маршрутизация и спец-файлы состояний.
- **a11y/адаптивность** — доступный UI «из коробки».
