# Урок 16: Мобильная разработка

Antigravity — отличный напарник для мобильной разработки, поддерживающий как Flutter, так и React Native.

---

## 💙 Flutter

Благодаря "родству" с Google, поддержка Dart работает идеально.

- **Генерация UI**: Агент пишет виджеты по скриншотам макетов.
- **State Management**: Реализует логику на Provider, Riverpod или BLoC.
- **Hot Reload Loop**: Агент следит за логами `flutter run` и правит ошибки "на лету".

---

## ⚛️ React Native & Expo

Для React Native агент предпочитает **Expo**.

- Агент берет на себя сложную настройку окружения.
- Навигация через Expo Router.
- Интеграция нативных модулей.

Кейс: Разработчики создают MVP приложений за один вечер, используя Antigravity для кода и Expo Go для теста на телефоне.

## 🔬 Как это работает глубже

Сила агента в мобильной разработке — **петля hot-reload**:

```
правка кода → flutter run / expo подхватывает →
агент читает лог рантайма → видит ошибку → правит → повтор
```

Агент не пересобирает приложение с нуля, а реагирует на лог `flutter run`
/ Metro в реальном времени — это резко сокращает цикл «ошибка → фикс».

Выбор стека влияет на стратегию: Flutter (Dart) даёт единый рендер и
предсказуемый UI; React Native + **Expo** снимает боль нативной настройки
окружения (агент предпочитает Expo именно поэтому).

## ⚠️ Типичные ошибки

- **State в виджете вместо state-management** — UI рассыпается при росте.
- **Игнор адаптивности** — вёрстка ломается на других разрешениях.
- **Bare React Native без Expo** — лишняя боль с нативным окружением для MVP.
- **Нет валидации формы** — «экран логина» без обработки ошибок ввода.

## 🧠 Ключевые концепции

- **Hot-reload loop** — агент чинит по живому логу рантайма.
- **State management** (Provider/Riverpod/BLoC, hooks) — управляемое состояние.
- **Expo** — упрощённое окружение для React Native.
- **Адаптивность** — корректная вёрстка на разных экранах.
