Урок 15: CI/CD Pipeline Generation

Автоматизация доставки кода — финальный аккорд инженерии. Antigravity умеет генерировать пайплайны для GitHub Actions, GitLab CI и Cloud Build. Тесно связано с Уроком 12 (Тесты) и Уроком 14 (Docker).

🔁 Генерация пайплайнов

Агент знает синтаксис YAML и лучшие практики CI/CD.

Сценарий: "Настрой CI пайплайн для проверки PR". Агент создаст .github/workflows/pr-check.yml с шагами:

  1. Checkout: Клонирование репозитория.
  2. Setup: Установка Node.js/Python/Go с кэшированием зависимостей.
  3. Lint & Test: Запуск проверок.
  4. Reporting: Отправка отчетов о покрытии (Codecov).

🔐 Keyless Security

Для Google Cloud Build агент настроит Workload Identity Federation. Это современный стандарт безопасности, который позволяет аутентифицироваться в облаке без хранения долгоживущих ключей JSON в секретах GitHub.

📝 Задание

  1. Попросите агента: "Создай GitHub Action для запуска тестов при каждом пуше в ветку main".
  2. Изучите созданный файл .github/workflows.

🔬 Как это работает глубже

Хороший пайплайн оптимизирован по трём осям:

Ось Приём Эффект
Скорость кэш зависимостей по hash(lock) минуты → секунды
Надёжность matrix по версиям рантайма ловит «работает у меня»
Безопасность OIDC вместо ключей нет долгоживущих секретов

Keyless-деплой (как в Уроке 13): GitHub Actions получает короткоживущий OIDC-токен и обменивает его на облачные креды. В секретах репозитория не лежит ни одного постоянного ключа.

Гейты ветки: required status checks блокируют merge, пока CI красный — это превращает пайплайн из «информера» в реальный барьер качества.

⚠️ Типичные ошибки

  • Кэш без привязки к lock-файлу — устаревший кэш ломает сборку.
  • Долгоживущие ключи в Secrets вместо OIDC.
  • CI без required checks — красный билд всё равно мёржится.
  • Тесты только на одной версии рантайма — скрытые несовместимости.
  • Секреты в логах (echo $TOKEN) — утечка в публичных логах.

🧠 Ключевые концепции

  • Кэширование по lock-хэшу — детерминированное ускорение.
  • Matrix-сборки — покрытие версий рантайма.
  • OIDC / keyless deploy — аутентификация без хранения ключей.
  • Required checks — пайплайн как барьер мёржа.

🧪 Практика

Собери пайплайн в Лабе 15 — CI/CD генерация пайплайнов (7 задач): PR-проверка, кэш, matrix, покрытие, keyless-деплой, гейты ветки, релизный workflow.
