Урок 1: Режимы агента Antigravity

Введение

Antigravity - это продвинутый ИИ-агент, который предоставляет несколько режимов работы для разных сценариев и задач. В этом уроке мы разберемся, как режимы работают и когда их использовать.

Режимы диалога (Conversation-Level Modes)

При начале нового диалога вы можете выбрать один из режимов:

1. Planning (Планирование)

Назначение: Глубокое исследование и планирование сложных задач.

  • Агент планирует действия перед выполнением
  • Создает implementation_plan.md с пошаговым плана
  • Требует вашего согласия перед выполнением
  • Идеален для проектов, где важна качество над скоростью
  • Используется для совместной работы и обсуждения подходов

Когда использовать:

  • Архитектурные решения для нового проекта
  • Рефакторинг сложных систем
  • Интеграция новых технологий
  • Работа над критичными компонентами

2. Fast (Быстрый)

Назначение: Быстрое выполнение простых задач.

  • Агент выполняет задачи напрямую без подробного планирования
  • Используется для простых задач (переименование переменных, запуск команд)
  • Полезно, когда важна скорость
  • Снижает время выполнения благодаря пропуску этапа планирования

Когда использовать:

  • Быстрые исправления багов
  • Простой рефакторинг
  • Генерация бойлерплейта кода
  • Автоматизация рутинных задач

Указания для ИИ (Rules for AI)

Вы можете настраивать поведение агента через два уровня правил:

Глобальные правила (Global Rules)

  • Расположение: ~/.claude/CLAUDE.md
  • Применяются: Ко всем вашим рабочим пространствам (workspaces)
  • Примеры:
    • "Всегда отвечай на русском языке"
    • "Соблюдай стиль Google Style Guide"
    • "Используй только функциональное программирование"
    • "Всегда напиши тесты перед кодом"

Агент автоматически учитывает эти правила при работе в любом проекте.

Правила рабочего пространства (Workspace Rules)

  • Расположение: Папка .agent/rules в корне проекта
  • Для каждого правила можно настроить активацию:
    • Manual: Активируется вручную через упоминание @ в строке ввода (например, @typescript-style)
    • Always On: Правило применяется всегда
    • Model Decision: Модель сама решает, применять ли правило
    • Glob: Правило применяется к файлам по маске (например, *.js или src/**/*.ts)

Агент комбинирует глобальные и локальные правила, где локальные имеют более высокий приоритет.

Настройки агента (Settings)

Настройки, общие для всех диалогов, находятся на вкладке "Agent" в панели настроек.

Artifact Review Policy (Политика проверки артефактов)

Always Proceed (Всегда продолжать)

  • Агент никогда не запрашивает проверку
  • Быстрое выполнение
  • Может привести к ошибкам без вашего контроля

Request Review (Запрашивать проверку) - Рекомендуется

  • Агент всегда спрашивает разрешение перед основными изменениями
  • Позволяет вам изучить план и добавить комментарии
  • Гарантирует контроль над процессом

Terminal Command Auto Execution (Авто-выполнение команд)

Request Review: Никогда не выполнять команды автоматически

  • Безопаснее всего
  • Требует вашего подтверждения каждый раз
  • Идеально для новых проектов

Always Proceed: Никогда не спрашивать

  • Быстрее, но рискованнее
  • Может привести к случайному удалению файлов
  • Используйте только если полностью доверяете агенту

Списки разрешенных (Allow list) и запрещенных (Deny list) настраиваются в той же вкладке "Agent".

Agent Non-Workspace File Access (Доступ к внешним файлам)

  • По умолчанию агент имеет доступ только к файлам в воркспейсе
  • Используйте с осторожностью, чтобы не раскрыть секретные данные
  • Включайте только когда необходимо

Внутренние режимы Agentic Mode

Внутри агентного режима работа делится на три фазы:

1. PLANNING (Планирование)

  • Анализ требования
  • Создание implementation_plan.md
  • Согласование плана с пользователем
  • Выявление потенциальных проблем

2. EXECUTION (Выполнение)

  • Написание кода
  • Создание файлов
  • Выполнение команд терминала
  • Интеграция с существующим кодом

3. VERIFICATION (Проверка)

  • Запуск тестов
  • Проверка работоспособности
  • Создание walkthrough.md (отчета о проделанной работе)
  • Убедитесь, что все требования выполнены

Как переключать режимы?

Агент самостоятельно управляет переключением внутренних режимов, но вы можете направлять его:

  • Чтобы начать планирование: Попросите составить план действий ("Make a plan for...")
  • Чтобы перейти к выполнению: Дайте команду на реализацию ("Go ahead", "Execute the plan")
  • Чтобы запустить проверку: Попросите протестировать результат ("Verify the changes")

Практическое задание

  1. Режим Planning: Попросите агента создать план для написания простого "Hello World" на Python. Обратите внимание, как агент перейдет в режим PLANNING.

  2. Утверждение плана: Утвердите план. Агент перейдет в EXECUTION.

  3. Проверка: Попросите проверить работу скрипта. Агент перейдет в VERIFICATION.

  4. Проверка приоритета правил: Создайте в текущем воркспейсе правило (Workspace Rule) в папке .agent/rules/, которое велит агенту отвечать на испанском. Затем поздоровайтесь с агентом. На каком языке он ответит, если в Глобальных правилах (Global Rules) у вас стоит русский? Это поможет понять, какой уровень правил имеет более высокий приоритет.

  5. Режим Fast: Попросите агента в режиме Fast переименовать переменную temp_var на temporary_variable во всех файлах проекта. Заметьте разницу в скорости выполнения.

Отключение правил

Для выключения локального правила в Antigravity без потери наработанного контента, откройте соответствующий файл в .agent/rules и обновите секцию метаданных с trigger: disabled.

Ключевые концепции

  • Режимы диалога — выбор между качеством (Planning) и скоростью (Fast)
  • Глобальные правила — определяют поведение агента во всех проектах
  • Локальные правила — специфичны для конкретного проекта
  • Фазы агентного цикла — Planning → Execution → Verification
  • Контроль над агентом — Review Policy и Auto Execution настройки
