Lesson 21: Advanced Patterns

This final lesson covers patterns used by teams running Claude Code at scale: multi-repo architectures, custom MCP tool servers, enterprise access control, and a capstone challenge to validate everything you've learned.

Architectural Audit with Claude Code

Claude Code can act as a continuous automated architect and security auditor — scanning an entire codebase and surfacing structural problems that accumulate silently over time.

SOLID Principle Auditing

Ask Claude to check your codebase for SOLID violations. It excels at finding "God Objects" — classes or modules with too many responsibilities that violate the Single Responsibility Principle. It can propose decomposition into loosely-coupled services, and it checks Open-Closed and Dependency Inversion violations, identifying tight coupling that hampers scaling and testing.

Code Quality Audit

Beyond SOLID, Claude checks naming conventions, identifies overly complex or redundant logic, and evaluates readability. It proposes improvements that make code self-documenting without changing observable behavior.

Error Handling & Resilience Audit

Claude finds code where exceptions are caught but the root cause is hidden — the classic "swallowing the root cause" antipattern. It also detects missing global error handlers, missing retry logic for unreliable external APIs, and missing Circuit Breaker patterns that prevent cascading failures in distributed systems. It can autonomously implement these patterns by wrapping network calls in safe adapters.

Test Coverage Audit

Claude analyzes the codebase for "blind spots" — logical branches and critical paths not covered by tests. It integrates with pytest + coverage.py to generate hundreds of unit and integration tests. If tests fail on first run, Claude enters a debug loop: reads the error, determines whether it's a bad test or a real bug, fixes it, and iterates until all tests are green.

Key best practice: always give Claude a feedback loop — let it run tests itself. Model performance multiplies when it can verify its own work.

Trigger an audit with a prompt like:

> Audit this codebase for SOLID violations.
> For each violation: identify the file, explain which principle is broken,
> and propose a decomposition strategy.
> Start with the service layer in src/services/.

Multi-Repo Agent Architecture

Large engineering organizations often have dozens of microservices. Claude Code agents can coordinate across them:

// Orchestrator agent
const [apiChanges, sdkChanges, docsChanges] = await Promise.all([
  runAgent('Update API endpoint in api-service repo', { cwd: './api-service' }),
  runAgent('Update SDK types to match new API', { cwd: './sdk' }),
  runAgent('Update API docs to reflect changes', { cwd: './docs' }),
]);
await runAgent(`Create a PR summarizing these coordinated changes: ${[apiChanges, sdkChanges, docsChanges].join('
')}`);

Custom MCP Tool Servers

Build your own MCP server to expose internal tools:

import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';

const server = new Server({ name: 'internal-tools', version: '1.0.0' });

server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [{
    name: 'deploy',
    description: 'Deploy a service to staging',
    inputSchema: { type: 'object', properties: { service: { type: 'string' } } }
  }]
}));

server.setRequestHandler(CallToolRequestSchema, async (req) => {
  const { service } = req.params.arguments;
  const result = await deployService(service);
  return { content: [{ type: 'text', text: result }] };
});

Enterprise Access Control

  • Use team-shared settings.json committed to the repo for consistent permissions
  • Restrict Claude's API key to a specific set of allowed models via Anthropic Workspaces
  • Audit logs via PostToolUse hooks forwarded to your SIEM
  • Integrate with SSO/LDAP for API key provisioning

Practical Exercises

Complete all three tasks to lock in the advanced patterns from this lesson before tackling the capstone:

  1. Custom MCP server. Build a minimal MCP server exposing one tool (e.g., deploy_staging(service) that prints a message and returns a fake deployment ID). Register it in your Claude Code settings and invoke it from a session. Confirm the tool appears in /mcp and that input/output flow correctly.
  2. Multi-repo orchestrator. Set up three small local repos (api, sdk, docs). Write an orchestrator that runs Claude in each via the SDK with cwd pointing at the right repo, makes a coordinated change (bump a shared version string), and opens a PR in each. Verify the three PRs reference each other in their descriptions.
  3. Enterprise access pattern. Author a committed .claude/settings.json with team-wide deny rules (no production deploys, no force pushes, no kubectl delete), and a PostToolUse hook that forwards audit lines to a local file standing in for a SIEM. Walk a teammate (or rubber duck) through the configuration and confirm it would block the three most dangerous commands in your environment.

Capstone Challenge

Design and implement a production-ready Claude Code agent that:

  1. Accepts a GitHub repository URL as input
  2. Clones the repo and analyzes its structure
  3. Identifies the top 3 most critical security issues
  4. Creates a GitHub issue for each one with detailed remediation steps
  5. Sends a Slack summary to a channel via MCP
  6. Logs all actions with structured observability
  7. Handles errors gracefully with retry logic

This capstone covers all 21 lessons: tooling, permissions, MCP, git integration, subagents, context management, security, and production patterns.
