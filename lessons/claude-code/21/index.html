Lesson 21: Advanced Patterns

This final lesson covers patterns used by teams running Claude Code at scale: multi-repo architectures, custom MCP tool servers, enterprise access control, and a capstone challenge to validate everything you've learned.

Multi-Repo Agent Architecture

Large engineering organizations often have dozens of microservices. Claude Code agents can coordinate across them:

// Orchestrator agent
const [apiChanges, sdkChanges, docsChanges] = await Promise.all([
  runAgent('Update API endpoint in api-service repo', { cwd: './api-service' }),
  runAgent('Update SDK types to match new API', { cwd: './sdk' }),
  runAgent('Update API docs to reflect changes', { cwd: './docs' }),
]);
await runAgent(`Create a PR summarizing these coordinated changes: ${[apiChanges, sdkChanges, docsChanges].join('
')}`);

Custom MCP Tool Servers

Build your own MCP server to expose internal tools:

import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';

const server = new Server({ name: 'internal-tools', version: '1.0.0' });

server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [{
    name: 'deploy',
    description: 'Deploy a service to staging',
    inputSchema: { type: 'object', properties: { service: { type: 'string' } } }
  }]
}));

server.setRequestHandler(CallToolRequestSchema, async (req) => {
  const { service } = req.params.arguments;
  const result = await deployService(service);
  return { content: [{ type: 'text', text: result }] };
});

Enterprise Access Control

  • Use team-shared settings.json committed to the repo for consistent permissions
  • Restrict Claude's API key to a specific set of allowed models via Anthropic Workspaces
  • Audit logs via PostToolUse hooks forwarded to your SIEM
  • Integrate with SSO/LDAP for API key provisioning

Capstone Challenge

Design and implement a production-ready Claude Code agent that:

  1. Accepts a GitHub repository URL as input
  2. Clones the repo and analyzes its structure
  3. Identifies the top 3 most critical security issues
  4. Creates a GitHub issue for each one with detailed remediation steps
  5. Sends a Slack summary to a channel via MCP
  6. Logs all actions with structured observability
  7. Handles errors gracefully with retry logic

This capstone covers all 21 lessons: tooling, permissions, MCP, git integration, subagents, context management, security, and production patterns.
