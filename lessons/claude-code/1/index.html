Lesson 1: Introduction to Claude Code

Claude Code is Anthropic's official command-line interface (CLI) for interacting with Claude directly from your terminal. Unlike browser-based chat interfaces, Claude Code integrates deeply with your local development environment — reading files, writing code, running shell commands, and managing git repositories on your behalf.

What is Claude Code?

Claude Code operates as an agentic coding assistant. The key difference from a standard chat interface is the agentic loop: Claude can autonomously take a sequence of actions — reading files, editing code, running tests, and committing changes — to complete complex tasks without requiring constant manual direction.

The Agentic Loop Model

At the core of Claude Code's operation is a continuous loop:

  1. Perception — Claude reads your request and any relevant files.
  2. Planning — It breaks the task into sub-steps.
  3. Action — It calls tools: Bash, Read, Edit, Write, WebSearch, etc.
  4. Observation — It reads the result of each action.
  5. Iteration — It continues until the task is complete or needs clarification.

How Claude Code Fits the Claude Ecosystem

Claude Code is built on top of the same Claude models (Opus, Sonnet, Haiku) available via the Anthropic API. It adds:

  • A persistent CLI session with conversation history
  • Pre-built tools for filesystem and shell access
  • MCP (Model Context Protocol) support for external integrations
  • Git-aware workflows and hooks
  • IDE extensions for VS Code and JetBrains

Key Concepts

  • CLI — runs in your terminal, works with any project
  • Agentic — multi-step autonomous task execution
  • Tools — structured actions Claude can take (read, write, bash, search)
  • CLAUDE.md — project memory that persists across sessions

Practical Exercises

Complete all three tasks to lock in the concepts from this lesson:

  1. Map the agentic loop to a real workflow. Pick a recurring chore (writing a commit message, generating a changelog, or reviewing a diff). Write a short note that breaks the task into the five loop stages — Perception, Planning, Action, Observation, Iteration — and lists which tool(s) Claude would call at each stage.
  2. Compare interfaces. Open Claude on the web (claude.ai) and ask it to "explain how to rename a function across a TypeScript project". Then describe in 3–5 bullet points what Claude Code can do that a browser chat cannot (filesystem access, persistent CLAUDE.md, tool loop, etc.).
  3. Identify a poor fit. Sketch one task that you would not automate with Claude Code (for example: a sensitive production database migration with no audit trail). Explain in two sentences why a human-in-the-loop is mandatory and which safeguards from later lessons (permissions, hooks, deny lists) would have to be in place before you could safely automate it.
