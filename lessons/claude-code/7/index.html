Lesson 7: IDE Integration

Claude Code works in your terminal, but it also integrates directly into VS Code and JetBrains IDEs, letting you stay in your editor while getting agentic assistance.

VS Code Extension

Install the Claude Code extension from the VS Code marketplace. Once installed:

  • A Claude Code panel appears in the sidebar
  • You can start sessions without leaving VS Code
  • File edits show as inline diffs you can accept or reject

JetBrains Plugin

Available for IntelliJ IDEA, PyCharm, WebStorm, and other JetBrains IDEs. Install from the JetBrains marketplace. The plugin adds a Claude Code tool window with the same session capabilities as VS Code.

Inline Diff Review

When Claude Code edits a file through the IDE extension, it shows a diff overlay in the editor. You can:

  • Accept the entire change with one click
  • Reject and ask Claude to try again
  • Accept individual hunks while rejecting others

This is the safest workflow for production codebases — every change is visible before it hits disk.

Keybindings

Default keybindings (VS Code):

ShortcutAction
Cmd/Ctrl+Shift+AOpen Claude Code session
Cmd/Ctrl+EnterSubmit prompt
EscapeCancel current action

All keybindings are customizable via the standard VS Code or JetBrains keybinding editors.

IDE-Native Workflows

  • Select code in the editor, then open Claude Code — the selection is automatically included as context
  • Use the terminal panel inside VS Code to run Claude Code in full CLI mode
  • Errors highlighted in the editor can be passed to Claude by right-clicking and selecting "Fix with Claude"

Practical Exercises

Complete all three tasks to make the IDE your primary Claude Code surface:

  1. Install and verify the extension. Install the Claude Code extension for VS Code or your JetBrains IDE. Open the sidebar panel and start a session. Confirm the active workspace folder appears as the project context.
  2. Fix a real defect via inline diff. Open a file with a known bug or code smell, highlight the problematic block, and ask Claude to fix it. Review the inline diff, accept one hunk and reject another, and confirm both partial-acceptance behaviors work as expected.
  3. Pass a diagnostic into Claude. Trigger a real linter or type error in the editor, then use the "Fix with Claude" action (or right-click context menu). Verify Claude reads the diagnostic, proposes a fix, and that you can accept it without leaving the editor.
  4. Customize a keybinding. Rebind "Open Claude Code session" to a chord that doesn't collide with your existing shortcuts. Document the new chord in your team's onboarding notes or your personal CLAUDE.md.
