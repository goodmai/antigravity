Lesson 8: Git & GitHub Workflows

Claude Code understands git natively. It can inspect your working tree, stage and commit changes, create branches, and interact with GitHub — making routine version-control tasks near-instant.

Automated Commits

After making a set of changes, ask Claude to commit them:

> Commit the changes we just made with a conventional commit message

Claude will run git diff --staged, analyze the changes, write a descriptive message, and execute git commit. It will ask for confirmation before pushing.

Branch Management

> Create a new branch called feature/login-refactor and switch to it
> List all branches and tell me which ones haven't been merged to main
> Delete the feature branch after it's been merged

Pull Request Creation

With GitHub MCP or gh CLI configured, Claude can create PRs:

> Create a pull request for the changes on this branch.
> Title it "fix: resolve login 404 after redirect" and describe the changes.

PR Review

> Review the changes in this PR and tell me if there are any obvious issues
> Summarize the diff in plain English for a non-technical reviewer

Conflict Resolution

> I have a merge conflict in src/auth.js — resolve it by keeping the main branch version
> Explain what changed on both sides of this conflict before resolving

Safe Git Practices

  • Claude will always confirm before git push or destructive operations
  • Force push is explicitly refused unless the user confirms twice
  • Claude never skips pre-commit hooks (--no-verify) without explicit permission

Practical Exercises

Complete all three tasks in a real (non-throwaway) git repository:

  1. Conventional commit drill. Make a small, well-scoped change to a file. Ask Claude to stage only that file, write a commit message following the Conventional Commits spec (feat:, fix:, refactor:, etc.), and run the commit. Review the message Claude produced — would you have written the same?
  2. Branch + PR flow. Ask Claude to create a feature branch with a descriptive name (e.g., fix/login-validation), push it with -u origin, and open a pull request whose body lists "Summary" and "Test plan" bullet sections. Confirm the PR URL is returned and the body renders correctly on GitHub.
  3. Conflict resolution. Intentionally create a small merge conflict (edit the same line in two branches). Ask Claude to merge and resolve. Inspect its choice — did it preserve both intents, or silently drop one? This is the muscle memory you need for real conflicts.
  4. Safety rehearsal. Ask Claude to "force-push my current branch to main". Confirm Claude refuses (or escalates for confirmation) and explain in 2 sentences which guardrail caught it: permission deny rule, system instruction, or your own intervention.
