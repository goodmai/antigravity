Lesson 10: Custom Slash Commands

Slash commands let you define reusable prompts that execute with a single command. They're stored as Markdown files and support argument interpolation, making them a lightweight automation layer on top of Claude Code.

Where Commands Live

  • ~/.claude/commands/ — global commands, available in all projects
  • .claude/commands/ (project root) — project-specific commands

Creating a Command

Create a Markdown file named after your command:

# ~/.claude/commands/review.md

Review the staged git diff for:
1. Logic errors or obvious bugs
2. Missing input validation
3. Test coverage gaps
4. Anything that could break in production

Be specific and cite line numbers.

Now run /review from any Claude Code session.

Commands with Arguments

Use $ARGUMENTS as a placeholder:

# .claude/commands/fix.md

Fix the following issue and write a test for it:

$ARGUMENTS

Usage: /fix The login button throws an uncaught exception when the API is down

Example: Conventional Commit

# .claude/commands/commit.md

Stage all changes and create a conventional commit.
Format: <type>(<scope>): <description>

Types: feat, fix, docs, style, refactor, test, chore

Analyze the diff, choose the right type and scope, write a clear description,
and commit. Show me the message before committing.

Listing Available Commands

/help

All custom commands appear in the help output alongside built-in commands.

Practical Exercises

Complete all three tasks to build a small but useful command library:

  1. Project-scoped /changelog. Create .claude/commands/changelog.md that asks Claude to run git log $(git describe --tags --abbrev=0)..HEAD and produce a CHANGELOG entry in Keep a Changelog format (Added / Changed / Fixed / Removed). Test it in a repo with several commits since the last tag.
  2. Command with arguments. Create /fix <issue> at .claude/commands/fix.md using $ARGUMENTS. The prompt should instruct Claude to (a) reproduce the issue, (b) implement a fix, and (c) add a test that fails before the fix and passes after. Test with: /fix login throws when API is down.
  3. Global command. Create ~/.claude/commands/review.md that asks Claude to review the staged diff for logic errors, missing validation, and test coverage gaps — citing line numbers. Run /review from two different projects to prove the global scope works.
  4. Discoverability check. Run /help in a session that has access to all three commands and confirm they appear in the listing. If a command is missing, verify it's a .md file with the correct name in the correct directory.
