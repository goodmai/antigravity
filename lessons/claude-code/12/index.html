Lesson 12: Subagents & Parallelism

Complex tasks often benefit from parallel execution. Claude Code and the Agent SDK support spawning subagents — independent agent instances that work on subtasks concurrently, then return results to an orchestrator.

Why Use Subagents?

  • Speed — parallelize independent subtasks
  • Isolation — each subagent has its own context, avoiding interference
  • Specialization — different subagents can use different models or tool sets
  • Context management — large tasks that would overflow one context window

Spawning Subagents in Claude Code

In Claude Code CLI sessions, you can spawn subagents via the Agent tool. When building with the SDK, you call your own agent function recursively or in parallel:

const results = await Promise.all([
  runAgent('Review src/auth.js for security issues'),
  runAgent('Review src/payment.js for security issues'),
  runAgent('Review src/api.js for security issues'),
]);

const report = await runAgent(
  `Synthesize these security reviews into a priority list:\n\n${results.join('\n\n')}`
);

Work Isolation Patterns

  • File isolation — give each subagent a different directory or file set
  • Git worktrees — each subagent works in its own isolated branch copy
  • Scoped permissions — restrict each subagent's tool access to its domain

Result Aggregation

After subagents complete, an orchestrator agent synthesizes their outputs. Common patterns:

  • Merge — combine outputs (e.g., merge code changes from multiple agents)
  • Rank — score and select the best result
  • Reduce — summarize multiple outputs into one

Practical Exercises

Complete all three tasks to build intuition for the orchestrator + worker pattern:

  1. Three-way solution race. Write an orchestrator that spawns three subagents in parallel, each asked to solve the same coding problem (e.g., "implement an LRU cache in TypeScript") with a different constraint — "use a Map", "use a doubly-linked list", "no external dependencies". Collect all three responses.
  2. Judge agent. Add a fourth agent that receives all three solutions and selects the best one with reasoning. Compare its pick to your own intuition; if you disagree, sharpen the judge's system prompt with explicit scoring criteria (correctness, readability, complexity) and rerun.
  3. Isolation via git worktrees. Repeat the experiment but give each subagent its own git worktree (use git worktree add). Confirm subagents can write files without stepping on each other, and that the orchestrator can diff each worktree to compare outputs.
  4. Failure containment. Make one subagent intentionally fail (throw an error or exceed iteration limit). Verify the orchestrator surfaces the failure but still processes the remaining two — never let one subagent take down the whole pipeline.
