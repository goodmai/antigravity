Lesson 20: Production Agents

Moving from experimental agent scripts to production-ready deployments requires error handling, observability, and reliability patterns that exploratory code rarely has.

Deployment Patterns

  • Serverless functions — invoke agents on demand via Lambda, Cloud Functions, etc.
  • Queue workers — agents consume tasks from a message queue (SQS, Pub/Sub)
  • Scheduled jobs — cron-triggered agents for routine tasks (daily reports, cleanups)
  • GitHub Actions — agents triggered by repository events

DevOps Automation with Claude Code

When integrated into the terminal, Claude Code becomes a capable DevOps assistant — not just generating scripts, but executing them and reacting to their output in real time.

Server Deployment

For server scenarios such as Ubuntu VMs on AWS EC2, Claude can generate and execute complex curl chains, configure web servers (Nginx/Apache), configure firewall rules (iptables/ufw), and install system dependencies — all within a single guided session.

Autonomous Permission Handling

When Claude encounters a "Permission denied" error it autonomously analyzes the output, understands that superuser privileges are required, and rewrites the command with sudo or adjusts permissions via chmod/chown. No human intervention needed for the retry.

Important: this autonomy requires vigilance. In rare cases, permission changes made by the agent can have unpredictable consequences for the OS. Always monitor bash commands executed by the agent.

Error Handling

async function runAgentWithRetry(task: string, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      return await runAgent(task);
    } catch (e) {
      if (e.status === 529) {  // API overloaded
        await sleep(Math.pow(2, attempt) * 1000);
        continue;
      }
      throw e;  // don't retry on other errors
    }
  }
  throw new Error(`Agent failed after ${maxRetries} attempts`);
}

Observability

Log structured events at key points in the agent loop:

logger.info({ event: 'agent_start', task_id, model });
logger.info({ event: 'tool_call', tool: name, input });
logger.info({ event: 'tool_result', tool: name, duration_ms });
logger.info({ event: 'agent_complete', task_id, total_tokens, cost_usd });

Rate Limiting and Cost Control

  • Set per-run token budgets and abort if exceeded
  • Track cumulative cost per workflow and alert on anomalies
  • Use Anthropic's usage API to monitor consumption by API key

Testing Production Agents

  • Record real tool outputs and replay them in tests (avoid live API calls in CI)
  • Use evaluation datasets — fixed inputs with known expected outputs
  • Test failure paths: API errors, tool failures, context overflow

Practical Exercises

Complete all three tasks — these are the bare minimum for an agent you'd let near production:

  1. Structured logging. Take an agent you built in lesson 11. Emit JSON logs at four points: agent_start, tool_call, tool_result (with duration_ms), and agent_complete (with total tokens and USD cost). Pipe the output to jq and confirm every event is parseable.
  2. Retry with exponential backoff. Wrap the API call so HTTP 529 (overloaded) and 503 trigger exponential backoff (1s, 2s, 4s) capped at 3 attempts. Other errors fail fast. Test by mocking the SDK to throw 529 twice then succeed — confirm the retries fire and the third attempt returns the result.
  3. Token budget. Add a per-run token budget. Log a warning at 80% consumed and abort cleanly at 100% (no half-completed work). Test with a budget of 5000 tokens against a task that obviously needs more — confirm the warning and abort both fire at the expected thresholds.
  4. Deploy as a workflow. Wrap the hardened agent in a GitHub Actions workflow triggered by workflow_dispatch with an input parameter for the task description. Run it from the Actions UI and confirm logs are visible, secrets are not, and the run exits with the right status code.
