Lesson 20: Production Agents

Moving from experimental agent scripts to production-ready deployments requires error handling, observability, and reliability patterns that exploratory code rarely has.

Deployment Patterns

  • Serverless functions — invoke agents on demand via Lambda, Cloud Functions, etc.
  • Queue workers — agents consume tasks from a message queue (SQS, Pub/Sub)
  • Scheduled jobs — cron-triggered agents for routine tasks (daily reports, cleanups)
  • GitHub Actions — agents triggered by repository events

Error Handling

async function runAgentWithRetry(task: string, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      return await runAgent(task);
    } catch (e) {
      if (e.status === 529) {  // API overloaded
        await sleep(Math.pow(2, attempt) * 1000);
        continue;
      }
      throw e;  // don't retry on other errors
    }
  }
  throw new Error(`Agent failed after ${maxRetries} attempts`);
}

Observability

Log structured events at key points in the agent loop:

logger.info({ event: 'agent_start', task_id, model });
logger.info({ event: 'tool_call', tool: name, input });
logger.info({ event: 'tool_result', tool: name, duration_ms });
logger.info({ event: 'agent_complete', task_id, total_tokens, cost_usd });

Rate Limiting and Cost Control

  • Set per-run token budgets and abort if exceeded
  • Track cumulative cost per workflow and alert on anomalies
  • Use Anthropic's usage API to monitor consumption by API key

Testing Production Agents

  • Record real tool outputs and replay them in tests (avoid live API calls in CI)
  • Use evaluation datasets — fixed inputs with known expected outputs
  • Test failure paths: API errors, tool failures, context overflow

Practical Exercise

Take a simple agent you've built and add: structured logging with duration tracking, exponential backoff retry on API errors, and a token budget that logs a warning at 80% and aborts at 100%. Deploy it as a GitHub Action triggered by a workflow_dispatch event.
