Lesson 16: CI/CD Integration

Claude Code can run non-interactively in CI/CD pipelines, enabling automated code review, documentation generation, and quality gate enforcement on every pull request.

Headless Mode

Use --print flag for non-interactive execution:

claude --print "Review the diff and list any issues" --output-format json

This runs once, prints the result, and exits with a zero/non-zero code based on success.

GitHub Actions Example

name: Claude Code Review
on:
  pull_request:

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      
      - name: Run Claude Code Review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          npm install -g @anthropic-ai/claude-code
          git diff origin/main...HEAD > diff.txt
          claude --print "Review diff.txt for bugs and security issues. 
            Exit with code 1 if any critical issues are found."             --permission-mode bypassPermissions

Quality Gates

Claude Code can enforce custom quality rules that static analyzers can't:

  • "Does this PR add tests for all new public functions?"
  • "Are all user-facing error messages internationalized?"
  • "Does the migration file have a corresponding rollback?"

Automated Documentation

claude --print "Update the CHANGELOG with an entry for the changes in this diff"   --permission-mode acceptEdits

Cost Management in CI

  • Use Haiku for simple checks (linting, format verification)
  • Use Sonnet for code review
  • Cache CLAUDE.md context to reduce repeated token usage
  • Scope reviews to the diff only, not the entire codebase

Practical Exercise

Write a GitHub Actions workflow that runs Claude Code on every PR to check: does the PR include a test for each new function? Have it post a comment with the results and fail the check if any new function is untested.
