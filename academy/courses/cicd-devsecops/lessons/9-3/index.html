Гибрид: GH Actions → Akash, fallback на AWS

jobs:
  deploy:
    runs-on: ubuntu-24.04
    steps:
      - name: Deploy to Akash (primary)
        id: akash
        continue-on-error: true
        run: |
          akash tx deployment create deploy.yml --from $WALLET ...
          # health-check
          curl --fail https://akash-deployment.example.com/health

      - name: Fallback to AWS EKS
        if: steps.akash.outcome == 'failure'
        run: |
          aws eks update-kubeconfig --name my-cluster
          kubectl apply -f k8s/

Threat model гибрида:

  • DNS управляется одним provider (Cloudflare/Route53). При его падении —

ни Akash, ни AWS не доступны → нужен multi-DNS (anycast + secondary).

  • mTLS-сертификаты у обоих провайдеров одинаковые → ключ должен быть в Vault,

а не в env-var каждой среды.

Расширенный workflow с мониторингом escrow-баланса

jobs:
  deploy:
    runs-on: ubuntu-24.04
    steps:
      - name: Check Akash escrow balance
        id: escrow-check
        run: |
          BALANCE=$(akash query deployment get \
            --owner $WALLET_ADDRESS \
            --dseq $DEPLOYMENT_SEQ \
            --output json | jq -r '.escrow_account.balance.amount')
          # Переводим из uakt в AKT (делим на 1_000_000)
          AKT=$(echo "scale=4; $BALANCE / 1000000" | bc)
          echo "balance=$AKT" >> $GITHUB_OUTPUT
          echo "Escrow balance: $AKT AKT"

      - name: Alert if balance low
        if: ${{ steps.escrow-check.outputs.balance < 0.5 }}
        run: |
          curl -s -X POST "https://api.telegram.org/bot${TG_TOKEN}/sendMessage" \
            -d chat_id="${TG_CHAT_ID}" \
            -d text="⚠️ Akash escrow balance LOW: ${{ steps.escrow-check.outputs.balance }} AKT — пополните deployment!"
        env:
          TG_TOKEN: ${{ secrets.TELEGRAM_BOT_TOKEN }}
          TG_CHAT_ID: ${{ secrets.TELEGRAM_CHAT_ID }}

      - name: Deploy to Akash (primary)
        id: akash
        continue-on-error: true
        run: |
          akash tx deployment create deploy.yml --from $WALLET --gas auto
          curl --fail https://akash-deployment.example.com/health

      - name: Fallback to AWS EKS
        if: steps.akash.outcome == 'failure'
        run: |
          aws eks update-kubeconfig --name my-cluster
          kubectl apply -f k8s/

Кейс: SaaS-продукт экономит 60% на compute

Реальная архитектура: Akash как primary (дешёвый compute), AWS EKS как fallback (надёжность). При 720 часах в месяц:

  • Akash: ~$58/мес (8 CPU / 16 GB) vs AWS: ~$245/мес — экономия 76%.
  • Фактическая uptime Akash ~99.5% → 3.6 ч/мес downtime.
  • При fallback на EKS эти 3.6 ч стоят ~$1.2 → итого ~$59.2/мес.
  • Vs чистый AWS: $245/мес → реальная экономия ~60%.

Bash-скрипт мониторинга баланса AKT с Telegram-алертом

#!/usr/bin/env bash
# monitor-escrow.sh — запускать через cron каждые 15 минут

set -euo pipefail

WALLET="${AKASH_WALLET_ADDRESS}"
DSEQ="${AKASH_DEPLOYMENT_SEQ}"
MIN_BALANCE=0.5   # AKT — порог для алерта
TG_TOKEN="${TELEGRAM_BOT_TOKEN}"
TG_CHAT="${TELEGRAM_CHAT_ID}"

# Получаем баланс escrow
RAW=$(akash query deployment get \
  --owner "$WALLET" \
  --dseq "$DSEQ" \
  --output json 2>/dev/null)

if [ $? -ne 0 ]; then
  echo "ERROR: deployment not found or Akash RPC unavailable"
  exit 1
fi

BALANCE_UAKT=$(echo "$RAW" | jq -r '.escrow_account.balance.amount // "0"')
BALANCE_AKT=$(echo "scale=6; $BALANCE_UAKT / 1000000" | bc)

echo "Current escrow balance: $BALANCE_AKT AKT"

# Сравниваем с порогом (bc возвращает 1 если выражение истинно)
IS_LOW=$(echo "$BALANCE_AKT < $MIN_BALANCE" | bc -l)

if [ "$IS_LOW" -eq 1 ]; then
  MSG="⚠️ *Akash Escrow Alert*%0A"
  MSG+="Balance: \`${BALANCE_AKT} AKT\`%0A"
  MSG+="Threshold: \`${MIN_BALANCE} AKT\`%0A"
  MSG+="Action required: top up deployment \`${DSEQ}\`"

  curl -s -X POST "https://api.telegram.org/bot${TG_TOKEN}/sendMessage" \
    -d "chat_id=${TG_CHAT}" \
    -d "text=${MSG}" \
    -d "parse_mode=Markdown" \
    > /dev/null

  echo "ALERT sent to Telegram"
  exit 2  # non-zero для cron-мониторинга
fi

echo "Balance OK"
