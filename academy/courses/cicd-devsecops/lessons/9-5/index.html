Конкурентная среда DePIN: Akash vs AIOZ и экосистема

Канон: Akash docs, AIOZ Network docs, AIOZ W3S docs, Render docs, Golem docs, Gensyn docs.

Рынок DePIN-инфраструктуры фрагментирован: каждый протокол занимает нишу по типу нагрузки и модели доверия. Если Akash — это «AWS EC2 децентрализованного мира» (контейнерный compute), то AIOZ Network — это «AWS S3 + Cloudflare» (хранение + CDN + edge AI). Понимать различия критично при выборе стека.

2. Архитектура AIOZ Network

AIOZ Network — Layer-1 блокчейн с двойной совместимостью: EVM (Ethereum-экосистема) и Cosmos IBC (межцепочечная передача токенов и сообщений). Это означает: смарт-контракты Solidity работают нативно, и одновременно возможен IBC-мост к Akash, Osmosis, Cosmos Hub.

W3S — S3-совместимое объектное хранилище

Файлы загружаются через S3-compatible API (endpoint: https://s3.w3s.link). Каждый объект получает Content-ID (CID) и реплицируется на глобальную сеть нод. Раздача контента CDN-маршрутизируется к ближайшей ноде.

Как работает CDN-маршрутизация в AIOZ:

Для каждого запроса сеть выбирает оптимальную ноду по формуле минимальной латентности:

L_min = min_{i ∈ N}(d(n_i, u) + δ_i)

где:
  N      — множество нод сети, хранящих объект
  d(n_i, u) — географическое расстояние (или RTT) от ноды n_i до пользователя u
  δ_i    — текущая нагрузка ноды n_i (задержка из-за очереди обработки)
  L_min  — минимально достижимая латентность для данного запроса

На практике: при запросе видео-файла алгоритм обходит все ноды, имеющие реплику, и выбирает ту, у которой d(n_i, u) + δ_i минимально. Перегруженная нода в Сингапуре может проиграть незагруженной ноде в Германии, если пользователь из Европы.

W3AI — Edge AI inference

Запросы к AI-моделям (REST/gRPC) маршрутизируются на edge-ноды по той же логике минимизации латентности. Ноды хранят квантизированные модели локально. Это снижает latency по сравнению с централизованным облачным inference (нет трансатлантического hop).

W3IPFS — Decentralized hosting

NFT-метаданные, dApp-фронтенды, статические сайты. Каждый файл адресуется через IPFS CID; AIOZ ноды пиннят контент и раздают через HTTP-gateway. Аналог Fleek, но с токен-инсентивами для хранящих нод.

Layer-1: EVM + IBC

Нативная совместимость с MetaMask, ethers.js, Hardhat (EVM-слой) плюс возможность IBC-трансфера токенов из/в Akash, Cosmos Hub, Osmosis. Для DevOps-инженера это значит: можно автоматически пополнять AIOZ-кошелёк через IBC-мост из кошелька Akash без CEX.

3. Математическая модель CDN-эффективности

Классическая задача выбора CDN-ноды формализуется через задачу минимизации суммарной задержки. Разберём на Python-псевдокоде:

from dataclasses import dataclass
from typing import List

@dataclass
class Node:
    node_id: str
    region: str
    rtt_to_user_ms: float   # d(n_i, u) — RTT от ноды до пользователя
    current_load_ms: float  # δ_i — дополнительная задержка из-за нагрузки

def select_optimal_node(nodes: List[Node]) -> Node:
    """
    L_min = min_{i in N}(d(n_i, u) + delta_i)
    Возвращает ноду с минимальной суммарной задержкой.
    """
    return min(nodes, key=lambda n: n.rtt_to_user_ms + n.current_load_ms)

# Пример: пользователь из Москвы, запрашивает видео-файл
nodes = [
    Node("sg-01", "Singapore", rtt_to_user_ms=180, current_load_ms=5),   # 185 ms
    Node("de-01", "Frankfurt",  rtt_to_user_ms=45,  current_load_ms=120), # 165 ms
    Node("us-01", "New York",   rtt_to_user_ms=130, current_load_ms=10),  # 140 ms
    Node("ru-01", "Moscow",     rtt_to_user_ms=10,  current_load_ms=200), # 210 ms — перегружена!
]

best = select_optimal_node(nodes)
print(f"Optimal: {best.node_id} ({best.region})")
# Output: Optimal: us-01 (New York)  ← перегруженная московская нода проигрывает!

Вывод для практики: географически близкая нода не всегда оптимальна. В AIOZ маршрутизатор учитывает текущую нагрузку нод в реальном времени — именно поэтому CDN-эффективность AIOZ выше наивного «ближайший сервер».

4. Akash vs AIOZ — когда что выбирать

КритерийAkashAIOZ Network
Тип нагрузкиContainer compute (CPU/GPU)Storage + CDN + edge AI inference
Аналог в AWSEC2 / ECS / EKSS3 + CloudFront + SageMaker Endpoint
API для разработчикаSDL (YAML-like), akash CLIS3-compatible REST API, AWS CLI
Барьер входаСредний (SDL, Cosmos wallet, reverse-auction)Низкий (знакомый S3 API + AWS CLI)
ОплатаAKT / USDC escrow, поблочноAIOZ токен
Блокчейн-базаCosmos SDKLayer-1 EVM + Cosmos IBC
Egress fee$0$0 (для нод-участников)
Идеален дляМикросервисы, K8s-workloads, CI/CD, API-серверыМедиа-хранение, CDN, стриминг, edge AI, NFT-метаданные
Не подходит дляСтатика/CDN, архивное хранение больших файловСложная контейнерная оркестрация, stateful databases

Правило большого пальца: если ваш bottleneck — это вычисления (CPU, GPU, memory для кода) → Akash. Если bottleneck — хранение и раздача контента (bandwidth, latency до пользователя) → AIOZ. Для ML-проектов нередко нужны оба: Akash для training/serving, AIOZ для хранения datasets и раздачи результатов.

5. Практика: работа с AIOZ W3S через S3 API

AIOZ W3S полностью совместим с AWS S3 API. Это означает: любой инструмент, работающий с S3 (AWS CLI, boto3, Terraform S3 backend, MinIO клиент), работает с AIOZ W3S с минимальными изменениями — только меняем endpoint.

# Конфигурация AWS CLI для работы с AIOZ W3S
aws configure set aws_access_key_id $AIOZ_KEY
aws configure set aws_secret_access_key $AIOZ_SECRET

# Загрузка артефакта (HTML test report) в AIOZ W3S
aws s3 cp ./test-report.html s3://my-bucket/reports/test-report.html \
  --endpoint-url https://s3.w3s.link

# Загрузка целой директории (например, Playwright report)
aws s3 sync ./playwright-report/ s3://my-bucket/playwright/ \
  --endpoint-url https://s3.w3s.link

# Получение публичного URL (если bucket public)
echo "Report URL: https://my-bucket.s3.w3s.link/reports/test-report.html"

# Список объектов в bucket
aws s3 ls s3://my-bucket/ --endpoint-url https://s3.w3s.link

# Удаление объекта
aws s3 rm s3://my-bucket/reports/old-report.html \
  --endpoint-url https://s3.w3s.link

В GH Actions — через переменные окружения из Secrets:

- name: Upload test report to AIOZ W3S
  id: aioz-upload
  run: |
    # Конфигурируем AWS CLI для AIOZ endpoint
    aws configure set aws_access_key_id "$AIOZ_KEY"
    aws configure set aws_secret_access_key "$AIOZ_SECRET"

    # Синхронизируем директорию с отчётом
    aws s3 sync ./playwright-report/ \
      s3://${{ vars.AIOZ_BUCKET }}/reports/${{ github.run_id }}/ \
      --endpoint-url https://s3.w3s.link

    # Формируем публичную ссылку
    REPORT_URL="https://${{ vars.AIOZ_BUCKET }}.s3.w3s.link/reports/${{ github.run_id }}/index.html"

    # Записываем в Step Summary
    echo "## Test Report (AIOZ W3S)" >> $GITHUB_STEP_SUMMARY
    echo "URL: $REPORT_URL" >> $GITHUB_STEP_SUMMARY
    echo "report-url=$REPORT_URL" >> $GITHUB_OUTPUT
  env:
    AIOZ_KEY: ${{ secrets.AIOZ_ACCESS_KEY }}
    AIOZ_SECRET: ${{ secrets.AIOZ_SECRET_KEY }}

6. Гибридная архитектура: Akash (compute) + AIOZ (storage + CDN)

Комбинация двух DePIN-протоколов даёт полный стек без централизованных облаков: Akash обрабатывает запросы, AIOZ хранит и раздаёт артефакты.

---
# deploy.yml — Akash SDL
# API-сервис использует AIOZ W3S как объектное хранилище
version: "2.0"
services:
  api:
    image: ghcr.io/myorg/api@sha256:abc...
    env:
      - STORAGE_ENDPOINT=https://s3.w3s.link   # AIOZ W3S endpoint
      - STORAGE_BUCKET=my-artifacts             # имя bucket в AIOZ
      - STORAGE_REGION=us-east-1                # любое (S3-compatible)
    expose:
      - port: 8080
        as: 8080
        to: [{ global: true }]
  worker:
    image: ghcr.io/myorg/worker@sha256:def...
    env:
      - STORAGE_ENDPOINT=https://s3.w3s.link
      - STORAGE_BUCKET=my-artifacts
      - QUEUE_SIZE=10
    expose:
      - port: 9323    # metrics
        to: [{ global: false }]
profiles:
  compute:
    api:
      resources:
        cpu: { units: 2 }
        memory: { size: 2Gi }
        storage: { size: 10Gi }
    worker:
      resources:
        cpu: { units: 4 }
        memory: { size: 4Gi }
        storage: { size: 20Gi }
  placement:
    dcloud:
      attributes: { host: akash }
      signedBy: { anyOf: ["akash1..."] }
      pricing:
        api: { denom: uakt, amount: 300 }
        worker: { denom: uakt, amount: 600 }
deployment:
  api:
    dcloud:
      profile: api
      count: 1
  worker:
    dcloud:
      profile: worker
      count: 1

Как это работает:

  1. Akash-deployment поднимает api и worker контейнеры.
  2. Worker обрабатывает задачи (например, видео-транскодинг) и сохраняет результаты в AIOZ W3S через S3 API (STORAGE_ENDPOINT).
  3. Пользователи получают готовые файлы напрямую из AIOZ CDN — без нагрузки на Akash-ноду и без egress-fee с обеих сторон.

Что сохраняется в AIOZ W3S: видеофайлы, ML-модели, test-отчёты, SBOM/провенанс, build-артефакты. Всё, что нужно хранить долго и раздавать быстро.
