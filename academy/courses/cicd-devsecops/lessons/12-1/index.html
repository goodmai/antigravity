Топ-30 типичных ошибок

Pipeline / Git

  1. uses: actions/checkout@v4 (tag, а не SHA) — supply chain attack.

Фикс: pin by full commit SHA, использовать pin-github-action.

  1. Default GITHUB_TOKEN имеет write — overprivilege.

Фикс: permissions: { contents: read } в job (минимум) или в workflow.

  1. pull_request_target + checkout PR-кода — RCE из untrusted forks.

Фикс: не делать checkout untrusted кода в _target, или

permissions: {} пусто.

  1. PAT в repo secrets — токен живёт год, после увольнения admin'а — катастрофа.

Фикс: GitHub App + fine-grained PAT с short TTL.

  1. Self-merge PR'а — обход review.

Фикс: Require pull request reviews — Dismiss stale + Restrict who can dismiss.

  1. Force-push в main. Фикс: protected branch + linear history.
  2. branch_name подставляется в shell без escape: eval "echo ${BRANCH}".

Фикс: через env: + "$BRANCH" в кавычках, не string-templating.

Containers / k8s

  1. FROM image:latest — невоспроизводимая сборка.

Фикс: pin tag + better digest @sha256:....

  1. USER root в образе + runAsNonRoot: true в k8s → CrashLoopBackOff

или невозможность сделать чисто.

  1. readOnlyRootFilesystem: false — exploit пишет webshell.

Фикс: true + emptyDir для /tmp.

  1. Без resources.limits — один pod ест всю ноду.

Фикс: обязательны requests+limits + LimitRange на namespace.

  1. hostNetwork: true "потому что проще" — обход network policies, root

namespace. Фикс: никогда в prod.

  1. automountServiceAccountToken: true дефолтом — все поды могут читать

kube-API. Фикс: false + явный SA где нужно.

  1. Один namespace для всего — нет isolation.

Фикс: ns per environment/service + NetworkPolicy default-deny.

Secrets

  1. AWS Access Keys в GitHub Secrets — long-lived.

Фикс: OIDC-федерация.

  1. Секрет вылетел в логе (set -x + curl -H "Authorization: $TOKEN").

Фикс: GH masks secrets, но если запиcали в файл и cat — не маскируется.

Используйте add-mask::.

  1. echo $SECRET > file без umask 077 — другие процессы прочтут.
  2. .env файлы в Docker layer — слой в registry, секрет утёк навсегда.

Фикс: BuildKit --secret, не COPY .env.

Releases

  1. Один и тот же образ — разные теги (prod-latest перезатирается).

Фикс: immutable tags + digest.

  1. semver нарушен — patch ломает API.

Фикс: Conventional Commits → semantic-release.

  1. Hot-fix напрямую в main, минуя CI (даже «маленький»).

Фикс: запрет на force-push, обязательные status checks.

Observability

  1. «У нас же есть логи» — но без structured logging и trace_id.

Фикс: JSON-логи, OpenTelemetry, exemplars в Prometheus.

  1. Алёрт «CPU > 90%» — алёрт на симптом, а не SLO.

Фикс: multi-burn-rate alerts на error budget.

  1. Нет deadman-switch alert'а — если Prom молчит, никто не знает.

Фикс: absent(up{job="..."} == 1) алёрт всегда.

Data / DR

  1. «Бэкапы есть, мы их не тестируем» — Schrödinger's backup.

Фикс: restore-rehearsal в CI, обязательно.

  1. DROP TABLE без EXPLAIN review (а в git diff не видно).

Фикс: Atlas/atlas migrate lint падает на destructive.

  1. ALTER TABLE ... ADD COLUMN с дефолтом на 100M-строк — час downtime.

Фикс: expand-contract + online DDL.

Misc

  1. CI запускается на каждый коммит, даже на chore: bump readme.

Фикс: paths-filter + skip-ci метки.

  1. Никто не читает security-alerts из Dependabot — backlog растёт.

Фикс: SLA на critical CVE (24h), еженедельный review.

  1. «Сначала фичи, безопасность потом».

Фикс: definition-of-done включает security gates; PR без них не мерджится.
