Идентичность и доступ

Канон: OAuth 2.1 draft, OIDC Core.

Аутентификация отвечает «кто ты», авторизация — «что тебе можно». Их нельзя смешивать.

OAuth 2.1: Authorization Code + PKCE

app → /authorize?code_challenge=... → IdP
IdP → redirect code → app
app → /token (code + code_verifier) → access + refresh
refresh rotation: каждый refresh выдаёт новый refresh, старый аннулируется
RBAC vs ABAC. RBAC — роли (просто, грубо). ABAC — атрибуты (гибко, сложнее аудит). Для маркетплейса: RBAC на админку, ABAC на «автор видит только свои выплаты».
Артефакт урока. Диаграмма auth-потока (Authorization Code + PKCE + refresh rotation).
