Клиент–сервер и слоистая архитектура

Канон: Clean Architecture (Martin), 12-Factor App.

Слоистая («чистая») архитектура задаёт правило зависимостей: исходный код может зависеть только внутрь — к домену. Инфраструктура (БД, HTTP, очереди) зависит от домена, а не наоборот.

Infrastructureрепозитории, клиенты, адаптеры—

Порты и адаптеры

// domain объявляет ПОРТ (интерфейс)
interface OrderRepository { save(o: Order): Promise<void> }

// infrastructure поставляет АДАПТЕР
class PgOrderRepository implements OrderRepository { /* SQL */ }

// application получает порт через DI — БД заменяема в тестах
Маркер ошибки. Если в доменной сущности появился import pg или аннотация ORM — правило зависимостей нарушено, и домен больше не тестируется без базы.
