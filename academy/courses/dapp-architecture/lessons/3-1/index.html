Модуль 3 — Децентрализованные аналоги и альтернативы · Урок 3.1 · карта

Карта соответствий

Канон: plan.md курса, Ethereum dev docs, IPFS docs.

Модуль 3 не вводит новый продукт. Мы берём тот же маркетплейс цифровых работ с лентой и платежами и проецируем его на децентрализованные аналоги — по тем же девяти кирпичам, что и в модулях 1–2. Цель урока — построить карту соответствий и для каждого кирпича честно назвать цену смены парадигмы.

1. Принцип проекции: один продукт, три парадигмы

Модуль 1 — современная классика (managed-облако, Postgres, S3). Модуль 2 — Google Cloud-специфика. Модуль 3 — децентрализация. Это не три разных системы, а одна система через три линзы. Девять кирпичей — инвариант: вопросы «где исполняется код», «где истина о данных», «кто пользователь» остаются; меняются только ответы и их стоимость.

Главная мысль курса. Децентрализация — не «лучше», а другой набор компромиссов. Архитектор обязан назвать цену: газ, латентность, финальность, доверие к ноде, потеря приватности. «Всё на блокчейне» — антипаттерн.

3. Спектр децентрализации и его цена

Децентрализация — не бинарный флаг, а спектр. Один кирпич может быть полностью on-chain, другой — гибридным, третий осознанно централизованным. Оценивайте каждый по тем же осям, что и весь курс.

Пример использования элементов

Применим карту к маркетплейсу. Не всё стоит децентрализовать. Черновик матрицы решений (фрагмент):

Кирпич        Решение М3              Обоснование
-----------   ---------------------   --------------------------------
Платёж        on-chain (контракт)     нужна неоспоримость и атомарность
Владение      on-chain (маппинг/NFT)  истина о праве — публичная
Файл работы   IPFS + Filecoin deal    дёшево, content-addressed
Лента         off-chain индекс        латентность важнее неоспоримости
Поиск         централизованно         газ за индекс не оправдан
Аутентиф.     SIWE (кошелёк)          self-sovereign, без пароля

Принцип фиксируем: on-chain — только то, чему нужна неоспоримость и публичная истина (деньги, право собственности). Всё остальное — гибрид или централизованно, и решение обосновывается ADR.

Артефакт урока. Матрица-черновик соответствий 9×3 (классика ↔ Google ↔ децентрализация) + первичная разметка каждого кирпича по спектру децентрализации для маркетплейса.

Закрепление — 7 вопросов и задач

Ответьте сами, затем раскройте разбор.

  1. вопросПочему модуль 3 переиспользует тот же продукт, а не вводит новый? Что это даёт сравнению?
  2. вопросПочему девять кирпичей называются инвариантом, хотя ответы на них меняются между модулями?
  3. вопросЧто означает «спектр децентрализации» и по каким осям его измеряют?
  4. вопросПочему «всё на блокчейне» считается антипаттерном в этом курсе?
  5. задачаЗаполните матрицу 9×3 для маркетплейса: для каждого кирпича укажите аналог в М1, М2 и М3.
  6. задачаДля трёх кирпичей (Платёж, Файл работы, Поиск) разметьте позицию по спектру и обоснуйте одним предложением.
  7. задачаВыберите один кирпич, который вы осознанно оставите централизованным, и сформулируйте критерий обоснования.
Разбор ответов
  1. Один продукт изолирует переменную «парадигма»: различия в цене, доверии и латентности видны напрямую, потому что домен и требования неизменны. Новый продукт смешал бы эффект домена с эффектом парадигмы.
  2. Кирпичи — это вопросы («где исполняется код?»), а не ответы. Вопросы универсальны для любой системы; меняется лишь технология ответа, что и позволяет сравнивать парадигмы по общей сетке.
  3. Это непрерывная шкала от централизованного до полностью децентрализованного. Оси: стоимость, латентность, доверие, суверенитет данных, сложность эксплуатации, lock-in, цензуроустойчивость.
  4. Запись в состояние стоит газа, латентность ограничена финальностью блока, всё публично. Для ленты или поиска это неоправданная плата — выгоднее гибрид; on-chain нужен лишь там, где ценна неоспоримость.
  5. Образец: Compute — VM / Cloud Run / контракт; Storage — S3 / GCS / IPFS; Identity — OIDC / Identity Platform / SIWE; и так по всем девяти строкам таблицы соответствий.
  6. Платёж — полностью децентрализованно (атомарность и неоспоримость); Файл работы — гибрид (IPFS дёшево, но pinning платный); Поиск — централизованно (индекс в газе нерентабелен).
  7. Образец: полнотекстовый поиск остаётся централизованным; критерий — операция не требует публичной неоспоримой истины и чувствительна к латентности и стоимости записи.
