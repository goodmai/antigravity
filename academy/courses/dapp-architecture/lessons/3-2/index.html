Децентрализованный compute

Канон: Akash docs, Fluence docs.

Это децентрализованный аналог кирпича Compute из модулей 1–2 (Cloud Run / GKE). Вместо одного провайдера — рынок вычислений, где ноды анонимные и недоверенные. Меняется не «где крутится контейнер», а модель оплаты и модель доверия.

1. Рынок вычислений вместо провайдера

Akash — обратный аукцион: вы публикуете манифест (SDL), провайдеры делают ставки, вы выбираете и фондируете escrow в токене. Golem и Flux — похожая модель для батч-задач; Fluence — peer-to-peer исполнение функций с верификацией. Общая идея: нет SLA-контракта с юрлицом, есть экономический стимул ноды отработать честно.

  • Оплата: escrow в токене (AKT), списание поблочно, закрытие lease возвращает остаток.
  • Доверие к ноде: провайдер видит ваш контейнер. Секреты внутрь не кладём; данные шифруем в покое.
  • Reproducible builds: образ должен быть детерминирован (pinned digest, а не :latest), иначе нечем проверить, что запущено именно то.

2. SDL: декларативный манифест деплоя

---
version: "2.0"
services:
  web:
    image: myorg/marketplace-api@sha256:9f2b...   # pinned digest
    expose:
      - port: 8080
        as: 80
        to: [{ global: true }]
profiles:
  compute:
    web:
      resources: { cpu: { units: 0.5 }, memory: { size: 512Mi }, storage: { size: 1Gi } }
  placement:
    dc:
      pricing:
        web: { denom: uakt, amount: 1000 }   # max ставка
deployment:
  web:
    dc: { profile: web, count: 1 }

Деплой → провайдеры делают bid → выбор lease → escrow → запуск. Нет консоли облака с кнопкой «масштабировать»; масштаб — это новый bid.

Пример использования элементов

Для маркетплейса hot-path (API оплаты, лента) держим на облаке: нужен жёсткий SLA и низкая латентность. На Akash выносим stateless батч: генерация превью загруженных работ, перекодирование медиа, переиндексация. Эти задачи терпят минуты на lease и не содержат секретов.

flow: автор загрузил работу
  → событие в очереди
  → воркер на Akash берёт задачу (образ pinned digest)
  → генерит превью, кладёт в IPFS (урок 3.5)
  → пишет CID обратно; lease закрывается, escrow освобождён

Так мы получаем экономию на тяжёлом CPU без риска для денежного пути.

Закрепление — 7 вопросов и задач

Ответьте сами, затем раскройте разбор.

  1. вопросЧем модель оплаты Akash принципиально отличается от биллинга Cloud Run?
  2. вопросПочему недопустимо класть секреты внутрь контейнера, запускаемого на анонимной ноде?
  3. вопросЗачем нужен pinned digest образа вместо тега :latest в SDL?
  4. вопросНа чём держится доверие к провайдеру Akash, если SLA-контракта с юрлицом нет?
  5. задачаНапишите SDL-профиль для stateless-воркера превью (cpu, memory, без публичного порта).
  6. задачаСформулируйте критерий, по которому задача маркетплейса подходит для Akash, и приведите две подходящие и одну неподходящую.
  7. задачаНабросайте ADR-04: контекст, решение (hot-path в облаке, батч на Akash), последствия.
Разбор ответов
  1. Cloud Run — постфактумный биллинг по юрлицу-провайдеру. Akash — предоплаченный escrow в токене, списываемый поблочно; нет счёта, есть фонд lease, и волатильность токена влияет на стоимость.
  2. Провайдер технически имеет доступ к runtime контейнера и может прочитать переменные окружения и файлы. Секрет нужно держать снаружи (внешний KMS/подпись) и передавать как короткоживущий токен.
  3. Digest фиксирует точный bytecode образа. С :latest нельзя доказать, что нода запустила именно проверенную сборку — ломается reproducible build и аудит.
  4. На экономическом стимуле: провайдер заработает только при честной отработке lease, а несоответствие манифесту приводит к разрыву lease и потере дохода. Это вероятностная гарантия, а не контрактная.
  5. Образец: профиль compute с cpu 0.25, memory 256Mi, storage 512Mi и без блока expose — воркер не принимает входящий трафик, только тянет задачи из очереди.
  6. Критерий: stateless, без секретов, терпит минуты задержки старта. Подходят: генерация превью, перекодирование медиа. Не подходит: API оплаты (нужен SLA и низкая латентность hot-path).
  7. Контекст: тяжёлый CPU на превью дорог в облаке. Решение: hot-path в Cloud Run, батч на Akash с pinned digest. Последствия: экономия CPU, ценой сложности мониторинга lease и волатильности токена.
