API-стили и контракты

Канон: REST (Fielding, гл. 5), OpenAPI Specification.

Контракт — это обещание между командами. Стиль API выбирается по характеру взаимодействия, а не по моде.

СтильКогдаСлабое место
RESTресурсный CRUD, кэш на HTTPover/under-fetching
GraphQLгибкие клиенты, агрегациясложность кэша, N+1
gRPCсервис↔сервис, низкая латентностьбраузер без прокси

Обратная совместимость

  • Добавлять поля — можно; удалять/менять смысл — ломающее изменение.
  • Версионируйте контракт (/v1, media-type), а не URL «на глаз».
  • Контракт-тесты в CI ловят нарушение раньше прода.
paths:
  /works/{id}:
    get:
      responses:
        '200': { content: { application/json: { schema: { $ref: '#/components/schemas/Work' } } } }
        '404': { description: not found }
