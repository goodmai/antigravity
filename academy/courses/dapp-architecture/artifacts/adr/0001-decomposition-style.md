# ADR-0001: Стиль декомпозиции системы

- **Статус:** proposed
- **Дата:** YYYY-MM-DD
- **Решает:** кирпич Compute/границы · урок 1.3

## Контекст

Маркетплейс цифровых работ + лента + платежи. Команда из N человек,
ожидаемая нагрузка, частота изменений по контекстам различается
(Catalog меняется часто, Payments — редко, но критично).

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Цена распределённости |
|---|---|---|---|
| Монолит | простой деплой, дешёвый рефакторинг границ | общий релиз-поезд | нет |
| Модульный монолит | явные границы, один процесс | дисциплина границ вручную | низкая |
| Микросервисы | независимый деплой/масштаб | сеть, eventual consistency, ops | высокая |

## Решение

<Заполнить. Подсказка курса: начинать модульным монолитом; выделять
сервис только при доказанной независимой причине изменения/масштаба
(закон Конвея).>

## Последствия

- Что станет триггером выделения первого сервиса?
- Какие границы bounded context фиксируем сейчас?
