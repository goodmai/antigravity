Многопоточность, channels, async/await

На Android вы не имеете права блокировать main-поток, иначе ANR. Rust даёт два инструмента: OS-потоки (std::thread) и async поверх runtime'а (tokio, async-std, smol). Async на мобильных устройствах — это легковесные таски, которые не сжирают per-thread стек по 8 МБ.

OS-потоки и channels

async/await

Функция async fn возвращает Future — value, которое ничего не делает, пока не будет polled ранером (executor'ом). На Android executor — это tokio::runtime::Runtime, созданный единожды при загрузке .so.

На Playground в режиме edition = 2021 async-runtime'ов нет, поэтому демонстрируем сэмулированно: построим Future вручную через executor-в-двух-строчках futures::executor::block_on. В Android-проекте вы напишете #[tokio::main] и забудете об этом.

tokio на Android

[dependencies]
tokio = { version = "1", features = ["rt-multi-thread", "macros", "time"] }

// в Rust-ядре:
#[tokio::main(flavor = "multi_thread", worker_threads = 2)]
async fn run() -> anyhow::Result<()> {
    let resp = reqwest::get("https://example.com").await?;
    log::info!("status = {}", resp.status());
    Ok(())
}
Задание: измените double на возвращающую u64 и убедитесь, что компилятор подсветит несоответствие в pipeline. Это и есть «асинхронность с типами».
