Модули, crates и Cargo

В Rust есть три уровня организации кода: модуль внутри файла (mod), crate — единица компиляции (бинарь или библиотека), и workspace — несколько crate'ов с общим Cargo.lock. Для Rust-ядра Android-приложения каноничный приём — workspace из core/ (логика) и android/ (FFI-обёртка).

Модули и видимость

// src/lib.rs
pub mod auth {
    pub fn sign_in(token: &str) -> bool { !token.is_empty() }
    fn hash(_t: &str) -> u64 { 0 }      // приватная
}

// Использование извне:
// my_crate::auth::sign_in("abc");

Cargo.toml: зависимости и features

Cargo читает Cargo.toml и резолвит зависимости из crates.io. Используйте features, чтобы условно подключать функционал — это позволит собрать одно и то же ядро для Android, iOS и WASM без ifdef-ов. 

[package]
name = "rustdroid-core"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib", "rlib"]        # cdylib — для .so под Android

[dependencies]
serde = { version = "1", features = ["derive"] }
log   = "0.4"

[features]
default = []
android = ["jni", "android_logger"]
jni      = ["dep:jni"]
android_logger = ["dep:android_logger"]

[target.'cfg(target_os = "android")'.dependencies]
jni = { version = "0.21", optional = true }
android_logger = { version = "0.14", optional = true }

Workspace для Rust-Android

# Cargo.toml в корне
[workspace]
members = ["core", "android-ffi", "ios-ffi"]
resolver = "2"

Workspace даёт общую папку target/ и одну версию каждого транзитивного крейта — это критично, когда вы линкуете tokio и в core, и в android-ffi: разные версии символов сломают сборку .so.
