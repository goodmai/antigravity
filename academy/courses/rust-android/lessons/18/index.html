Криптография и сетевые запросы

Конъюнкция «нативная скорость + memory safety + кросс-платформенный код» делает Rust любимым местом для крипто-стека мобильного приложения. Здесь мы соберём канонический набор: ring / aes-gcm для крипто и reqwest + rustls для HTTPS.

Cargo.toml

[dependencies]
sha2     = "0.10"
aes-gcm  = "0.10"
argon2   = "0.5"
rand     = "0.8"
reqwest  = { version = "0.12", default-features = false, features = ["rustls-tls", "json"] }
tokio    = { version = "1", features = ["rt-multi-thread", "macros"] }
serde    = { version = "1", features = ["derive"] }
serde_json = "1"

Важно: default-features = false отключает openssl в reqwest. Линковать OpenSSL под Android — головная боль (нужен OPENSSL_DIR). С rustls-tls всё работает «из коробки» — это чисто Rust-реализация TLS.

Хеширование

AES-GCM шифрование

use aes_gcm::{Aes256Gcm, Key, Nonce, aead::{Aead, KeyInit}};
use rand::RngCore;

fn encrypt(plain: &[u8], key: &[u8; 32]) -> (Vec<u8>, [u8; 12]) {
    let cipher = Aes256Gcm::new(Key::<Aes256Gcm>::from_slice(key));
    let mut nonce_bytes = [0u8; 12];
    rand::thread_rng().fill_bytes(&mut nonce_bytes);
    let nonce = Nonce::from_slice(&nonce_bytes);
    let ct = cipher.encrypt(nonce, plain).unwrap();
    (ct, nonce_bytes)
}

Async HTTP

#[derive(serde::Deserialize)]
struct Status { ok: bool }

#[tokio::main]
async fn fetch() -> anyhow::Result<()> {
    let s: Status = reqwest::Client::new()
        .get("https://api.example.com/status")
        .send().await?
        .json().await?;
    log::info!("ok = {}", s.ok);
    Ok(())
}

Network Security Config на Android 14+

Не забудьте android:usesCleartextTraffic="false" в манифесте и, если делаете certificate pinning, прокиньте отпечатки в Rust через rustls::client::WebPkiVerifier с кастомным набором roots.

Задание: в реальном проекте добавьте argon2id для деривации ключа AES из мастер-пароля пользователя. См. Lab 12 — Capstone Password Manager.
