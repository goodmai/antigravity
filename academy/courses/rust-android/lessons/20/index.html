Безопасность, supply chain, fuzzing

Google в пост 2021 года сообщил, что 70 % CVE в Android — memory safety. В 2023-м Android Platform Security публично заявил, что «no memory safety vulnerabilities have been found in Android's Rust code». Это уровень, к которому стремимся.

Запрет unsafe в библиотеках высокого уровня

На уровне «бизнес-логики» поставьте директиву и пусть компилятор следит: 

// в верхушке lib.rs
#![forbid(unsafe_code)]

unsafe остаётся в FFI-обёртке (это неизбежно), но всё остальное должно быть safe.

cargo-audit и cargo-deny

cargo install cargo-audit cargo-deny
cargo audit            # CVE по transitive-зависимостям из RustSec advisory-db
cargo deny check       # лицензии, banned crates, дубликаты версий

Запускайте в CI на каждый PR. Пример deny.toml: 

[bans]
multiple-versions = "warn"
deny = [
  { name = "openssl" },          # используем rustls
  { name = "openssl-sys" },
]

[licenses]
allow = ["MIT", "Apache-2.0", "BSD-2-Clause", "BSD-3-Clause", "ISC"]
deny  = ["GPL-3.0", "AGPL-3.0"]

Fuzzing с cargo-fuzz

cargo install cargo-fuzz
cargo fuzz init
# fuzz/fuzz_targets/parse_jwt.rs
#![no_main]
use libfuzzer_sys::fuzz_target;
fuzz_target!(|data: &[u8]| {
    let _ = mycrate::jwt::parse(data);
});

cargo fuzz run parse_jwt -- -max_total_time=300

Hardened build на Android

  • PIE — Position Independent Executable: NDK включает по умолчанию.
  • RELRO: -Wl,-z,relro,-z,now.
  • Stack canaries: -Cforce-frame-pointers, -Z stack-protector=all (nightly).
  • Control Flow Integrity: -Cllvm-args=-fsanitize=cfi для LTO-сборок.
  • Скрыть DEBUG-build от Play Store: всегда strip = "symbols" для public release.

Проверка зависимостей на Android-несовместимость

Не все Rust-крейты собираются под Android. cargo-deny + cargo-watch + матрица CI на 4 target'а решают 99% случаев.

Задание: уберите комментарий из последней строки песочницы — компилятор откажет с «unsafe is not allowed by #![forbid]». Это и есть статическая гарантия безопасности на уровне модуля.
