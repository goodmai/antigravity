Типы и значения

В Rust каждое значение имеет статический тип, известный на этапе компиляции. Большинство типов выводится автоматически — но именно строгий тип гарантирует, что i32 не сложится с u8 молча и что String не дойдёт по ABI до Kotlin в виде сырого jbyteArray.

Скалярные типы

  • Целые: i8 i16 i32 i64 i128 isize и беззнаковые u8 … usize. По умолчанию литерал 1 — это i32.
  • С плавающей точкой: f32, f64 (по умолчанию).
  • Bool: true / false, 1 байт.
  • Char: 32-битный Unicode scalar value, не байт.

let, mut и shadowing

Все привязки иммутабельны по умолчанию. let mut делает переменную изменяемой. Shadowing — это перепривязка под тем же именем; новый let заводит новое значение, возможно другого типа, не нарушая иммутабельность.

Инференция типов и литералы

Если контекст не даёт компилятору однозначно вывести тип, можно дописать суффикс к литералу (1u8, 3.14f32) или указать тип в let. На Android это особенно важно: jint = i32, jlong = i64 — несовпадение размеров обнаружится только в рантайме.

Константы и static

const вычисляется на этапе компиляции, не имеет адреса и встраивается в каждое место использования. static имеет фиксированный адрес в памяти; static mut — это unsafe, потому что ломает гарантии borrow-checker'а. 

const MIN_ANDROID_API: u32 = 26;
static APP_NAME: &str = "RustDroid";
Задание: в первой песочнице добавьте let api_level: u8 = api_level as u8; и убедитесь, что api_level == 34. Затем попробуйте присвоить api_level = 35 без mut — компилятор откажется.
