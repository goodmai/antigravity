JNI: сигнатуры, JNIEnv, ссылки

JNI (Java Native Interface) — это бинарный контракт между JVM и нативной библиотекой. В Rust его проще всего использовать через крейт jni. Главные понятия: JNIEnv (контекст текущего потока), JClass / JObject (ссылки на Java-классы), сигнатуры (mangled-имена и type descriptors).

Сигнатура метода

Имя нативной функции должно быть длинным и канонизированным: Java_<package>_<Class>_<method>. Точки заменяются на подчёркивания, $ — на _00024. 

// Kotlin:
package io.daskibo.rust

class Hasher {
    external fun sha256(input: String): String
}

// Rust:
#[no_mangle]
pub extern "system" fn Java_io_daskibo_rust_Hasher_sha256(
    mut env: jni::JNIEnv,
    _class: jni::objects::JClass,
    input: jni::objects::JString,
) -> jni::sys::jstring {
    let s: String = env.get_string(&input).unwrap().into();
    let digest = hex::encode(sha2::Sha256::digest(s.as_bytes()));
    env.new_string(digest).unwrap().into_raw()
}

Local vs. Global references

Любой JObject, который вы получили из JNIEnv в рамках JNI-вызова — локальная ссылка, она освободится автоматически. Если вы хотите кэшировать объект между вызовами — возьмите global ref через env.new_global_ref(&obj) и держите его в OnceCell<GlobalRef>.
