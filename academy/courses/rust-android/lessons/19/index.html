Производительность: LTO, аллокаторы, simpleperf

Rust по умолчанию строит release-сборку с opt-level=3, но на Android можно выжать ещё:

Профиль release

[profile.release]
opt-level = 3
lto = "fat"           # link-time optimization, +5-15% perf, +30% время линковки
codegen-units = 1     # одна codegen-юнита → лучше LTO
strip = "symbols"     # убрать debug-символы из .so (на Play Store кладите debug отдельно)
panic = "abort"       # без unwind-таблиц — на Android-сборке резко меньше .so
overflow-checks = false

PGO (Profile-Guided Optimization)

С Rust 1.74+ и LLVM 17 в Android NDK r26+ можно собрать PGO-builds: 

# 1. instrumented build:
RUSTFLAGS="-Cprofile-generate=/tmp/pgo" cargo ndk -t arm64-v8a build --release

# 2. погонять приложение на устройстве — соберутся .profraw

# 3. слить и пересобрать:
llvm-profdata merge -o /tmp/pgo/merged.profdata /tmp/pgo/*.profraw
RUSTFLAGS="-Cprofile-use=/tmp/pgo/merged.profdata" cargo ndk -t arm64-v8a build --release

Аллокаторы

Системный libc на Android — Scudo: secure, но не самый быстрый. Для CPU-bound сценариев замените на mimalloc: 

#[global_allocator]
static GLOBAL: mimalloc::MiMalloc = mimalloc::MiMalloc;

Профилирование на устройстве: simpleperf

cd $ANDROID_NDK_HOME/simpleperf
./app_profiler.py -p io.daskibo.password -a .MainActivity \
    -lib ../../../../path/to/cargo/target/aarch64-linux-android/release/
./report_html.py

На выходе — flame-graph с символами вашей Rust-функции. Без шага -lib simpleperf не найдёт Rust-символы и покажет только libdaskibo.so+0x1234.

Маленький бенч на playground'е

Задание: на устройстве запустите simpleperf record с lock'ом на «маленьком ядре» (--cpu 0) — это полезно для сравнения «honest» single-thread производительности между нативным и Kotlin-вариантом.
