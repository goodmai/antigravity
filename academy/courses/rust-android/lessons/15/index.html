Модуль III · Lesson 15

Сборка .so-библиотеки и загрузка из Kotlin

В этом уроке мы соберём первый рабочий Rust→Kotlin pipeline: libdaskibo.so экспортирует функцию add(i32, i32) → i32, а Kotlin её вызывает.

Шаги

Cargo.toml объявляет cdylib

[package]
name    = "daskibo"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib"]   # ← обязательно, иначе .so не появится

[dependencies]
jni = { version = "0.21", default-features = false }

src/lib.rs — экспортируемая функция

use jni::JNIEnv;
use jni::objects::JClass;
use jni::sys::jint;

#[no_mangle]
pub extern "system" fn Java_io_daskibo_NativeKt_add(
    _env: JNIEnv,
    _class: JClass,
    a: jint,
    b: jint,
) -> jint {
    a + b
}

Сборка для 3 архитектур

cargo ndk \
  -t arm64-v8a -t armeabi-v7a -t x86_64 \
  -o ./app/src/main/jniLibs \
  build --release

cargo-ndk положит .so-файлы в каноничный каталог Android, откуда AGP их подхватит при сборке APK/AAB.

Kotlin: загрузка и вызов

// app/src/main/java/io/daskibo/Native.kt
package io.daskibo

object Native {
    init { System.loadLibrary("daskibo") }   // имя без префикса lib и без .so
    external fun add(a: Int, b: Int): Int
}

// MainActivity.kt
val sum = Native.add(2, 3)
Log.d("daskibo", "sum=$sum")  // → 5

Проверка через nm

$ANDROID_NDK_HOME/toolchains/llvm/prebuilt/linux-x86_64/bin/llvm-nm \
  -D app/src/main/jniLibs/arm64-v8a/libdaskibo.so | grep Java_

# 0000000000001234 T Java_io_daskibo_NativeKt_add

Видим символ — значит, JNI его найдёт. Если символа нет — либо забыли #[no_mangle], либо cdylib, либо опечатались в имени.

Эмулируем имя System.loadLibrary

Android-loader ищет файл с шаблоном lib<name>.so. Песочница ниже воссоздаёт эту логику — пригодится для отладки скриптов сборки.

Задание: добавьте функцию Java_io_daskibo_NativeKt_sub в lib.rs, пересоберите cargo ndk … build --release и убедитесь, что новый символ виден в llvm-nm.
