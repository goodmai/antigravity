Ownership, borrowing, slices

Главная фишка Rust — модель владения. Три правила, проверяемых компилятором:

  1. У каждого значения ровно один владелец.
  2. В один момент — либо одна &mut T-ссылка, либо сколько угодно &T-ссылок.
  3. Когда владелец выходит из scope — значение освобождается через Drop.

Эти правила исключают use-after-free, double-free и data race без сборщика мусора. Когда вы будете передавать байты через JNI, именно ownership решит, «кто должен освобождать буфер» — Rust или JVM.

Move vs. Copy

Заимствование

Чтобы не отдавать владение, передавайте &T (shared) или &mut T (exclusive). Это и есть borrowing. Borrow-checker следит, чтобы не возникло висячих ссылок и параллельной записи.

Slices: &str vs String

String — кучный, изменяемый, владеет байтами. &str — slice, ссылка на UTF-8 байты без владения. Принято: входные строки — &str, поля структур — String. В JNI на Rust-стороне Java-строка приходит как JString и превращается в &str через env.get_string().

Задание: попробуйте после take(s) добавить println!("{s}");. Borrow-checker откажет — s уже не владелец. Замените на take(s.clone()) — и компилятор будет доволен.
