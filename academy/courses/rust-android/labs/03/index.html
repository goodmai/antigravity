Lab 03 — Rust вызывает Android Toast

В предыдущих лабах мы шли «снизу вверх»: Kotlin → Rust. Теперь обратный путь: Rust сам вызывает Java API. Это пригождается, когда Rust-код знает о критичном событии (например, ошибке расшифровки) и хочет показать нативный UI без посредников.

Уровень
Intermediate
Время
~60 мин

Артефакт
Rust-функция, показывающая Toast

Идея

  1. Kotlin передаёт Rust ссылку на Activity.
  2. Rust получает JObject и через JNIEnv::call_static_method вызывает Toast.makeText(...).
  3. Дальше — .show() на полученной локальной ссылке.

Rust-код

use jni::{JNIEnv, objects::{JClass, JObject, JString, JValue}};

#[no_mangle]
pub extern "system" fn Java_io_daskibo_toast_NativeKt_toast(
    mut env: JNIEnv,
    _class: JClass,
    activity: JObject,
    msg: JString,
) {
    let toast_cls = env.find_class("android/widget/Toast").unwrap();
    let length_short = JValue::Int(0);

    // CharSequence-параметр: передаём JString — он реализует CharSequence.
    let toast = env.call_static_method(
        toast_cls,
        "makeText",
        "(Landroid/content/Context;Ljava/lang/CharSequence;I)Landroid/widget/Toast;",
        &[JValue::Object(&activity), JValue::Object(&msg.into()), length_short],
    ).unwrap().l().unwrap();

    env.call_method(toast, "show", "()V", &[]).unwrap();
}

Kotlin-код

// app/.../Native.kt
object Native {
    init { System.loadLibrary("toaster") }
    external fun toast(activity: Activity, message: String)
}

// MainActivity.kt — по кнопке
Native.toast(this, "Привет из Rust!")

UI Thread

Toast.show() требует main-looper. Если вы вызвали Native.toast() из background-потока — будет RuntimeException. Решение: либо гарантируйте вызов с main-thread в Kotlin, либо в Rust поднимите Handler: 

// в Kotlin — самый простой путь:
runOnUiThread { Native.toast(this, "from rust on main thread") }
Бонус: добавьте параметр duration: i32 и используйте Toast.LENGTH_LONG (значение 1) для важных сообщений.
