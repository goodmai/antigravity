Lab 11 — Crash reporting и symbolication

Когда Rust-код в продакшене упадёт (а он упадёт — хотя бы из-за panic! в библиотечном крейте), нужны бэктрейсы с символами, а не 0xdeadbeef. Здесь — два пути: sentry-rust (быстро, бесплатно до лимита) и breakpad (native minidumps, как у Firefox/Chrome).

Путь A — sentry-rust

[dependencies]
sentry = { version = "0.34", default-features = false, features = ["backtrace", "contexts", "panic"] }
sentry-android-trace = "0.2"
use once_cell::sync::OnceCell;

static _SENTRY: OnceCell<sentry::ClientInitGuard> = OnceCell::new();

#[no_mangle]
pub extern "system" fn JNI_OnLoad(_vm: jni::JavaVM, _: *mut std::ffi::c_void) -> jni::sys::jint {
    let guard = sentry::init(("https://YOUR_DSN@sentry.io/123", sentry::ClientOptions {
        release: sentry::release_name!(),
        traces_sample_rate: 0.1,
        ..Default::default()
    }));
    let _ = _SENTRY.set(guard);
    jni::sys::JNI_VERSION_1_6
}

Заливка debug-символов в Sentry

npm i -g @sentry/cli

# в CI после релиз-сборки:
sentry-cli login --auth-token $SENTRY_AUTH
sentry-cli debug-files upload \
    --org daskibo --project rust-android \
    target/aarch64-linux-android/release/libdaskibo.so

Путь B — Google Play native crashes

Play Console сам собирает minidump'ы. Чтобы Crashes показывали Rust-функции, загрузите debug symbols вместе с AAB через bundletool: 

./gradlew bundleRelease

# Внутри AAB положите BUNDLE-METADATA/com.android.tools.build.debugsymbols/*/libdaskibo.so.dbg
# Подробно: developer.android.com/guide/playcore/app-bundle/native-debug

Для Rust символы получаются автоматически, если у вас в Cargo.toml стоит [profile.release] debug = true, strip = "none", а финальный .so уже strip --strip-debug'ается на CI.

Симулируем «парсер бэктрейса»

Бонус: подключите log и sentry-log — все log::error! в Rust автоматически уходят как breadcrumbs в Sentry, что упрощает диагностику.
