MetaMask & кошельки: ключи, подпись, транзакция

Любая операция в Web3 — это транзакция, подписанная приватным ключом. Прежде чем писать смарт-контракты, нужно понять, что такое ключ, что такое адрес, как кошелёк хранит то и другое, какие поля попадают в подпись, и почему отправленную транзакцию иногда невозможно «вернуть», но почти всегда можно заменить. Урок собирает эту базу в одном месте, чтобы дальше в курсе вы концентрировались на контрактах, а не на «как мне переподписать тип-2 транзакцию с новым nonce».

Что вы получите. После этого урока вы сможете объяснить: что такое seed → ключи → адрес; чем подпись отличается от транзакции; зачем нужен nonce и chainId; как считается газ в EIP-1559; как отменить или ускорить «зависшую» транзакцию; чем горячий кошелёк отличается от холодного; и какие библиотеки нужны фронтенду для всего этого.

1. Что такое кошелёк

Кошелёк не хранит токены. Токены живут на блокчейне в mapping(address ⇒ uint256) смарт-контракта (ERC-20) или в нативном балансе аккаунта. Кошелёк хранит ключ, которым вы доказываете право распоряжаться этим балансом. Утратил ключ — утратил доступ; никто (ни MetaMask, ни Ethereum Foundation) не может его восстановить.

1.1 Seed-фраза → приватный ключ → публичный ключ → адрес

Современный кошелёк — это HD-wallet (Hierarchical Deterministic, BIP-32/39/44). Из одной seed-фразы детерминированно выводятся миллиарды аккаунтов: 

BIP-39 mnemonic   "test test test test test test test test test test test junk"
       │
       │  PBKDF2-HMAC-SHA512(mnemonic, "mnemonic" + passphrase, 2048)
       ▼
512-bit seed       fbd6e0a … (64 байта)
       │
       │  BIP-32  HMAC-SHA512("Bitcoin seed", seed)
       ▼
master extended key  (k_m, c_m)
       │
       │  derive по пути BIP-44:  m / purpose' / coin_type' / account' / change / index
       │  для Ethereum:           m / 44'      / 60'        / 0'       / 0      / i
       ▼
private key (32 байта, secp256k1)
       │
       │  публичный ключ = priv · G  (генератор кривой secp256k1)
       ▼
public key  (uncompressed, 64 байта)
       │
       │  keccak256(pubKey)[-20:]
       ▼
address    0x70997970C51812dc3A010C7d01b50e0d17dc79C8

Несколько важных следствий:

  • Адрес — это последние 20 байт keccak256 от публичного ключа. Поэтому проверка подписи на блокчейне = «восстановить публичный ключ из подписи → взять keccak256 → сравнить с адресом» (ecrecover).
  • EIP-55 checksum добавляет mixed-case к hex-адресу (0xAbCd…) для защиты от опечаток — на сети все буквы одинаковы, но кошелёк/Explorer считают checksum и подсвечивают ошибку.
  • Passphrase (25-е слово) в BIP-39 — это дополнительная строка к seed-фразе, которая даёт совершенно другой набор ключей. «Скрытый кошелёк» = та же seed-фраза, но с другим passphrase.

Попробуйте: введите свою или сгенерируйте новую mnemonic — увидите, как из одной фразы детерминированно выводятся первые пять Ethereum-аккаунтов. По умолчанию подставлена стандартная тестовая mnemonic Anvil / Hardhat — адреса из неё знают все, поэтому никаких реальных средств туда не кладите.

1.2 Создание и импорт в MetaMask

В UI это выглядит как два сценария — но криптографически они идентичны.

  • Создание. Расширение генерирует 12-словную mnemonic из 128 бит энтропии (crypto.getRandomValues) и просит вас сохранить её. После этого все «Account 1», «Account 2»… выводятся по индексу из BIP-44 пути.
  • Импорт по seed. Вы вводите 12/24 слова, кошелёк проверяет контрольную сумму BIP-39 (последнее слово — это checksum первых) и пересоздаёт ту же HD-tree. Поэтому ваш импортированный кошелёк сразу видит те же адреса и историю.
  • Импорт по приватному ключу — добавляет одиночный аккаунт не в HD-tree. Такой аккаунт нельзя восстановить из seed-фразы кошелька; беречь его нужно отдельно.

2. Подпись: что именно подписывается

MetaMask умеет три типа подписей. Понимание различий критично — большинство фишинг-атак паразитируют на том, что пользователь не видит, что он подписывает.

МетодЧто подписываетсяПрименение
personal_sign Префиксированная строка: "\x19Ethereum Signed Message:\n" + len + msg Логин по подписи (SIWE), доказательство владения адресом
eth_signTypedData_v4 (EIP-712) Структурированные данные с типами и доменом Permit для ERC-20, OpenSea-ордера, gasless-операции
eth_sendTransaction RLP-кодированная транзакция, отправляется в mempool Любое изменение состояния: перевод, вызов контракта, деплой

Только третий тип стоит газ и попадает в блокчейн. Первые два — это «офчейн»-подписи, которые сервер или контракт может проверить позже.

3. Анатомия транзакции

Транзакция на EVM-сети — это 9-12 полей, RLP-сериализованные и подписанные приватным ключом. Минимальная сущность: 

{
  type:                 2,                                  // 0 / 1 / 2 — см. ниже
  chainId:              1,                                  // EIP-155 — для replay protection
  nonce:                42,                                 // счётчик транзакций отправителя
  maxFeePerGas:         30_000_000_000n,                    // 30 gwei — потолок суммарной цены
  maxPriorityFeePerGas:  1_500_000_000n,                    // 1.5 gwei — чаевые валидатору
  gas:                  21_000n,                            // лимит газа (gasLimit)
  to:                   "0x70997…79C8",                     // null = деплой контракта
  value:                1_000_000_000_000_000_000n,         // 1 ETH в wei
  data:                 "0xa9059cbb…",                      // calldata: пустая = native transfer
  accessList:           []                                  // EIP-2930, опционально
}

3.1 Nonce

nonce — это последовательный счётчик транзакций аккаунта. Каждая ваша транзакция должна иметь следующий по порядку nonce. Если вы отправите nonce=10, а потом nonce=12 — вторая будет висеть в mempool как «зависшая», пока не появится nonce=11.

Это даёт нам три практических механизма:

  • Replay protection — одну и ту же транзакцию нельзя провести дважды (после майнинга nonce увеличился).
  • Отмена транзакции — отправляем новую транзакцию с тем же nonce, но to = моему же адресу, value = 0, и более высокий maxFeePerGas. Валидатор включит ту, что платит больше; старая молча выпадет из mempool.
  • Speed-up — то же самое, но to / value / data остаются прежними, мы только повышаем цену газа.

3.2 ChainId

chainId (EIP-155) включён в данные, по которым считается подпись. Поэтому транзакция, подписанная для Ethereum mainnet (1), не может быть «прокручена» на Polygon (137) — подпись окажется недействительной. Это защищает вас от cross-chain replay. В MetaMask chainId устанавливается выбранной сетью в шапке.

3.3 Газ: EIP-1559

С августа 2021 (London hard fork) Ethereum использует двухкомпонентную модель:

  • baseFeePerGas — динамическая цена, заданная сетью; растёт на 12.5% за блок, если предыдущий блок заполнен >50%, падает иначе. Сжигается (burn).
  • maxPriorityFeePerGas («tip») — ваши чаевые валидатору поверх baseFee. Чем выше — тем быстрее включат.
  • maxFeePerGas — суммарный потолок: baseFee + tip ≤ maxFee. Если рынок дороже потолка — транзакция ждёт.

Итоговая цена транзакции = gasUsed × (baseFee + min(tip, maxFee − baseFee)). MetaMask показывает вам три скорости («low / market / aggressive») — это разные tip'ы поверх текущего baseFee.

3.4 Типы транзакций

TypeEIPКогдаОсобенность
0—Legacy, до 2021gasPrice единое поле
1EIP-2930Berlin, 2021access lists — скидка на storage-read
2EIP-1559London, 2021maxFeePerGas + maxPriorityFeePerGas

3.5 Статусы транзакции

  • signed — подписана в кошельке, но ещё не отправлена.
  • pending (in mempool) — отправлена на ноду, ждёт включения в блок.
  • included / mined — попала в блок, status: 0x1 = успех.
  • reverted — попала в блок, но контракт вызвал revert, газ списан, состояние не изменилось.
  • replaced — другая транзакция с тем же nonce была включена раньше.
  • dropped — выпала из mempool (по таймауту или из-за низкого fee).
  • finalized — после ~64 слотов на Ethereum, состояние неизменно даже при reorg.

4. Отмена и ускорение транзакции

Алгоритм отмены «зависшей» транзакции в MetaMask:
  1. Откройте Activity → выберите pending-транзакцию.
  2. Cancel → MetaMask отправит self-transfer (to = ваш же адрес, value = 0) с тем же nonce, но +10% к maxFeePerGas и maxPriorityFeePerGas (это правило geth/erigon — иначе нода отбросит замену).
  3. Если первая транзакция уже включена — отмена ревертнётся, и вы заплатите ~21 000 газа за «холостой ход».
// Cancel вручную через viem:
import { createWalletClient, custom } from "viem";
import { mainnet } from "viem/chains";

const wallet = createWalletClient({ chain: mainnet, transport: custom(window.ethereum) });
await wallet.sendTransaction({
  to:                   account.address,        // себе
  value:                0n,
  nonce:                stuckNonce,             // тот же nonce
  maxFeePerGas:         oldMaxFee * 110n / 100n,
  maxPriorityFeePerGas: oldTip    * 110n / 100n,
});

5. Смарт-контракты и абстракция аккаунтов

На EVM существует два типа аккаунтов:

  • EOA (Externally Owned Account) — то, что вы привыкли называть кошельком. Контролируется приватным ключом, не имеет кода.
  • Contract Account — имеет байткод и собственный storage. Сам инициировать транзакцию не может; «оживает» только когда EOA его вызвал.

5.1 Account Abstraction (EIP-4337)

Классическая модель «EOA подписывает → контракт исполняет» неудобна: ключ нельзя ротировать, газ надо платить в native ETH, multi-sig требует отдельных транзакций. ERC-4337 (Account Abstraction) решает это без hard fork — добавляет параллельную инфраструктуру: 

EOA (signer)              Smart Account (EIP-4337)
─────────────             ───────────────────────
priv key подписывает      smart contract проверяет подпись
tx идёт сразу             UserOperation идёт в alt-mempool
                          ↓
                          Bundler упаковывает несколько UserOps в одну Ethereum-tx
                          ↓
                          EntryPoint.sol валидирует подписи & оплату
                          ↓
                          Paymaster (опционально) платит газ за пользователя
                          ↓
                          выполняется callData кошелька-контракта

Что это даёт: social recovery (восстановление по доверенным адресам вместо seed-фразы), gas в USDC (paymaster конвертирует), batched transactions (одна подпись на approve+swap+stake), session keys (временные ключи с ограничениями). Современные кошельки на AA — Safe (бывший Gnosis Safe), Argent, Biconomy Smart Account, ZeroDev Kernel.

EIP-7702 (Pectra, 2025) идёт ещё дальше: позволяет EOA временно исполнять код контракта, не теряя адреса. Это «лёгкая» AA без миграции на новый адрес.

6. Холодные и горячие кошельки

КлассГде живёт ключПлюсыМинусыПримеры
Hot (горячий) в памяти расширения/мобильного приложения Удобно, доступно из dApp одним кликом Уязвимо к malware, фишингу clipboard, утечке seed-фразы MetaMask, Rabby, Phantom, Trust Wallet
Cold (холодный) в Secure Element аппаратного устройства Ключ никогда не покидает чип, подпись на устройстве Дороже, медленнее, нужен физический доступ Ledger Nano X / S Plus, Trezor T, Keystone, GridPlus Lattice1
Smart wallet в коде контракта, ключ — EOA или passkey Social recovery, gas abstraction, multi-sig Транзакции дороже из-за overhead, не везде поддерживаются Safe, Argent, Biconomy, ZeroDev
MPC (Multi-Party Computation) осколки ключа распределены между серверами Нет single point of failure, можно «забыть пароль» Зависимость от провайдера, сложная криптография Fireblocks, Coinbase MPC, Web3Auth, Zengo
Практическое правило. Для daily-use держите ≤ суммы, которую готовы потерять, в горячем кошельке. Для накоплений — холодный Ledger / Trezor. Для активного DeFi — smart wallet с дневным лимитом и whitelist'ом адресов.

7.3 Стандарт для discovery: EIP-6963

Историческая проблема: несколько расширений-кошельков (MetaMask + Rabby + Phantom) перезаписывают друг друга в window.ethereum. EIP-6963 ввёл стандарт «multi-injected provider discovery»: каждый кошелёк диспатчит eip6963:announceProvider с уникальным rdns/icon/name, а dApp слушает eip6963:requestProvider. Все современные connect-kit'ы работают через EIP-6963 — пользователь видит реальный список установленных кошельков, а не одну «правую» иконку.

8. Минимальный workflow «подключить кошелёк»

import { createWalletClient, custom, parseEther } from "viem";
import { mainnet } from "viem/chains";

// 1) discovery
const provider = window.ethereum;
if (!provider) throw new Error("No injected wallet");

// 2) запрос доступа — открывает popup MetaMask
const [address] = await provider.request({ method: "eth_requestAccounts" });

// 3) переключение сети — EIP-3326
await provider.request({
  method: "wallet_switchEthereumChain",
  params: [{ chainId: "0x1" }],
});

// 4) клиент для запросов и подписи
const wallet = createWalletClient({
  account: address,
  chain:   mainnet,
  transport: custom(provider),
});

// 5) подпись плоского сообщения (SIWE login)
const sig = await wallet.signMessage({ message: "I am the owner of " + address });

// 6) отправка транзакции
const txHash = await wallet.sendTransaction({
  to:    "0x70997970C51812dc3A010C7d01b50e0d17dc79C8",
  value: parseEther("0.01"),
});

9. Чек-лист безопасности

  • Seed-фраза только на бумаге / металле; никогда не в облаке, скриншоте, телеге.
  • Для сумм > зарплаты — Ledger или Trezor; daily-spending — MetaMask + лимит.
  • EIP-712 подписи читайте до подписания — «approve unlimited» = доступ ко всему балансу токена.
  • Для подключения к незнакомым dApp — отдельный «burner»-аккаунт.
  • Включайте EIP-6963 / hardware-кошелёк-аппаратное подтверждение для критичных операций.
