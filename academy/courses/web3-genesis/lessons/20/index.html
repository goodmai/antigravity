Поставка dApp: Etherscan, IPFS, ENS, production-checklist

Контракт написан, протестирован, проаудирован и задеплоен — это половина пути. Вторая половина: верифицировать его на Etherscan, чтобы пользователи видели исходный код; задеплоить фронтенд на IPFS, чтобы он был неизменяемым и цензуростойким; привязать ENS-имя, чтобы пользователи попадали на правильный CID; и пройти производственный checklist — multisig, timelock, proxy admin, emergency pause.

Что вы получите. После урока вы умеете: верифицировать контракт командой forge verify-contract, в том числе с constructor args и multi-file; деплоить фронтенд на IPFS через Pinata/Filebase; установить contentHash ENS-домена на IPFS CID; использовать CREATE2 для детерминированных адресов; пройти production checklist перед mainnet-деплоем; настроить post-deploy верификацию.

1. Верификация контракта на Etherscan

Верификация — это публикация исходного кода контракта на Etherscan (или Blockscout) таким образом, чтобы платформа могла независимо скомпилировать его и убедиться, что полученный байткод совпадает с тем, что задеплоено на блокчейне. После этого любой может читать код и вызывать функции прямо из интерфейса «Read/Write Contract».

1.1 forge verify-contract

Foundry имеет встроенную поддержку верификации. Минимальный вызов: 

# Деплой + верификация одной командой (--verify флаг)
forge create src/SecureVault.sol:SecureVault \
  --rpc-url $MAINNET_RPC_URL \
  --private-key $DEPLOYER_KEY \
  --constructor-args $ADMIN_ADDRESS $GUARDIAN_ADDRESS \
  --verify \
  --etherscan-api-key $ETHERSCAN_API_KEY

# Если деплой уже произошёл — верифицировать отдельно
forge verify-contract \
  0xYourDeployedContractAddress \
  src/SecureVault.sol:SecureVault \
  --chain-id 1 \
  --etherscan-api-key $ETHERSCAN_API_KEY \
  --constructor-args $(cast abi-encode "constructor(address,address)" \
      $ADMIN_ADDRESS $GUARDIAN_ADDRESS)

1.2 foundry.toml — настройка верификатора

[profile.default]
src     = "src"
out     = "out"
libs    = ["lib"]
solc    = "0.8.24"
optimizer = true
optimizer_runs = 200

# Конфигурация верификатора
[etherscan]
mainnet = { key = "${ETHERSCAN_API_KEY}", url = "https://api.etherscan.io/api" }
sepolia = { key = "${ETHERSCAN_API_KEY}", url = "https://api-sepolia.etherscan.io/api" }
polygon = { key = "${POLYGONSCAN_API_KEY}", url = "https://api.polygonscan.com/api" }
arbitrum = { key = "${ARBISCAN_API_KEY}", url = "https://api.arbiscan.io/api" }

1.3 Encoding constructor arguments

Конструктор с аргументами требует отдельной передачи ABI-encoded аргументов. Etherscan ожидает их в hex без 0x префикса: 

# cast abi-encode возвращает hex с 0x, strip его для Etherscan
CONSTRUCTOR_ARGS=$(cast abi-encode \
  "constructor(address,address,uint256)" \
  "0xAdminAddress" \
  "0xGuardianAddress" \
  "86400" \
  | cut -c3-)   # убрать ведущий "0x"

echo "Constructor args: $CONSTRUCTOR_ARGS"

forge verify-contract \
  0xDeployedAddress \
  src/Vault.sol:Vault \
  --constructor-args $CONSTRUCTOR_ARGS \
  --chain-id 1 \
  --etherscan-api-key $ETHERSCAN_API_KEY

1.4 Верификация proxy + implementation

При деплое через UUPS или Transparent Proxy нужно верифицировать оба контракта: proxy и implementation отдельно. Etherscan автоматически определяет UUPS/Transparent паттерн и показывает «Read/Write as Proxy». 

# 1. Задеплоить implementation
forge create src/VaultV1.sol:VaultV1 \
  --rpc-url $RPC --private-key $KEY --verify --etherscan-api-key $KEY

# 2. Задеплоить ERC1967Proxy
forge create lib/openzeppelin-contracts/contracts/proxy/ERC1967/ERC1967Proxy.sol:ERC1967Proxy \
  --constructor-args $IMPL_ADDRESS $(cast calldata "initialize(address,address)" $ADMIN $GUARDIAN) \
  --rpc-url $RPC --private-key $KEY --verify --etherscan-api-key $KEY

# 3. Верифицировать proxy как proxy на Etherscan
# Это делается через UI: Contract → More Options → Is this a proxy?
# Или через API:
curl "https://api.etherscan.io/api?module=contract&action=verifyproxycontract\
&address=$PROXY_ADDRESS&apikey=$ETHERSCAN_API_KEY"

1.5 Flattening и multi-file верификация

Если автоматика не работает (необычный маршрут импортов, нестандартная структура), Etherscan поддерживает «Standard JSON» — полный input JSON компилятора, который воспроизводит компиляцию один в один: 

# Получить Standard JSON input для верификации
forge verify-contract \
  0xDeployedAddress \
  src/Vault.sol:Vault \
  --show-standard-json-input \
  > standard-json-input.json

# Загрузить через Etherscan UI:
# Contract → Verify → Standard-Json-Input → вставить файл

2. IPFS для фронтенда: неизменяемый деплой

IPFS (InterPlanetary File System) — контент-адресуемая распределённая файловая система. Файлы адресуются по своему хэшу (CID), а не по location URL. Это означает: задеплоенный фронтенд неизменяем — любое изменение создаёт новый CID. Пользователь, открывший ipfs://CID, гарантированно видит именно тот код, который вы опубликовали.

2.1 Локальный деплой через IPFS CLI

# Установить IPFS Desktop или Kubo CLI
# https://docs.ipfs.tech/install/

# Добавить папку сборки фронтенда рекурсивно
ipfs add -r ./dist --cid-version 1 --hash sha2-256

# Вывод:
# added bafybeihdwdcefgh4dqkjv67uzcmw7ojee6xedzdetojuzjevtenxquvyku dist/index.html
# added bafybeid...  dist/assets/index-BxG0Bq9F.js
# added bafybeia...  dist/assets/index-DQkl1Npq.css
# added bafybeig...  dist   ← это корневой CID папки

# Корневой CID для ENS:
IPFS_CID="bafybeig..."

echo "Deploy URL: https://ipfs.io/ipfs/$IPFS_CID"
echo "dweb.link:  https://$IPFS_CID.ipfs.dweb.link"

2.2 Pinata: managed pinning

Собственная нода IPFS не гарантирует доступность файлов — если нода упала, файлы недоступны. Pinning services (Pinata, NFT.Storage, Filebase) держат файлы «закреплёнными» в своих нодах, обеспечивая доступность. 

#!/bin/bash
# deploy-ipfs.sh — сборка + загрузка на Pinata

set -e

# Сборка фронтенда
npm run build

# Загрузка на Pinata через API v3
RESPONSE=$(curl -s -X POST "https://uploads.pinata.cloud/v3/files" \
  -H "Authorization: Bearer $PINATA_JWT" \
  -F "file=@./dist;type=application/octet-stream" \
  -F 'pinataMetadata={"name":"my-dapp-v1.2.3"}' \
  -F 'pinataOptions={"cidVersion":1}')

CID=$(echo $RESPONSE | jq -r '.data.cid')
echo "Pinned to IPFS: $CID"
echo "Gateway URL: https://gateway.pinata.cloud/ipfs/$CID"

# Сохранить CID для ENS update
echo $CID > .ipfs-cid

2.3 CIDv1 vs CIDv0

ВерсияФорматРекомендация
CIDv0 Qm... (base58btc, SHA-256, dag-pb) Легаси; поддерживается везде, но менее гибкий
CIDv1 bafy... (base32, multicodec, multihash) Рекомендуется; поддерживает разные хэш-функции, лучше для браузера

Для ENS contentHash всегда используйте CIDv1 — это требование протокола. При загрузке добавляйте флаг --cid-version 1.

3. ENS: привязка домена к IPFS CID

ENS (Ethereum Name Service) — децентрализованный DNS на Ethereum. Домен вида myprotocol.eth — это NFT (ERC-721), который хранится в ENS Registry контракте. Через resolver вы можете привязать к нему IPFS-хэш фронтенда — тогда браузеры с поддержкой ENS (Brave, MetaMask, Opera) откроют ваш dApp по имени myprotocol.eth.

3.1 Установить contentHash на IPFS CID

import { createWalletClient, http, encodeFunctionData } from "viem";
import { mainnet } from "viem/chains";
import { normalize } from "viem/ens";

// ENS Public Resolver ABI (минимальный)
const PUBLIC_RESOLVER_ABI = [
  {
    name: "setContenthash",
    type: "function",
    inputs: [
      { name: "node", type: "bytes32" },
      { name: "hash", type: "bytes" },
    ],
    outputs: [],
    stateMutability: "nonpayable",
  },
] as const;

const ENS_PUBLIC_RESOLVER = "0x4976fb03C32e5B8cfe2b6cCB31c09Ba78EBaBa41";

// Конвертировать IPFS CID в contentHash bytes
// contentHash encoding: 0xe3010170 + varint(CID length) + CID bytes
function ipfsCidToContentHash(cid: string): `0x${string}` {
  // Используем готовую библиотеку @ensdomains/content-hash
  // npm install @ensdomains/content-hash
  const { encode } = require("@ensdomains/content-hash");
  return `0x${encode("ipfs", cid)}`;
}

async function setEnsContentHash(
  ensName: string,
  ipfsCid: string,
  walletClient: ReturnType
) {
  // Вычислить namehash (bytes32 ключ в ENS Registry)
  const publicClient = createPublicClient({ chain: mainnet, transport: http() });
  const node = await publicClient.getEnsAddress({ name: normalize(ensName) });
  // Для namehash используем viem namehash utility:
  const { namehash } = await import("viem/ens");
  const nameHash = namehash(ensName);

  const contentHashBytes = ipfsCidToContentHash(ipfsCid);

  const txHash = await walletClient.writeContract({
    address: ENS_PUBLIC_RESOLVER,
    abi: PUBLIC_RESOLVER_ABI,
    functionName: "setContenthash",
    args: [nameHash, contentHashBytes],
  });

  console.log(`ENS contentHash updated. TX: ${txHash}`);
  console.log(`Visit: https://app.ens.domains/${ensName}`);
}

// Пример
const wallet = createWalletClient({
  chain: mainnet,
  transport: http(process.env.RPC_URL),
  account: privateKeyToAccount(`0x${process.env.PRIVATE_KEY}`),
});

await setEnsContentHash(
  "myprotocol.eth",
  "bafybeig...", // ваш IPFS CID
  wallet
);

4. Детерминированные деплои: CREATE2, salt, factory

Обычный CREATE даёт адрес контракта, зависящий от deployer-адреса и nonce — случайный с точки зрения пользователя. CREATE2 (EIP-1014) позволяет рассчитать адрес до деплоя — он зависит только от deployer, salt и байткода инициализации. Это открывает мощные паттерны: pre-fund контракт до деплоя, одинаковый адрес на всех сетях, factory паттерны.

4.1 CREATE2 адрес: формула

// Формула адреса при CREATE2:
// address = keccak256(0xff ++ deployer ++ salt ++ keccak256(initCode))[12:]

// Предварительный расчёт адреса в Solidity:
function computeAddress(
    address deployer,
    bytes32 salt,
    bytes32 initCodeHash
) internal pure returns (address) {
    return address(uint160(uint256(keccak256(abi.encodePacked(
        bytes1(0xff),
        deployer,
        salt,
        initCodeHash
    )))));
}

// Предварительный расчёт в TypeScript (viem):
import { getCreate2Address, keccak256, encodeDeployData } from "viem";

const initCode = encodeDeployData({
  abi: VaultABI,
  bytecode: VaultBytecode,
  args: [adminAddress, guardianAddress],
});

const predictedAddress = getCreate2Address({
  from: FACTORY_ADDRESS,
  salt: keccak256(toHex("vault-v1-mainnet")),
  bytecodeHash: keccak256(initCode),
});

console.log("Vault will be deployed to:", predictedAddress);
// Теперь можно заранее отправить ETH на этот адрес или настроить allowances

4.2 Determinstic Factory контракт

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract DeterministicFactory {
    event Deployed(address indexed contractAddress, bytes32 indexed salt);

    /// @notice Задеплоить контракт с предсказуемым адресом через CREATE2
    function deploy(bytes32 salt, bytes memory initCode)
        external
        returns (address deployed)
    {
        assembly {
            deployed := create2(
                callvalue(),           // value (ETH) для нового контракта
                add(initCode, 0x20),   // указатель на начало bytecode
                mload(initCode),       // длина bytecode
                salt
            )
        }
        require(deployed != address(0), "CREATE2 failed");
        emit Deployed(deployed, salt);
    }

    /// @notice Предварительно рассчитать адрес без деплоя
    function computeAddress(bytes32 salt, bytes32 initCodeHash)
        external
        view
        returns (address)
    {
        return address(uint160(uint256(keccak256(abi.encodePacked(
            bytes1(0xff), address(this), salt, initCodeHash
        )))));
    }
}

4.3 Foundry script с CREATE2

// script/DeployVault.s.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "forge-std/Script.sol";
import "../src/SecureVault.sol";

contract DeployVault is Script {
    // Используем Foundry встроенный CREATE2 factory (0x4e59b44847b379578588920cA78FbF26c0B4956C)
    address constant CREATE2_FACTORY = 0x4e59b44847b379578588920cA78FbF26c0B4956C;

    function run() external {
        uint256 deployerKey = vm.envUint("DEPLOYER_KEY");
        address admin    = vm.envAddress("ADMIN_ADDRESS");
        address guardian = vm.envAddress("GUARDIAN_ADDRESS");

        // Одинаковый salt → одинаковый адрес на всех сетях
        bytes32 salt = keccak256("securevault.v1.production");

        vm.startBroadcast(deployerKey);

        // Предварительный расчёт адреса
        bytes memory initCode = abi.encodePacked(
            type(SecureVault).creationCode,
            abi.encode(admin, guardian)
        );
        bytes32 initCodeHash = keccak256(initCode);

        address predicted = address(uint160(uint256(keccak256(abi.encodePacked(
            bytes1(0xff), CREATE2_FACTORY, salt, initCodeHash
        )))));
        console.log("Predicted address:", predicted);

        // Деплой через Foundry CREATE2 factory
        SecureVault vault = new SecureVault{salt: salt}(admin, guardian);

        require(address(vault) == predicted, "Address mismatch");
        console.log("Deployed to:", address(vault));

        vm.stopBroadcast();
    }
}

# Запуск deployment script
forge script script/DeployVault.s.sol:DeployVault \
  --rpc-url $MAINNET_RPC_URL \
  --broadcast \
  --verify \
  --etherscan-api-key $ETHERSCAN_API_KEY \
  -vvvv

# --broadcast  — реальная отправка транзакций
# --verify     — автоматическая верификация на Etherscan
# -vvvv        — максимальная детализация логов

5. Production deployment checklist

Перед деплоем в mainnet пройдите этот чеклист. Каждый пункт — это либо предотвращённый exploit, либо сохранённое время при инциденте.

#ПунктИнструмент / стандарт
1 Multisig deployer — деплой из Safe 3-of-5, не с EOA-кошелька Safe (Gnosis) + Foundry --sender
2 Timelock controller — все admin-функции за 48ч задержкой OZ TimelockController
3 Proxy admin — управление upgrades через TimelockController OZ ProxyAdmin + UUPS
4 Emergency pause — guardian мультисиг может паузить немедленно OZ Pausable + GUARDIAN_ROLE
5 Аудит — минимум один независимый аудит, исправлены все critical/high Trail of Bits / Spearbit / Code4rena
6 Bug bounty — активная программа до деплоя (Immunefi) Immunefi / HackerOne
7 Tenderly мониторинг — алерты настроены до деплоя Tenderly Alerts + Web3 Actions
8 Тесты на форке mainnet — forge test --fork-url прошли Foundry mainnet fork
9 Детерминированный адрес — одинаковый на всех сетях через CREATE2 CREATE2 + Foundry script
10 Incident runbook — задокументированы шаги при инциденте Notion / Confluence

5.1 TimelockController + ProxyAdmin

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "@openzeppelin/contracts/governance/TimelockController.sol";
import "@openzeppelin/contracts/proxy/transparent/ProxyAdmin.sol";

// Deployment order:
// 1. Deploy TimelockController (минимальная задержка = 48ч)
// 2. Deploy ProxyAdmin (owner = TimelockController)
// 3. Deploy Implementation
// 4. Deploy TransparentUpgradeableProxy (admin = ProxyAdmin)

contract DeployScript {
    function deployTimelock(
        address[] memory proposers,   // Safe multisig адрес
        address[] memory executors    // Safe multisig адрес (или address(0) = любой)
    ) external returns (address) {
        uint256 minDelay = 48 hours;  // 48 часов до исполнения любой admin-операции
        TimelockController timelock = new TimelockController(
            minDelay, proposers, executors, address(0)
        );
        return address(timelock);
    }
}

6. Frontend деплой: Cloudflare Pages, Vercel, IPFS gateways

Для максимальной доступности фронтенда используется комбинация: IPFS как «неизменяемый» слой + традиционные CDN как fast gateway + ENS как точка входа.

6.1 Архитектура доступности

СлойURLХарактеристика
ENS myprotocol.eth Неизменяемое имя, contentHash → IPFS CID
IPFS native ipfs://bafy... Цензуростойкий, нужен IPFS-совместимый браузер или gateway
Public gateway https://bafy....ipfs.dweb.link Protocol Labs gateway, работает в любом браузере
Pinata gateway https://myprotocol.mypinata.cloud Кастомный домен, быстрее чем public gateways
Cloudflare Pages https://myprotocol.pages.dev Traditional CDN, лучший performance, но централизован

6.2 GitHub Actions CI/CD для IPFS деплоя

# .github/workflows/deploy.yml
name: Deploy to IPFS + Update ENS

      - name: Deploy to Cloudflare Pages
        uses: cloudflare/pages-action@v1
        with:
          apiToken: ${{ secrets.CF_API_TOKEN }}
          accountId: ${{ secrets.CF_ACCOUNT_ID }}
          projectName: myprotocol-dapp
          directory: dist

7. Post-deploy верификация

После деплоя обязательно пройдите проверки — они ловят проблемы, которые не видны в staging, но критичны в mainnet.

7.1 Проверить байткод на Etherscan

# Сравнить on-chain байткод с локальной компиляцией
ON_CHAIN=$(cast code 0xDeployedAddress --rpc-url $RPC_URL)
LOCAL=$(cat out/SecureVault.sol/SecureVault.json | jq -r '.deployedBytecode.object')

if [ "$ON_CHAIN" = "0x$LOCAL" ]; then
  echo "✅ Bytecode matches local compilation"
else
  echo "❌ BYTECODE MISMATCH — verify your deployment"
  diff <(echo $ON_CHAIN) <(echo "0x$LOCAL")
fi

7.2 Проверить ABI через Etherscan API

#!/usr/bin/env ts-node
// scripts/verify-abi.ts — проверить что on-chain ABI совпадает с локальным

import fs from "fs";
import { createPublicClient, http } from "viem";
import { mainnet } from "viem/chains";

async function verifyAbi(contractAddress: string) {
  // Получить ABI с Etherscan
  const resp = await fetch(
    `https://api.etherscan.io/api?module=contract&action=getabi` +
    `&address=${contractAddress}&apikey=${process.env.ETHERSCAN_API_KEY}`
  );
  const data = await resp.json();

  if (data.status !== "1") {
    console.error("Contract not verified on Etherscan:", data.result);
    process.exit(1);
  }

  const etherscanAbi = JSON.parse(data.result);

  // Загрузить локальный ABI из Foundry out/
  const localAbi = JSON.parse(
    fs.readFileSync("out/SecureVault.sol/SecureVault.json", "utf8")
  ).abi;

  // Сравнить количество и сигнатуры функций
  const etherscanSigs = new Set(
    etherscanAbi.map((x: any) => `${x.type}:${x.name}`)
  );
  const localSigs = new Set(
    localAbi.map((x: any) => `${x.type}:${x.name}`)
  );

  const mismatches = [...localSigs].filter((sig) => !etherscanSigs.has(sig));
  if (mismatches.length > 0) {
    console.error("❌ ABI mismatch. Missing on Etherscan:", mismatches);
    process.exit(1);
  }

  console.log("✅ ABI matches between local and Etherscan");

  // Smoke-test: вызвать view-функцию
  const client = createPublicClient({ chain: mainnet, transport: http() });
  const paused = await client.readContract({
    address: contractAddress as `0x${string}`,
    abi: localAbi,
    functionName: "paused",
  });
  console.log(`✅ Contract is ${paused ? "PAUSED" : "active"} on-chain`);
}

await verifyAbi(process.argv[2]);

8. Полный pipeline: forge script + verify

Собираем всё вместе — production deployment script, который включает: проверку среды, деплой с CREATE2, автоверификацию, сохранение артефактов. 

#!/bin/bash
# scripts/deploy-production.sh
set -euo pipefail

echo "=== Web3 Genesis Protocol: Production Deploy ==="

# 1. Проверить переменные среды
: "${MAINNET_RPC_URL:?}" "${DEPLOYER_KEY:?}" "${ADMIN_ADDRESS:?}"
: "${GUARDIAN_ADDRESS:?}" "${ETHERSCAN_API_KEY:?}"

# 2. Убедиться что тесты прошли
echo "→ Running tests..."
forge test --fork-url $MAINNET_RPC_URL -q
echo "✅ All tests passed"

# 3. Деплой через Foundry script
echo "→ Deploying contracts..."
forge script script/DeployVault.s.sol:DeployVault \
  --rpc-url $MAINNET_RPC_URL \
  --broadcast \
  --verify \
  --etherscan-api-key $ETHERSCAN_API_KEY \
  --slow \      # ждём каждую транзакцию
  -vvv \
  2>&1 | tee deploy-$(date +%Y%m%d-%H%M%S).log

# 4. Сохранить адрес задеплоенного контракта
DEPLOYED=$(cat broadcast/DeployVault.s.sol/1/run-latest.json \
  | jq -r '.transactions[0].contractAddress')
echo "✅ Contract deployed at: $DEPLOYED"
echo $DEPLOYED > .deployed-address

# 5. Запустить post-deploy тесты
echo "→ Running post-deploy tests..."
DEPLOYED_ADDRESS=$DEPLOYED forge test \
  --match-path test/PostDeploy.t.sol \
  --fork-url $MAINNET_RPC_URL \
  -v
echo "✅ Post-deploy tests passed"

# 6. Проверить байткод
echo "→ Verifying bytecode..."
ON_CHAIN=$(cast code $DEPLOYED --rpc-url $MAINNET_RPC_URL)
LOCAL_BYTECODE=$(cat out/SecureVault.sol/SecureVault.json | jq -r '.deployedBytecode.object')
[ "$ON_CHAIN" = "0x$LOCAL_BYTECODE" ] \
  && echo "✅ Bytecode verified" \
  || (echo "❌ BYTECODE MISMATCH" && exit 1)

echo ""
echo "=== Deploy Complete ==="
echo "Contract:  $DEPLOYED"
echo "Etherscan: https://etherscan.io/address/$DEPLOYED"
echo ""
echo "Next steps:"
echo "  1. Build and pin frontend: ./scripts/deploy-ipfs.sh"
echo "  2. Update ENS contentHash: npx ts-node scripts/update-ens.ts"
echo "  3. Configure Tenderly alerts for $DEPLOYED"
