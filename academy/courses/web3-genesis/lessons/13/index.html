Wallet UX — EIP-6963, WalletConnect v2 и обработка ошибок

→ продолжение Lesson 12 — wagmi. Хуки у нас есть; теперь делаем «правильный» UX подключения.

Подключение кошелька — единственный непредсказуемый момент в dApp. Пользователь может: иметь несколько кошельков сразу (MetaMask + Rabby + Coinbase Wallet); открыть страницу с мобильного, где extension не работает; отказаться от подключения; переключить chain в кошельке без вашего согласия. Каждый из этих сценариев требует своего UI. В этом уроке — каноничный набор паттернов.

Что вы получите. После урока вы умеете: обнаруживать установленные кошельки через EIP-6963; интегрировать WalletConnect v2 для мобильных и hardware-кошельков; обрабатывать ошибки подключения (UserRejected, ChainMismatch, ResourceUnavailable); корректно показывать кошельковую сессию через перезагрузку страницы; готовить «безкошельковый» fallback (read-only режим).

1. История проблемы «window.ethereum»

До 2024 года стандартом был EIP-1193: каждый кошелёк инжектировал window.ethereum. Если установлены два кошелька — они дерутся за этот глобал, и побеждает тот, кто инжектировался последним. Пользователь открывает dApp, ждёт MetaMask — а вместо неё открывается Coinbase Wallet. «Поломка ожиданий», классическая UX-проблема.

EIP-6963 (Multi Injected Provider Discovery) — 2023. Решает проблему через event-based discovery: dApp шлёт eip6963:requestProvider, каждый кошелёк отвечает событием eip6963:announceProvider со своими метаданными (имя, иконка, uuid). dApp показывает пользователю список и тот сам выбирает. 

// Что происходит под капотом (псевдокод):
window.addEventListener('eip6963:announceProvider', (event) => {
  const { info, provider } = event.detail
  // info = { name: 'MetaMask', icon: 'data:image/...', rdns: 'io.metamask', uuid: '...' }
  // provider — это EIP-1193 provider, на который можно сразу сделать request()
  wallets.push({ info, provider })
})

window.dispatchEvent(new Event('eip6963:requestProvider'))

wagmi 2.x использует EIP-6963 «из коробки», когда вы добавляете injected() connector. useConnect().connectors возвращает массив всех обнаруженных кошельков с правильными именами и иконками.

2. UI выбора кошелька — pattern

// src/WalletPicker.tsx
import { useConnect } from 'wagmi'

export function WalletPicker() {
  const { connectors, connect, isPending, error } = useConnect()

  // wagmi 2.x возвращает один injected-connector на каждый EIP-6963 wallet.
  // Дополнительно есть WalletConnect, Coinbase Wallet и т.д.
  const injected = connectors.filter(c => c.type === 'injected')
  const wc       = connectors.filter(c => c.id === 'walletConnect')
  const coinbase = connectors.filter(c => c.id === 'coinbaseWallet')

  return (
    <dialog open>
      <h3>Выберите кошелёк</h3>
      <section>
        <h4>Установленные расширения</h4>
        {injected.length === 0 && (
          <p>Не обнаружено. Установите <a href="https://metamask.io">MetaMask</a> или <a href="https://rabby.io">Rabby</a>.</p>
        )}
        {injected.map(c => (
          <button key={c.uid} onClick={() => connect({ connector: c })} disabled={isPending}>
            <img src={c.icon} alt="" width={24} /> {c.name}
          </button>
        ))}
      </section>
      <section>
        <h4>Мобильные кошельки</h4>
        {wc.map(c => (
          <button key={c.uid} onClick={() => connect({ connector: c })} disabled={isPending}>
            WalletConnect (QR) — Trust, Rainbow, Ledger Live…
          </button>
        ))}
      </section>
      {error && <p style={{color:'red'}}>Ошибка: {error.shortMessage}</p>}
    </dialog>
  )
}

3. Обработка типичных ошибок коннекта

viem нормализует ошибки. Каждая имеет shortMessage (для UI) и name (для логики). Главные:

  • UserRejectedRequestError — пользователь нажал «Отмена» в popup'е кошелька. Это не программная ошибка: ничего не логируйте в Sentry, просто верните UI в исходное состояние.
  • ResourceUnavailableRpcError — кошелёк уже занят другим запросом. Покажите тост: «Откройте кошелёк и завершите текущий запрос».
  • ChainMismatchError — у dApp один chain, у кошелька другой. Предложите switchChain.
  • ConnectorAlreadyConnectedError — повторный connect на уже подключённый коннектор. Просто игнорируйте.
  • HttpRequestError — RPC-нода недоступна. Покажите пользователю, что проблема в инфраструктуре (не в его кошельке).
import { UserRejectedRequestError, ChainMismatchError } from 'viem'

function handleConnectError(error: unknown) {
  if (error instanceof UserRejectedRequestError) {
    // Не показываем как ошибку — просто closeModal()
    return
  }
  if (error instanceof ChainMismatchError) {
    toast.warn('Switch network in wallet')
    return
  }
  // Всё остальное — настоящие ошибки
  toast.error('Connection failed: ' + (error as Error).message)
  console.error(error)
}

4. WalletConnect v2 — мобильные кошельки

Расширение MetaMask не работает на мобильном Safari. Решение — WalletConnect: dApp генерирует QR-код, пользователь сканирует его в мобильном кошельке (Trust, Rainbow, Coinbase Wallet, Ledger Live), и устанавливается зашифрованная сессия через relay-сервер. 

// src/wagmi.ts
import { createConfig, http } from 'wagmi'
import { mainnet, sepolia } from 'wagmi/chains'
import { injected, walletConnect, coinbaseWallet } from 'wagmi/connectors'

export const config = createConfig({
  chains: [mainnet, sepolia],
  connectors: [
    injected({ shimDisconnect: true }),
    walletConnect({
      projectId: import.meta.env.VITE_WC_PROJECT_ID,    // получите на cloud.walletconnect.com
      metadata: {
        name: 'My dApp',
        description: 'Best dApp in the multiverse',
        url: 'https://my-dapp.example',
        icons: ['https://my-dapp.example/icon.png'],
      },
      showQrModal: true,                                 // встроенный QR-модал
    }),
    coinbaseWallet({
      appName: 'My dApp',
      preference: 'all',                                 // и extension, и smart-wallet
    }),
  ],
  transports: {
    [mainnet.id]: http(),
    [sepolia.id]: http(),
  },
})
WalletConnect projectId. Бесплатный план — 100k запросов в месяц, для большинства проектов достаточно. На production обязательно настройте allowedDomains в кабинете WC — иначе кто угодно может использовать ваш projectId и съесть лимиты.

5. Smart wallets и passkey (EIP-7702)

Coinbase Smart Wallet (Base + Optimism), Safe — это контрактные кошельки. Адрес — это адрес контракта, а не EOA. Технически у них есть особенности:

  • signMessage возвращает не 65-байтовую ECDSA, а ERC-1271-совместимую подпись. Проверяйте через publicClient.verifyMessage — он автоматически делает ERC-1271 fallback.
  • Газ может оплачиваться спонсором (paymaster). Для большинства dApp это прозрачно, но важно знать.
  • Транзакции могут быть батчевыми (EIP-5792 wallet_sendCalls) — несколько действий за одну подпись.
  • EIP-7702 (Pectra, 2025): EOA может временно делегировать на код контракта. Это размывает границу между EOA и smart wallet. wagmi обрабатывает через useSendCalls.

6. Сессия через перезагрузку

По умолчанию injected() connector сохраняет состояние в localStorage. После reload wagmi автоматически делает eth_accounts и если кошелёк всё ещё разрешает доступ — session восстанавливается. Если пользователь отозвал доступ — список адресов пуст, wagmi считает кошелёк disconnected. 

// src/App.tsx
import { useAccount, useReconnect } from 'wagmi'
import { useEffect } from 'react'

export function App() {
  const { reconnect } = useReconnect()
  const { isReconnecting, isConnected } = useAccount()

  // Восстанавливаем сессию один раз при mount
  useEffect(() => {
    reconnect()
  }, [])

  if (isReconnecting) return <p>Restoring session…</p>
  if (!isConnected)   return <ConnectButton />
  return <Dashboard />
}

7. Read-only fallback

Не все пользователи готовы подключать кошелёк сразу. Хороший UX позволяет смотреть данные dApp без connect: цены, объёмы, графики. Это делается на одном PublicClient (или wagmi useReadContract без account). 

// Глобальная статистика, видна всем
export function ProtocolStats() {
  const { data: tvl } = useReadContract({
    address: VAULT,
    abi: vaultAbi,
    functionName: 'totalAssets',
    // НЕТ account, НЕТ args зависимых от user
  })

  return <p>TVL: {formatEther(tvl ?? 0n)} ETH</p>
}

// Персональная статистика — только при isConnected
export function MyPosition() {
  const { address, isConnected } = useAccount()
  const { data } = useReadContract({
    address: VAULT,
    abi: vaultAbi,
    functionName: 'balanceOf',
    args: address ? [address] : undefined,
    query: { enabled: !!address },
  })

  if (!isConnected) return <p>Connect wallet to see your position</p>
  return <p>Your shares: {data?.toString()}</p>
}

8. Безопасность подключения

8.1 Никогда не запрашивать private key

dApp не должен и не может видеть private key. Любая просьба «введите seed phrase» = фишинг. EIP-1193 даёт только provider, через который можно подписать сообщение/транзакцию.

8.2 Origin pinning

Кошельки сравнивают origin запроса с origin'ом, на котором пользователь сделал connect. Если ваш dApp работает на нескольких доменах (app.foo.com, app-staging.foo.com) — на каждом будет отдельный «сеанс» в кошельке. Это не баг, это feature: компрометация одного домена не даёт доступ к подписи на другом.

8.3 EIP-712 vs personal_sign

Раньше большинство подписей делалось через personal_sign — пользователь видел только хеш или произвольную строку. Это создавало «слепые» подписи. EIP-712 (typed data) показывает структурированное сообщение с понятными полями: «Permit: spend 100 USDC by 0x..., expires at ...». wagmi useSignTypedData — стандарт для любой подписи с пользовательским решением.

Задача 2 — Обработка всех ошибок коннекта

# src/handleConnect.ts
import { UserRejectedRequestError, ResourceUnavailableRpcError } from 'viem'

export function handleConnectError(error: unknown, toast: Toast) {
  if (error instanceof UserRejectedRequestError) {
    // closeModal без сообщения — это нормальная отмена пользователя
    return { kind: 'user-cancel' }
  }
  if (error instanceof ResourceUnavailableRpcError) {
    toast.warn('Откройте кошелёк и завершите предыдущий запрос')
    return { kind: 'busy' }
  }
  if (error instanceof Error && error.message.includes('already connected')) {
    return { kind: 'already-connected' }
  }
  if (error instanceof Error && error.message.includes('Connection request reset')) {
    toast.warn('Соединение разорвано. Попробуйте ещё раз.')
    return { kind: 'reset' }
  }
  // Всё остальное — настоящие ошибки
  toast.error('Не удалось подключиться: ' + (error as Error).message)
  console.error(error)
  return { kind: 'unknown' }
}

# Использование:
const { connect } = useConnect({
  mutation: {
    onError: handleConnectError,
  },
})

Задача 3 — Restore-session pattern

# src/App.tsx
import { useReconnect, useAccount } from 'wagmi'
import { useEffect, useState } from 'react'

export function App() {
  const [restored, setRestored] = useState(false)
  const { reconnect } = useReconnect()
  const { isConnected, isConnecting, isReconnecting } = useAccount()

  useEffect(() => {
    if (!restored) {
      reconnect().finally(() => setRestored(true))
    }
  }, [restored])

  // 3 разных state, 3 разных UI
  if (!restored || isReconnecting) return <Splash text="Восстанавливаем сессию…" />
  if (isConnecting)                return <Splash text="Открываем кошелёк…" />
  if (!isConnected)                return <HomePage />            // read-only mode

  return <Dashboard />

  # Tест:
  # 1. Подключите кошелёк, сделайте reload — должна остаться сессия.
  # 2. В кошельке нажмите Disconnect → reload — должен открыться HomePage.
  # 3. Очистите localStorage → reload — снова HomePage, никаких exception.
}

Задача 4 — Switch network с автодобавлением chain

# src/SwitchNetwork.tsx
import { useSwitchChain, useChainId } from 'wagmi'
import { base, optimism, arbitrum, sepolia } from 'wagmi/chains'

const TARGET_CHAINS = [base, optimism, arbitrum, sepolia]

export function SwitchNetwork() {
  const chainId = useChainId()
  const { switchChain, isPending, error } = useSwitchChain()

  return (
    <>
      {TARGET_CHAINS.map(c => (
        <button
          key={c.id}
          disabled={isPending || chainId === c.id}
          onClick={() => switchChain({ chainId: c.id })}
        >
          {chainId === c.id ? '✓ ' : ''}{c.name}
        </button>
      ))}
      {error && <p>Ошибка: {error.shortMessage}</p>}
    </>
  )
}
