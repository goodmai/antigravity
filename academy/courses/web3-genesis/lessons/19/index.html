Monitoring & Tenderly Alerts: мониторинг контрактов в продакшене

Смарт-контракт задеплоен, тесты прошли, аудит получен — кажется, дело сделано. На самом деле это только начало: продакшен живёт 24/7, атаки случаются в любое время, а «тихая» ошибка контракта может слить протокол за несколько блоков прежде чем кто-то заметит. В этом уроке вы узнаете, как выстроить полный стек наблюдаемости — от Tenderly Alerts до собственных ethers.js/viem-подписок — и что делать, когда что-то всё-таки пошло не так.

Что вы получите. После урока вы умеете: создать алерты в Tenderly на события, вызовы функций, изменения состояния и падение баланса; написать Tenderly Web3 Action на TypeScript; использовать Simulation API для pre-execution validation; подписаться на on-chain события через viem watchContractEvent и ethers.js; сравнить Tenderly с OpenZeppelin Defender; воспроизвести упавшую транзакцию через trace-replay; составить production-checklist по мониторингу.

1. Почему мониторинг критичен: тихие сбои и атаки

Blockchain-протоколы страдают от особого класса проблем, которых нет в обычном бэкенде. Традиционный сервис упадёт с 5xx, алерт сработает, SRE поднимет инцидент. Контракт же никогда не упадёт сам по себе — он будет тихо делать не то, что задумывалось, пока кто-то не выведет все средства.

Тип проблемыСигнал без мониторингаСигнал с мониторингом
Reentrancy атака Баланс контракта = 0, Twitter в панике Алерт при первом подозрительном вызове + аномальный gas usage
Oracle manipulation (MEV) Liquidation cascade через 3 блока Алерт при price deviation > N% за один блок
Missed event Off-chain сервис «теряет» депозиты пользователей Алерт при разрыве между событиями > X минут
Pause не сработал Контракт продолжает принимать деньги после exploit Алерт при вызове pauseAdmin + проверка флага paused
Proxy upgrade Неожиданно изменилась логика контракта Алерт на Upgraded(address) с проверкой нового impl-адреса

Знаменитые атаки — Ronin Bridge ($625M, 2022), Euler Finance ($197M, 2023), Curve Finance ($62M, 2023) — были замечены задним числом. У команд, у которых были настроены алерты, окно реакции сокращается с часов до минут. Именно это время решает — успел ли паузить контракт, успел ли drain-proof сработать.

2. Tenderly Alerting: создание алертов

Tenderly — наиболее полная платформа для Web3 ops: дашборд транзакций, симуляция, отладка trace и, главное, Alerting — система нотификаций, которая реагирует на on-chain события без написания инфраструктурного кода.

2.1 Типы алертов

ТипКогда срабатываетПример использования
Successful Transaction Любая успешная транзакция к адресу Мониторинг нового контракта после деплоя
Failed Transaction Транзакция реверчена Детект revert-loop атак, отладка пользовательских ошибок
Function Call Вызвана конкретная функция Алерт при вызове withdraw() крупнее threshold
Event Emitted Контракт эмитировал событие с нужными параметрами Алерт на Transfer(from, to, amount) с amount > 1000 ETH
State Change Слот storage изменился Алерт при изменении owner — потенциальный takeover
Balance Change Нативный баланс адреса изменился Алерт при падении баланса multisig ниже 0.5 ETH
ERC-20 Transfer ERC-20 токен переведён от/к адресу Мониторинг treasury wallet на неожиданные оттоки

2.2 Создание алерта через UI

Зайдите в Dashboard → Alerts → New Alert. Шаги:

  1. Target — введите адрес контракта или выберите из добавленных проектов. Можно указать несколько адресов одним алертом.
  2. Alert type — выберите из таблицы выше.
  3. Filters — для Event: название события + фильтр по параметрам (например, amount > 1000000000000000000000 для 1000 ETH).
  4. Destination — Email, Slack, Telegram, Discord Webhook, PagerDuty, Webhook URL. Можно несколько назначений одновременно.
  5. Network — Mainnet, Sepolia, Polygon, Arbitrum, Optimism и др.
Совет. Для продакшен-протокола создайте минимум три уровня алертов: (1) «информационный» — в Slack-канал команды; (2) «предупреждение» — в PagerDuty с SLA 15 минут; (3) «критический» — звонок дежурному инженеру через PagerDuty, если паузить нужно немедленно.

3. Tenderly Web3 Actions: serverless-функции на событиях

Алерты отправляют уведомления. Web3 Actions — идут дальше: это серверные JS/TS-функции, которые исполняются при наступлении on-chain события. Можно автоматически паузить контракт, обновить off-chain базу, вызвать внешний API.

3.1 Структура проекта

# Установить CLI
npm install -g @tenderly/cli

# Инициализировать проект
tenderly init
tenderly actions init

# Структура
my-project/
├── actions/
│   ├── tenderly.yaml      # конфигурация trigger'ов
│   └── monitorWithdrawal.ts
└── package.json

3.2 Конфигурация trigger в tenderly.yaml

account_id: "your-account"
project_slug: "your-project"

actions:
  monitorWithdrawal:
    runtime: v2
    description: "Auto-pause on large withdrawal"
    trigger:
      type: transaction
      transaction:
        status:
          - mined
        filters:
          - network: 1
            eventEmitted:
              contract:
                address: "0xYourContractAddress"
              name: "WithdrawalProcessed"
              # Фильтр на уровне ABI-параметров
    function: monitorWithdrawal.ts:onWithdrawal
    execution_type: parallel

3.3 Функция-обработчик (TypeScript)

import {
  ActionFn,
  Context,
  Event,
  TransactionEvent,
} from "@tenderly/actions";
import { ethers } from "ethers";

// ABI для вызова pause()
const VAULT_ABI = [
  "event WithdrawalProcessed(address indexed recipient, uint256 amount)",
  "function pause() external",
  "function paused() view returns (bool)",
];

const LARGE_WITHDRAWAL_THRESHOLD = ethers.parseEther("50"); // 50 ETH

export const onWithdrawal: ActionFn = async (context: Context, event: Event) => {
  const txEvent = event as TransactionEvent;

  // Получаем провайдер через Tenderly-контекст
  const provider = await context.gateways.getGateway("mainnet");
  const rpcUrl = await provider.get();
  const ethersProvider = new ethers.JsonRpcProvider(rpcUrl);

  // Декодируем logs
  const iface = new ethers.Interface(VAULT_ABI);
  for (const log of txEvent.logs) {
    let decoded;
    try {
      decoded = iface.parseLog(log);
    } catch {
      continue;
    }

    if (decoded?.name === "WithdrawalProcessed") {
      const amount: bigint = decoded.args.amount;

      if (amount > LARGE_WITHDRAWAL_THRESHOLD) {
        console.log(`🚨 Large withdrawal detected: ${ethers.formatEther(amount)} ETH`);
        console.log(`Recipient: ${decoded.args.recipient}`);
        console.log(`TX hash: ${txEvent.hash}`);

        // Достаём приватный ключ из зашифрованного Secrets-хранилища Tenderly
        const adminKey = await context.secrets.get("GUARDIAN_PRIVATE_KEY");
        const wallet = new ethers.Wallet(adminKey, ethersProvider);
        const vault = new ethers.Contract(
          "0xYourContractAddress",
          VAULT_ABI,
          wallet
        );

        // Паузим контракт
        const alreadyPaused = await vault.paused();
        if (!alreadyPaused) {
          const tx = await vault.pause();
          await tx.wait();
          console.log(`✅ Contract paused. Pause TX: ${tx.hash}`);
        }

        // Уведомляем в PagerDuty
        await fetch("https://events.pagerduty.com/v2/enqueue", {
          method: "POST",
          headers: { "Content-Type": "application/json" },
          body: JSON.stringify({
            routing_key: await context.secrets.get("PAGERDUTY_KEY"),
            event_action: "trigger",
            payload: {
              summary: `Large withdrawal: ${ethers.formatEther(amount)} ETH`,
              severity: "critical",
              source: "tenderly-web3-action",
              custom_details: {
                tx_hash: txEvent.hash,
                recipient: decoded.args.recipient,
              },
            },
          }),
        });
      }
    }
  }
};
Secrets. Tenderly Web3 Actions имеют зашифрованное хранилище секретов — context.secrets.get("KEY"). Никогда не хардкодьте приватные ключи прямо в коде функции; используйте только Secrets API.

4. Tenderly Simulation API: pre-execution validation

Simulation API позволяет сымитировать транзакцию на актуальном состоянии блокчейна до её отправки. Это мощный инструмент: можно проверить, не реверчен ли вызов, сколько газа потратит, какие события эмитируются — и всё это без трат газа и без риска для реальных средств.

4.1 Сценарии применения

  • Pre-execution validation в UI dApp: перед тем как пользователь нажмёт «Confirm» в MetaMask, симулируем транзакцию и показываем, что именно произойдёт — «вы получите 1.23 WETH, потратив 500 USDC».
  • Tender Gas Estimation: более точная оценка газа, чем eth_estimateGas, с декодированием причины реверта.
  • What-if scenarios: тестирование upgrade'ов, parameter changes, liquidation scenarios на fork'е mainnet без реальных транзакций.
  • MEV-защита: проверить, не ухудшит ли sandwich bot вашу транзакцию при текущем состоянии пула.

4.2 Вызов Simulation API

// Симуляция перед отправкой swap-транзакции
async function simulateBeforeSend(
  from: string,
  to: string,
  data: string,
  value: bigint
): Promise<{ success: boolean; gasUsed: number; revertReason?: string }> {
  const TENDERLY_PROJECT = process.env.TENDERLY_PROJECT!;
  const TENDERLY_ACCOUNT = process.env.TENDERLY_ACCOUNT!;
  const TENDERLY_KEY = process.env.TENDERLY_ACCESS_KEY!;

  const resp = await fetch(
    `https://api.tenderly.co/api/v1/account/${TENDERLY_ACCOUNT}/project/${TENDERLY_PROJECT}/simulate`,
    {
      method: "POST",
      headers: {
        "X-Access-Key": TENDERLY_KEY,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        network_id: "1",
        from,
        to,
        input: data,
        value: value.toString(),
        gas: 500_000,
        gas_price: "20000000000",
        save: true,           // сохранить для отладки в дашборде
        save_if_fails: true,  // сохранить даже если реверт
        simulation_type: "full", // full trace
      }),
    }
  );

  const result = await resp.json();
  const sim = result.simulation;

  if (!sim.status) {
    // Достаём причину реверта из decoded output
    const revertReason = sim.transaction?.error_message ?? "unknown revert";
    console.error("Simulation failed:", revertReason);
    return { success: false, gasUsed: sim.gas_used, revertReason };
  }

  console.log("Simulation passed. Gas used:", sim.gas_used);
  // Логируем эмитированные события
  for (const log of sim.transaction?.transaction_info?.logs ?? []) {
    console.log("Event:", log.name, log.inputs);
  }

  return { success: true, gasUsed: sim.gas_used };
}

// Пример использования перед реальным вызовом swap
const { success, revertReason } = await simulateBeforeSend(
  userAddress,
  UNISWAP_V3_ROUTER,
  swapCalldata,
  0n
);

if (!success) {
  showError(`Transaction would fail: ${revertReason}`);
  return;
}

// Только если симуляция успешна — отправляем
await walletClient.sendTransaction({ to: UNISWAP_V3_ROUTER, data: swapCalldata });

5. RPC-мониторинг: ethers.js и viem event subscriptions

Для некоторых случаев (более дешёвый стек, self-hosted, нет привязки к Tenderly) мониторинг можно строить напрямую через WebSocket RPC-подписки.

5.1 viem: watchContractEvent

import { createPublicClient, webSocket, parseAbi } from "viem";
import { mainnet } from "viem/chains";

const VAULT_ABI = parseAbi([
  "event WithdrawalProcessed(address indexed recipient, uint256 indexed tokenId, uint256 amount)",
  "event Paused(address account)",
  "event Unpaused(address account)",
]);

const client = createPublicClient({
  chain: mainnet,
  // WebSocket для real-time подписки (vs HTTP polling)
  transport: webSocket("wss://mainnet.infura.io/ws/v3/YOUR_KEY"),
});

// Подписка на конкретное событие контракта
const unwatch = client.watchContractEvent({
  address: "0xYourVaultAddress",
  abi: VAULT_ABI,
  eventName: "WithdrawalProcessed",
  // Фильтр по indexed параметрам
  args: { tokenId: 42n },
  onLogs: (logs) => {
    for (const log of logs) {
      const { recipient, amount } = log.args;
      console.log(`Withdrawal: ${recipient} → ${amount} wei`);
      if (amount! > parseEther("50")) {
        triggerEmergencyPause();
      }
    }
  },
  onError: (error) => {
    console.error("Subscription error:", error);
    // Реконнект-логика
  },
});

5.2 getLogs с ретраем (polling fallback)

import { createPublicClient, http, parseAbiItem } from "viem";
import { mainnet } from "viem/chains";

const client = createPublicClient({ chain: mainnet, transport: http() });

async function pollEvents(fromBlock: bigint) {
  while (true) {
    const latestBlock = await client.getBlockNumber();

    if (latestBlock > fromBlock) {
      const logs = await client.getLogs({
        address: "0xYourVaultAddress",
        event: parseAbiItem(
          "event WithdrawalProcessed(address indexed recipient, uint256 amount)"
        ),
        fromBlock,
        toBlock: latestBlock,
      });

      for (const log of logs) {
        await processWithdrawal(log);
      }

      fromBlock = latestBlock + 1n;
    }

    await new Promise((r) => setTimeout(r, 12_000)); // ~1 блок = 12 сек
  }
}

// Стартуем с блока деплоя контракта
await pollEvents(19_000_000n);

5.3 ethers.js: provider.on и queryFilter

import { ethers } from "ethers";

const provider = new ethers.WebSocketProvider(
  "wss://mainnet.infura.io/ws/v3/YOUR_KEY"
);
const vault = new ethers.Contract("0xYourVaultAddress", VAULT_ABI, provider);

// Подписка real-time
vault.on("WithdrawalProcessed", (recipient, amount, event) => {
  console.log(`TX: ${event.transactionHash}`);
  console.log(`Withdrawal: ${ethers.formatEther(amount)} ETH to ${recipient}`);
});

// Исторические события
const filter = vault.filters.WithdrawalProcessed(null, null);
const logs = await vault.queryFilter(filter, -10_000); // последние 10 000 блоков
console.log(`Found ${logs.length} past withdrawals`);

// Реконнект при падении WS
provider.on("error", async (err) => {
  console.error("WS Error:", err);
  await provider.destroy();
  // перезапустить провайдер...
});
WebSocket vs HTTP polling. WebSocket дают push-нотификации без задержки (~100ms vs ~12000ms), но нестабильны при длительной работе — нужен реконнект. Для критичного мониторинга используйте оба: WS как primary, HTTP polling как fallback с проверкой пропущенных блоков.

6. OpenZeppelin Defender Monitors

OpenZeppelin Defender — конкурент Tenderly с несколько другим фокусом: больше внимания к automated response (автоматические транзакции), мультисиг управление, Relayers для gasless operations.

import { Defender } from "@openzeppelin/defender-sdk";

const client = new Defender({
  apiKey: process.env.DEFENDER_KEY!,
  apiSecret: process.env.DEFENDER_SECRET!,

// Создать Monitor
const monitor = await client.monitor.create({

  // Autotask — serverless функция (аналог Web3 Actions)
  autotaskId: "YOUR_AUTOTASK_ID",
});

console.log("Monitor created:", monitor.monitorId);

7. Post-mortem: воспроизведение упавшей транзакции

Когда инцидент уже произошёл, Tenderly позволяет пошагово воспроизвести упавшую транзакцию — увидеть каждый шаг EVM, изменения состояния, стек вызовов, декодированные ошибки.

7.1 Trace replay в UI

  1. Откройте Tenderly Dashboard → Explorer, введите hash упавшей транзакции.
  2. Перейдите во вкладку Debugger — видите call tree: каждый вызов, sub-call, delegatecall с результатами.
  3. Во вкладке State Changes — все затронутые storage слоты с before/after значениями, декодированными через ABI.
  4. Вкладка Events — события, которые были бы эмитированы (даже если транзакция реверчена — виртуальные события до revert видны).
  5. Re-simulate: измените параметры (другой block number, другой from, другая сумма) — пересимулируйте и сравните результаты.

7.2 Trace через API

// Получить trace упавшей транзакции программно
async function analyzeFailedTx(txHash: string) {
  const resp = await fetch(
    `https://api.tenderly.co/api/v1/public-contract/1/trace/${txHash}`,
    {
      headers: { "X-Access-Key": process.env.TENDERLY_ACCESS_KEY! },
    }
  );

  const trace = await resp.json();

  // Найти точку реверта в call tree
  function findRevert(calls: any[], depth = 0): void {
    for (const call of calls) {
      const indent = "  ".repeat(depth);
      const status = call.error ? "❌ REVERT" : "✅";
      console.log(
        `${indent}${status} ${call.type} ${call.to} → ${call.function_name ?? "(fallback)"}`
      );
      if (call.error) {
        console.log(`${indent}  Error: ${call.error}`);
        console.log(`${indent}  Error reason: ${call.error_reason ?? "N/A"}`);
      }
      if (call.calls?.length) {
        findRevert(call.calls, depth + 1);
      }
    }
  }

  findRevert(trace.transaction_info.call_trace.calls ?? []);
}

// Пример
await analyzeFailedTx("0xabcd1234...упавшая транзакция...");

7.3 Декодирование custom errors через trace

// Solidity custom error в контракте
// error InsufficientBalance(address user, uint256 required, uint256 actual);

// Tenderly декодирует это автоматически если ABI загружен.
// Если нет — декодируем вручную:
import { decodeErrorResult, parseAbi } from "viem";

const ABI = parseAbi([
  "error InsufficientBalance(address user, uint256 required, uint256 actual)",
]);

// Из trace получаем revert data (hex)
const revertData = "0x12345678..."; // первые 4 байта = selector, остальное = args

try {
  const decoded = decodeErrorResult({ abi: ABI, data: revertData });
  console.log("Custom error:", decoded.errorName);
  console.log("Args:", decoded.args);
  // InsufficientBalance { user: "0x...", required: 1000n, actual: 500n }
} catch {
  // Не custom error — попробовать как стандартный revert(string)
  console.log("Standard revert:", hexToString(revertData.slice(10)));
}

8.1 Pausable pattern в контракте

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "@openzeppelin/contracts/utils/Pausable.sol";
import "@openzeppelin/contracts/access/AccessControl.sol";

contract SecureVault is Pausable, AccessControl {
    bytes32 public constant GUARDIAN_ROLE = keccak256("GUARDIAN_ROLE");
    bytes32 public constant OPERATOR_ROLE  = keccak256("OPERATOR_ROLE");

    // Guardians — адреса Tenderly Web3 Action, может быть несколько
    // Operator — multisig Safe, может выполнять операции

    event WithdrawalProcessed(
        address indexed recipient,
        uint256 amount,
        uint256 timestamp
    );

    constructor(address admin, address guardian) {
        _grantRole(DEFAULT_ADMIN_ROLE, admin);
        _grantRole(GUARDIAN_ROLE, guardian);
        _grantRole(OPERATOR_ROLE, admin);
    }

    // Только guardian или admin могут паузить
    function pause() external onlyRole(GUARDIAN_ROLE) {
        _pause();
    }

    // Только admin может снять паузу (намеренно строже)
    function unpause() external onlyRole(DEFAULT_ADMIN_ROLE) {
        _unpause();
    }

    function withdraw(address recipient, uint256 amount)
        external
        onlyRole(OPERATOR_ROLE)
        whenNotPaused  // ← ключевой модификатор
    {
        require(address(this).balance >= amount, "InsufficientBalance");
        // Slippage protection: здесь для native ETH это limit
        require(amount <= 10 ether, "ExceedsLimit");

        (bool ok,) = recipient.call{value: amount}("");
        require(ok, "TransferFailed");

        emit WithdrawalProcessed(recipient, amount, block.timestamp);
    }

    receive() external payable {}
}
