Модуль III · Lesson 14 · transaction · pending · optimistic UI

Transaction UX — pending states, replacement, dropped

→ продолжение Lesson 13 — Wallet UX. Кошелёк подключён, теперь правильно рисуем жизненный цикл одной транзакции.

У классического web-приложения запрос имеет три состояния: idle → loading → done/error. У web3 — минимум семь: idle → simulating → awaiting-signature → signed/pending → mining → confirmed → finalized → (replaced/dropped/reverted). Каждое требует своего UI, и пропуск даже одного — это «застрявший» интерфейс, где пользователь не знает, что происходит. Этот урок — каноничный набор паттернов отрисовки транзакции.

Что вы получите. После урока вы умеете: правильно различать все стадии tx; делать optimistic UI с rollback при revert; ловить replacement (cancel/speed-up в кошельке); обнаруживать dropped tx; реализовывать gas-bump для застрявших транзакций; показывать reorg-safe-confirmations (1/3/12 confirmations).

1. Полный жизненный цикл транзакции

└─────────┘                    └─────────────┘                  │   signature     │
                                      │                         └────────┬────────┘

                       success state   show new hash      restart flow   show revert

2. simulate + write + wait — три хука wagmi

// src/SendTx.tsx
import {
  useSimulateContract,
  useWriteContract,
  useWaitForTransactionReceipt,
} from 'wagmi'

export function SendTx({ to, amount }: { to: \`0x\${string}\`, amount: bigint }) {
  // 1. Simulate — постоянно, инвалидируется при изменении args
  const {
    data: simulation,
    error: simError,
    isLoading: isSimulating,
  } = useSimulateContract({
    address: USDC,
    abi: erc20Abi,
    functionName: 'transfer',
    args: [to, amount],
  })

  // 2. Write — выполняется по клику
  const {
    writeContract,
    data: hash,
    isPending: isAwaitingSignature,
    error: writeError,
    reset,
  } = useWriteContract()

  // 3. Wait — после подписи, до confirmation
  const {
    isLoading: isMining,
    isSuccess: isConfirmed,
    isError:   isReverted,
    data:      receipt,
  } = useWaitForTransactionReceipt({
    hash,
    confirmations: 1,           // 1 для testnet, 3-12 для money-критичных
  })

  // Производные state — один источник правды
  const status =
    simError              ? 'sim-error'   :
    isSimulating          ? 'simulating'  :
    isAwaitingSignature   ? 'awaiting'    :
    isMining              ? 'mining'      :
    isConfirmed           ? 'confirmed'   :
    isReverted            ? 'reverted'    :
    writeError            ? 'write-error' :
    'idle'

  return (
    <div>
      <StatusBadge status={status} hash={hash} />

      <button
        disabled={!simulation || isAwaitingSignature || isMining}
        onClick={() => writeContract(simulation!.request)}
      >
        {status === 'awaiting' && 'Подпишите в кошельке…'}
        {status === 'mining'   && \`Майнинг… \${receipt?.blockNumber ?? '–'}\`}
        {status === 'confirmed'&& '✓ Подтверждено'}
        {status === 'idle'     && 'Отправить'}
        {status === 'sim-error'&& '✗ Симуляция упала'}
      </button>

      {(status === 'confirmed' || status === 'reverted') && (
        <button onClick={reset}>Новая транзакция</button>
      )}
    </div>
  )
}

3. Optimistic UI и rollback

«Подождите 12 секунд, пока появится подтверждение» — плохой UX. Лучше — сразу обновить интерфейс, как будто transaction уже прошла, и откатить, если она revert'нулась. TanStack Query даёт это «бесплатно» через queryClient.setQueryData + onError rollback. 

// src/useOptimisticTransfer.ts
import { useMutation, useQueryClient } from '@tanstack/react-query'
import { useWriteContract, useWaitForTransactionReceipt } from 'wagmi'

export function useOptimisticTransfer(myAddress: \`0x\${string}\`) {
  const qc = useQueryClient()
  const { writeContractAsync } = useWriteContract()

  return useMutation({
    mutationFn: async ({ to, amount }: { to: \`0x\${string}\`, amount: bigint }) => {
      const hash = await writeContractAsync({
        address: USDC,
        abi: erc20Abi,
        functionName: 'transfer',
        args: [to, amount],
      })
      return { hash, to, amount }
    },

    // 1. Optimistic update — РАЗУ после клика, до подписи
    onMutate: async ({ amount }) => {
      // Запретить refetch, чтобы не перетёр оптимистичное значение
      await qc.cancelQueries({ queryKey: ['readContract', { functionName: 'balanceOf' }] })

      const prev = qc.getQueryData<bigint>([
        'readContract',
        { address: USDC, functionName: 'balanceOf', args: [myAddress] },
      ])

      // Уменьшаем баланс на amount немедленно
      qc.setQueryData(
        ['readContract', { address: USDC, functionName: 'balanceOf', args: [myAddress] }],
        (old?: bigint) => (old ?? 0n) - amount,
      )

      return { prev }    // rollback context
    },

    // 2. Rollback — если writeContractAsync бросил (user-rejected / revert на simulate)
    onError: (_err, _vars, ctx) => {
      if (ctx?.prev !== undefined) {
        qc.setQueryData(
          ['readContract', { address: USDC, functionName: 'balanceOf', args: [myAddress] }],
          ctx.prev,
        )
      }
    },

    // 3. После confirmation — refetch актуальные данные (включая возможный revert)
    onSettled: () => {
      qc.invalidateQueries({ queryKey: ['readContract'] })
    },
  })
}
Важно: revert после mining. Даже после подписи и включения в блок tx может revert'нуться (state изменился между simulate и mining). Поэтому помимо onError мы обязательно делаем invalidateQueries в onSettled — реальное состояние из chain заменит оптимистичное.

4. Replacement: speed-up и cancel

Пользователь подписал tx, но она «висит» в mempool. Он идёт в MetaMask и нажимает Speed Up (повышает maxFeePerGas на ту же nonce) или Cancel (отправляет zero-value tx на свой адрес с той же nonce, но большим fee). Старая tx умирает, новая может прийти с другим hash. Если ваш UI слушает только старый hash — он «застрянет» навсегда. 

// viem умеет ловить replacement через onReplaced callback
import { useWaitForTransactionReceipt } from 'wagmi'

const { isLoading, isSuccess } = useWaitForTransactionReceipt({
  hash,
  onReplaced: (replacement) => {
    // replacement.reason: 'replaced' | 'repriced' | 'cancelled'
    // replacement.transaction.hash — НОВЫЙ hash
    console.log('Tx replaced!', replacement.reason, replacement.transaction.hash)

    if (replacement.reason === 'cancelled') {
      toast.warn('Транзакция отменена пользователем в кошельке')
    } else {
      // 'replaced' / 'repriced' — следим за новым hash дальше
      toast.info('Транзакция ускорена, новый hash: ' + replacement.transaction.hash)
    }
  },
})

5. Dropped transactions

Транзакция может «исчезнуть» из mempool: нода её reject'нула, mempool зачищен после длительного pending, или nonce-gap (пользователь отправил другую tx с тем же nonce). Если 5+ минут нет receipt — нужно проверить. 

import { usePublicClient } from 'wagmi'
import { useQuery } from '@tanstack/react-query'

function useTransactionStatus(hash?: \`0x\${string}\`) {
  const publicClient = usePublicClient()

  return useQuery({
    queryKey: ['tx-status', hash],
    enabled: !!hash,
    queryFn: async () => {
      if (!publicClient || !hash) return null

      // 1. Сначала пробуем receipt — самый быстрый путь
      try {
        return { kind: 'mined', receipt: await publicClient.getTransactionReceipt({ hash }) }
      } catch {}

      // 2. Если нет receipt — проверяем mempool
      try {
        const tx = await publicClient.getTransaction({ hash })
        return { kind: 'pending', tx }
      } catch {
        // 3. Если tx тоже нет — она dropped
        return { kind: 'dropped' }
      }
    },
    refetchInterval: (q) => {
      const data = q.state.data
      if (!data || data.kind === 'pending') return 5000
      return false
    },
  })
}

// В UI:
const { data } = useTransactionStatus(hash)
if (data?.kind === 'dropped') {
  return <p>Транзакция выпала из mempool. <button onClick={retry}>Отправить заново</button></p>
}

6. Gas bump — ускорение из dApp

Альтернатива MetaMask Speed Up: дать пользователю кнопку «Ускорить» прямо в dApp. Технически это новая транзакция с тем же nonce и повышенным maxFeePerGas (минимум +10%, иначе нода отвергнет как «replacement underpriced»). 

import { useWalletClient, usePublicClient } from 'wagmi'

async function speedUpTx(originalHash: \`0x\${string}\`) {
  const walletClient = useWalletClient().data
  const publicClient = usePublicClient()
  if (!walletClient || !publicClient) return

  // 1. Достаём оригинальную tx
  const original = await publicClient.getTransaction({ hash: originalHash })
  if (!original) throw new Error('original tx not found')

  // 2. Считаем новые fees (+25% relative to original)
  const newMaxFee   = (original.maxFeePerGas         ?? 0n) * 125n / 100n
  const newMaxPrio  = (original.maxPriorityFeePerGas ?? 0n) * 125n / 100n

  // 3. Отправляем «дубликат» с тем же nonce — старая умрёт
  const newHash = await walletClient.sendTransaction({
    to:    original.to ?? undefined,
    data:  original.input,
    value: original.value,
    nonce: original.nonce,                       // КРИТИЧНО — тот же nonce
    maxFeePerGas:         newMaxFee,
    maxPriorityFeePerGas: newMaxPrio,
  })

  return newHash
}

7. Reorg-safe confirmations

Один блок = вероятностное подтверждение. Reorg (откат блока) случается редко, но больно. Для критичных операций ждите N подтверждений:

Тип операцииConfirmationsВремя на mainnet
UI feedback (показать ✓)1~12 сек
Off-chain ledger / database write3-6~36–72 сек
Финализация фиатной выплаты12-32 (finality)~6 мин (после Merge)
На L2 (Optimism/Arbitrum)0 после batched proof / 1 после soft confirm~2 сек soft / ~7 дней hard (challenge period)
// wagmi
const { isSuccess: isConfirmed1 } = useWaitForTransactionReceipt({
  hash, confirmations: 1,
})

const { isSuccess: isConfirmed12 } = useWaitForTransactionReceipt({
  hash, confirmations: 12,
})

// UI:
{isConfirmed1 && !isConfirmed12 && (
  <p>✓ Принято · ждём финализации (12/12 confirmations)…</p>
)}
{isConfirmed12 && <p>✓ Финализировано в chain</p>}

const VARIANTS: Record<Status, { text: string; cls: string; icon: string }> = {
  idle:       { text: 'Готово к отправке',     cls: 'badge-idle',   icon: '○' },
  simulating: { text: 'Симуляция…',             cls: 'badge-yellow', icon: '⏳' },
  awaiting:   { text: 'Подпишите в кошельке',   cls: 'badge-blue',   icon: '🔑' },
  mining:     { text: 'Майнинг…',                cls: 'badge-blue',   icon: '⛏️' },
  confirmed:  { text: 'Подтверждено',           cls: 'badge-green',  icon: '✓' },
  reverted:   { text: 'Транзакция отменена',    cls: 'badge-red',    icon: '✗' },
  replaced:   { text: 'Ускорено в кошельке',    cls: 'badge-purple', icon: '↻' },
  dropped:    { text: 'Выпала из mempool',      cls: 'badge-red',    icon: '⚠' },
}

export function StatusBadge({ status, hash }: { status: Status; hash?: string }) {
  const v = VARIANTS[status]
  return (
    <span className={\`badge \${v.cls}\`}>
      <span className="icon">{v.icon}</span>
      <span>{v.text}</span>
      {hash && (
        <a href={\`https://etherscan.io/tx/\${hash}\`} target="_blank" rel="noopener">
          {hash.slice(0, 8)}…
        </a>
      )}
    </span>
  )
}

Задача 4 — Gas bump кнопка

# src/SpeedUp.tsx
import { useWalletClient, usePublicClient } from 'wagmi'

export function SpeedUp({ hash }: { hash: \`0x\${string}\` }) {
  const walletClient = useWalletClient().data
  const publicClient = usePublicClient()
  const [newHash, setNewHash] = useState<string>()

  const onSpeed = async () => {
    if (!walletClient || !publicClient) return
    const orig = await publicClient.getTransaction({ hash })
    if (!orig) return alert('not found')

    const h = await walletClient.sendTransaction({
      to:    orig.to ?? undefined,
      data:  orig.input,
      value: orig.value,
      nonce: orig.nonce,
      maxFeePerGas:         (orig.maxFeePerGas         ?? 0n) * 125n / 100n,
      maxPriorityFeePerGas: (orig.maxPriorityFeePerGas ?? 0n) * 125n / 100n,
    })
    setNewHash(h)
  }

  return (
    <div>
      <button onClick={onSpeed}>Ускорить (+25% gas)</button>
      {newHash && <p>Новый hash: {newHash}</p>}
    </div>
  )
}

# 3. Нажмите Ускорить — новая tx с тем же nonce и +25% fee.
