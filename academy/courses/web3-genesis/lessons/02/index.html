ERC-20: Deploy & Transfer

→ продолжение Lesson 01 — MetaMask & кошельки. Там вы разобрались с тем, кто подписывает транзакции; здесь — что эти транзакции делают.

ERC-20 — это самый распространённый стандарт fungible-токенов на EVM-совместимых сетях. Стандарт описывает шесть обязательных функций (totalSupply, balanceOf, transfer, transferFrom, approve, allowance) и два события (Transfer, Approval). В этом уроке мы сосредоточимся на трёх ключевых механиках: деплой, передача, чтение баланса. Всё это вы запустите прямо в браузере, без MetaMask, RPC и оплаты газа.

Зачем учебная песочница? Скорость обратной связи решает. Локальный детерминированный симулятор моделирует ровно те инварианты, которые потом проверит реальный контракт: дебет/кредит, неизменность totalSupply, запрет перевода на address(0), событие Transfer. После того как вы поймёте механику здесь, мы перейдём на Tenderly Virtual Testnet в следующих уроках — там RPC, отладчик и реальная виртуальная сеть.

1. Минимальная реализация ERC-20

Самый компактный «честный» ERC-20 — это книга балансов mapping(address => uint256) плюс счётчик предложения totalSupply. Всё остальное (метаданные, события, проверки) — это правила, без которых стандарт перестаёт быть стандартом. 

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract MinimalERC20 {
    string  public name;
    string  public symbol;
    uint8   public decimals;
    uint256 public totalSupply;

    mapping(address => uint256) public balanceOf;
    mapping(address => mapping(address => uint256)) public allowance;

    event Transfer(address indexed from, address indexed to, uint256 value);
    event Approval(address indexed owner, address indexed spender, uint256 value);

    constructor(string memory n, string memory s, uint8 d, uint256 supply) {
        name = n;
        symbol = s;
        decimals = d;
        totalSupply = supply * 10 ** d;
        balanceOf[msg.sender] = totalSupply;
        emit Transfer(address(0), msg.sender, totalSupply);
    }

    function transfer(address to, uint256 value) external returns (bool) {
        require(to != address(0), "ERC20: transfer to the zero address");
        require(balanceOf[msg.sender] >= value, "ERC20: transfer amount exceeds balance");
        unchecked {
            balanceOf[msg.sender] -= value;
            balanceOf[to] += value;
        }
        emit Transfer(msg.sender, to, value);
        return true;
    }
}

Обратите внимание на четыре инварианта, которые мы будем проверять во всём курсе: (1) totalSupply неизменно после деплоя, (2) сумма всех balanceOf равна totalSupply, (3) любой движение средств порождает Transfer-event, (4) запрет перевода на нулевой адрес.

3. Что произошло «под капотом»

  1. Deploy. Создаётся адрес контракта (детерминированно от имени деплойера и текущего nonce), totalSupply = initialSupply × 10^decimals зачисляется на balanceOf[deployer], эмитируется Transfer(address(0), deployer, totalSupply). Это «mint»-event: ERC-20 не имеет отдельного Mint-события — выпуск выражается переводом «из нулевого адреса».
  2. Transfer. Песочница проверяет два инварианта (to != 0x0, balance >= value), затем атомарно уменьшает balanceOf[from] и увеличивает balanceOf[to], эмитирует Transfer(from, to, value). Газовая стоимость списывается с native-баланса отправителя — точно так же, как в настоящей сети.
  3. Read views. balanceOf и totalSupply — это просто чтение из mapping и storage-слота; они бесплатны и не требуют транзакции.

4. Задание

Попробуйте. В песочнице доступны все 6 функций EIP-20: transfer, approve, transferFrom, плюс read-views balanceOf, allowance, totalSupply. Воспроизведите шесть сценариев:
  1. Деплой 1 000 AGT от Alice → проверьте, что у Alice ровно 1000 AGT, у Bob 0 AGT, у самого контракта тоже 0.
  2. Перевод 100 AGT Alice → Bob → Carol. Сумма балансов должна остаться 1000 AGT.
  3. Попробуйте перевести 10 000 AGT от Alice. Транзакция должна ревертнуться с сообщением «exceeds balance».
  4. Approve. Alice выдаёт Bob allowance 50 AGT. В карточке Allowances появится строка alice → bob 50 AGT; в ленте — событие Approval.
  5. TransferFrom. Bob (spender) переводит 25 AGT Alice → Carol. Allowance должна уменьшиться с 50 до 25, balance Carol — вырасти на 25.
  6. Infinite approve. Введите max в поле Allowance — это запишет 2²⁵⁶−1. Сделайте transferFrom 100. Проверьте, что allowance не уменьшилась (это поведение OZ / USDC — главный источник drainer-атак).

5. Тот же контракт — но в настоящем Solidity-компиляторе

In-memory симулятор учит ментальной модели; следующий шаг — запустить тот же контракт через solc-js и встроенный JavaScript-EVM. Ниже — кнопка, которая открывает Remix IDE прямо в странице с уже загруженным MinimalERC20.sol и включённым auto-compile. Деплоить можно без MetaMask: Remix → Deploy & run → Environment: Remix VM. 

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract MinimalERC20 {
    string  public name;
    string  public symbol;
    uint8   public decimals;
    uint256 public totalSupply;

    mapping(address => uint256) public balanceOf;
    mapping(address => mapping(address => uint256)) public allowance;

    event Transfer(address indexed from, address indexed to, uint256 value);
    event Approval(address indexed owner, address indexed spender, uint256 value);

    constructor(string memory n, string memory s, uint8 d, uint256 supply) {
        name = n;
        symbol = s;
        decimals = d;
        totalSupply = supply * 10 ** d;
        balanceOf[msg.sender] = totalSupply;
        emit Transfer(address(0), msg.sender, totalSupply);
    }

    function transfer(address to, uint256 value) external returns (bool) {
        require(to != address(0), "ERC20: transfer to the zero address");
        require(balanceOf[msg.sender] >= value, "ERC20: transfer amount exceeds balance");
        unchecked {
            balanceOf[msg.sender] -= value;
            balanceOf[to] += value;
        }
        emit Transfer(msg.sender, to, value);
        return true;
    }

    function approve(address spender, uint256 value) external returns (bool) {
        allowance[msg.sender][spender] = value;
        emit Approval(msg.sender, spender, value);
        return true;
    }

    function transferFrom(address from, address to, uint256 value) external returns (bool) {
        require(to != address(0), "ERC20: transfer to the zero address");
        uint256 allowed = allowance[from][msg.sender];
        require(allowed >= value, "ERC20: insufficient allowance");
        require(balanceOf[from] >= value, "ERC20: transfer amount exceeds balance");
        if (allowed != type(uint256).max) {
            unchecked { allowance[from][msg.sender] = allowed - value; }
        }
        unchecked {
            balanceOf[from] -= value;
            balanceOf[to] += value;
        }
        emit Transfer(from, to, value);
        return true;
    }
}
