Anvil & Foundry — локальная среда разработки для EVM

→ продолжение Lesson 03 — Ноды, JSON-RPC. Там мы изучили, как фронтенд разговаривает с блокчейном через JSON-RPC. Здесь мы разворачиваем собственный EVM-node прямо на ноутбуке, форкаем mainnet и пишем тесты на Solidity.

Каждый раз гонять тест против Sepolia — дорого и медленно: 12 секунд на блок, нужны тестовые ETH, публичные RPC лимитируют запросы. Foundry решает эту проблему: anvil поднимает полноценный EVM-node в памяти за <200 мс, forge test прогоняет тысячи юнит-тестов на Solidity прямо против него, а cast позволяет вызывать контракты и отправлять транзакции из командной строки — без MetaMask, без фронтенда, без ожиданий.

Что вы получите. После урока вы умеете: запустить локальный Anvil-node и задеплоить на него контракт одной командой; форкнуть mainnet или Sepolia, чтобы тест работал с реальными контрактами (USDC, Uniswap, Aave) без единого wei; написать полноценный forge test для ERC-20 с fuzzing-тестом; читать и записывать storage slot через cast; и воспроизвести тестовое состояние через anvil --state.

1. Что такое Foundry: четыре инструмента

Foundry — open-source toolkit для разработки на Solidity, написанный на Rust компанией Paradigm. Включает четыре исполняемых файла:

ИнструментЧто делаетАналог в HardHat-мире
forge Компилирует контракты, запускает тесты на Solidity, управляет зависимостями через git-submodules npx hardhat compile, npx hardhat test
anvil Локальный EVM-node в памяти (JSON-RPC :8545). Форкает любую сеть. Чит-коды для манипуляции состоянием. npx hardhat node, Ganache
cast CLI для взаимодействия с любым JSON-RPC: eth_call, send tx, decode ABI, read storage, ENS resolve npx hardhat run, ethers scripts
chisel Интерактивная Solidity REPL: пишете выражение — получаете результат в EVM мгновенно нет прямого аналога

Главное отличие от HardHat: тесты пишутся на Solidity, а не на JavaScript/TypeScript. Это означает: нет сериализации типов между JS и EVM, полная поддержка всех Solidity-конструкций в тестах, и скорость — forge test работает в 10–100 раз быстрее аналогов на JS.

2. Установка Foundry

Foundry устанавливается одной командой через foundryup — официальный installer, который скачивает pre-built бинари для вашей платформы (Linux, macOS, Windows WSL2): 

# Шаг 1: скачать и запустить foundryup
curl -L https://foundry.paradigm.xyz | bash

# Шаг 2: перезагрузить shell (или source ~/.bashrc / ~/.zshrc)
# Команда foundryup добавляет ~/.foundry/bin в PATH

# Шаг 3: установить/обновить последнюю версию
foundryup

# Проверка установки:
forge --version   # forge 0.2.0 (abcdef 2025-04-10T...)
anvil --version   # anvil 0.2.0 (abcdef 2025-04-10T...)
cast --version    # cast 0.2.0 (abcdef 2025-04-10T...)
chisel --version  # chisel 0.2.0 (abcdef 2025-04-10T...)
Обновление. Команда foundryup всегда устанавливает последний стабильный выпуск. Для конкретной версии: foundryup --version nightly-abc1234. Бинари кладутся в ~/.foundry/bin/. На macOS Apple Silicon (M1/M2/M3) нативно собран arm64 — Rosetta не нужна.

4. Fork mainnet с Anvil

Самая мощная функция Anvil — форк любой EVM-сети. При форке Anvil «притворяется» нодой выбранной сети: при запросе данных (storage, bytecode, balance) сначала смотрит в локальный кеш, а при промахе — делает реальный запрос к указанному RPC. Новые транзакции исполняются только локально: вы полностью изолированы от mainnet. 

# Форк Ethereum mainnet (нужен RPC-URL с архивными данными):
export ETH_RPC_URL=https://eth.llamarpc.com
anvil --fork-url $ETH_RPC_URL

# Форк конкретного блока (воспроизводимо!):
anvil --fork-url $ETH_RPC_URL --fork-block-number 21500000

# Форк Sepolia:
anvil --fork-url https://sepolia.gateway.tenderly.co

# Форк Arbitrum One:
anvil --fork-url https://arb1.arbitrum.io/rpc
Зачем форк mainnet? Вы получаете реальное состояние всех контрактов — USDC, Uniswap v3, Aave, ENS — прямо у себя локально. Можно: написать тест, который реально вызывает USDC.transfer(); проверить свой контракт против конкретной версии протокола; воспроизвести exploit, опубликованный в post-mortem (указав блок прямо перед атакой); протестировать интеграцию с любым контрактом без нужды в тестовых токенах. Всё это — без единой реальной транзакции в сеть.

4.1 Читаем форкнутое состояние

# После запуска: anvil --fork-url $ETH_RPC_URL

# Баланс USDC у Binance (крупнейший holder на mainnet):
USDC=0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48
BINANCE=0x28C6c06298d514Db089934071355E5743bf21d60

# 2500000000000000   (2.5 трлн USDC-units = 2.5 млрд USDC)

# Получить ETH у произвольного адреса — чит-код Anvil:
cast rpc anvil_setBalance $BINANCE 0x56BC75E2D63100000 --rpc-url http://localhost:8545
# (0x56BC75E2D63100000 = 100 ETH в wei)

# Имперсонация: отправить tx от чужого имени (без приватного ключа):
cast rpc anvil_impersonateAccount $BINANCE --rpc-url http://localhost:8545
cast send $USDC "transfer(address,uint256)" 0xf39F...2266 1000000000 \
  --from $BINANCE --rpc-url http://localhost:8545 --unlocked

5.4 Структура теста на Solidity

Тест в Foundry — обычный Solidity-контракт, наследующий Test из forge-std. Каждая функция с префиксом test — отдельный тест; setUp() вызывается перед каждым тестом. 

// test/Counter.t.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.25;

import "forge-std/Test.sol";
import "../src/Counter.sol";

contract CounterTest is Test {
    Counter public counter;

    // Вызывается перед каждым тестом — чистое состояние
    function setUp() public {
        counter = new Counter();
        counter.setNumber(0);
    }

    // test-функции должны начинаться с "test"
    function test_Increment() public {
        counter.increment();
        assertEq(counter.number(), 1);
    }

    // testFail_ — ожидаем, что функция reverts
    function testFail_SetNumberByStranger() public {
        vm.prank(address(0xdead)); // следующий вызов от другого адреса
        counter.setNumber(42);     // должен revert (если есть доступ-контроль)
    }

    // Fuzz-тест: forge автоматически подбирает граничные значения x
    function testFuzz_SetNumber(uint256 x) public {
        counter.setNumber(x);
        assertEq(counter.number(), x);
    }
}
# Запустить все тесты:
forge test

# Запустить с подробным выводом (трассировка вызовов):
forge test -vvv

# Запустить конкретный тест по имени:
forge test --match-test test_Increment -vvvv

# Запустить тесты с форком mainnet:
forge test --fork-url $ETH_RPC_URL -vv

# Показать потребление газа:
forge test --gas-report

5.5 Cheatcodes: vm.* в тестах

В тестах forge-std доступен объект vm — специальный адрес 0x7109709ECfa91a80626fF3989D68f67F5b1DD12D, через который тест управляет состоянием EVM: 

// Примеры cheatcodes в тесте
contract MyTest is Test {

    function test_Cheats() public {
        // Изменить msg.sender для следующего вызова:
        vm.prank(address(0xAlice));
        token.transfer(bob, 100);

        // Изменить msg.sender для всего блока до stopPrank():
        vm.startPrank(address(0xAlice));
        token.approve(spender, 1000);
        token.transfer(bob, 100);
        vm.stopPrank();

        // Перемотать время вперёд:
        vm.warp(block.timestamp + 7 days);

        // Перемотать блоки вперёд:
        vm.roll(block.number + 100);

        // Принудительно задать ETH-баланс адреса:
        vm.deal(address(0xAlice), 10 ether);

        // Ожидать revert со строкой (проверяет сообщение):
        vm.expectRevert("Insufficient balance");
        token.transfer(bob, 10_000_000 ether);

        // Ожидать конкретный event:
        vm.expectEmit(true, true, false, true);
        emit Transfer(alice, bob, 100);
        token.transfer(bob, 100);

        // Читать environment variables в тесте:
        string memory rpc = vm.envString("ETH_RPC_URL");

        // Mock-вызов: любой вызов balanceOf вернёт 999:
        vm.mockCall(
            address(token),
            abi.encodeWithSelector(IERC20.balanceOf.selector, address(this)),
            abi.encode(999)
        );
    }
}

6. Cast: вызов контрактов из командной строки

cast — это Swiss Army knife для работы с EVM через командную строку. Работает с любым JSON-RPC endpoint: Anvil, Alchemy, Infura, llamarpc.

6.1 eth_call — чтение данных

# Вызвать view-функцию (не тратит газ, не меняет состояние):
# Синтаксис: cast call <address> "<signature>" [args...] --rpc-url <url>

# Баланс USDC у адреса:
cast call 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48 \
  "balanceOf(address)(uint256)" \
  0x28C6c06298d514Db089934071355E5743bf21d60 \
  --rpc-url $ETH_RPC_URL
# 2500000000000000

# Символ токена:
cast call 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48 \
  "symbol()(string)" \
  --rpc-url $ETH_RPC_URL
# USDC

# ENS: получить адрес по имени (автоматический resolve):
cast resolve-name vitalik.eth --rpc-url $ETH_RPC_URL
# 0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045

# Обратный resolve: имя по адресу:
cast lookup-address 0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045 --rpc-url $ETH_RPC_URL
# vitalik.eth

6.2 Отправка транзакций

# Отправить ETH:
cast send 0x70997970C51812dc3A010C7d01b50e0d17dc79C8 \
  --value 1ether \
  --private-key 0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80 \
  --rpc-url http://localhost:8545

# Вызвать write-функцию контракта:
cast send 0xMY_CONTRACT \
  "transfer(address,uint256)" \
  0xRecipient 1000000 \
  --private-key $PRIVATE_KEY \
  --rpc-url http://localhost:8545

# Отправить без ожидания майнинга:
cast send ... --async

# Получить receipt после:
cast receipt 0xTX_HASH --rpc-url http://localhost:8545

6.3 Декодирование данных

# Декодировать calldata транзакции (ABI-encode):
cast calldata-decode "transfer(address,uint256)" \
  0xa9059cbb000000000000000000000000d8da6bf26964af9d7eed9e03e53415d37aa9604500000000000000000000000000000000000000000000000000000000000f4240
# address: 0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045
# uint256: 1000000

# Декодировать возвращаемые данные:
cast abi-decode "balanceOf(address)(uint256)" 0x000...00000f4240
# 1000000

# Вычислить selector функции (первые 4 байта calldata):
cast sig "transfer(address,uint256)"
# 0xa9059cbb

# Посмотреть event signature (topic0):
cast sig-event "Transfer(address indexed,address indexed,uint256)"
# 0xddf252ad1be2c89b69c2b068fc378daa952ba7f163c4a11628f55a4df523b3ef

# Перевести wei в ether:
cast to-unit 1000000000000000000 ether
# 1.000000000000000000

6.4 Чтение storage slots

Каждый контракт хранит данные в 32-байтовых ячейках (slots). Слот 0 — первая переменная контракта, слот 1 — вторая, и т.д. (для простых типов). Маппинги и динамические массивы используют keccak256-производные от ключа + slot-номера. 

# Прочитать slot 0 контракта (обычно owner или другая первая переменная):
cast storage 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48 0 --rpc-url $ETH_RPC_URL
# 0x00000000000000000000000043506849d7c04f9138d1a2050bbf3a0c054402dd

# Для маппинга balances[address]:
# slot = keccak256(abi.encode(address, uint256(slot_of_mapping)))
# Вычислить вручную:
cast keccak $(cast abi-encode "f(address,uint256)" 0xd8dA6BF...96045 9)
# Используем результат как slot:
cast storage $USDC 0x<computed_slot> --rpc-url $ETH_RPC_URL

# Посмотреть весь layout storage (нужен ABI):
forge inspect MyContract storageLayout

6.5 Полезные утилиты cast

# Конвертации:
cast to-hex 1000000          # → 0xf4240
cast to-dec 0xf4240          # → 1000000
cast to-wei 1.5 ether        # → 1500000000000000000
cast from-wei 1500000000000000000 ether  # → 1.500000000000000000

# Информация о блоке:
cast block latest --rpc-url $ETH_RPC_URL

# Информация о транзакции:
cast tx 0xTX_HASH --rpc-url $ETH_RPC_URL

# Код контракта:

cast run 0xTX_HASH --rpc-url $ETH_RPC_URL

7. Четыре практические задачи

7.1 Задача №1 — запустить Anvil и задеплоить контракт через forge create

Создаём простой контракт, деплоим через forge create и проверяем через cast call. Используем стандартный аккаунт Anvil — никаких тестовых токенов, никаких Faucets. 

# Шаг 1: Создать проект и написать контракт
forge init task01 --no-git
cat > task01/src/Greeter.sol << 'EOF'
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.25;

contract Greeter {
    string private greeting;
    address public immutable owner;

    event GreetingSet(address indexed by, string newGreeting);

    constructor(string memory _greeting) {
        greeting = _greeting;
        owner = msg.sender;
    }

    function greet() external view returns (string memory) {
        return greeting;
    }

    function setGreeting(string calldata _greeting) external {
        require(msg.sender == owner, "only owner");
        greeting = _greeting;
        emit GreetingSet(msg.sender, _greeting);
    }
}
EOF

# Шаг 2: Запустить Anvil в отдельном терминале
anvil &
ANVIL_PID=$!

# Шаг 3: Задеплоить контракт
# --private-key — первый аккаунт Anvil
GREETER=$(forge create task01/src/Greeter.sol:Greeter \
  --constructor-args "Hello, Foundry!" \
  --private-key 0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80 \
  --rpc-url http://127.0.0.1:8545 \
  --json | jq -r '.deployedTo')

echo "Greeter deployed to: $GREETER"

# Шаг 4: Прочитать greeting
cast call $GREETER "greet()(string)" --rpc-url http://127.0.0.1:8545
# Hello, Foundry!

# Шаг 5: Обновить greeting
cast send $GREETER "setGreeting(string)" "Hello, Anvil!" \

7.3 Задача №3 — forge test для ERC-20 transfer

Пишем полноценный тестовый контракт для самописного ERC-20. Покрываем: transfer, transferFrom с approve, mint, burn, и фаззинг на инвариантах балансов. 

// src/SimpleToken.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.25;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/access/Ownable.sol";

contract SimpleToken is ERC20, Ownable {
    constructor(string memory name_, string memory symbol_, uint256 initialSupply)
        ERC20(name_, symbol_)
        Ownable(msg.sender)
    {
        _mint(msg.sender, initialSupply * 10 ** decimals());
    }

    function mint(address to, uint256 amount) external onlyOwner {
        _mint(to, amount);
    }

    function burn(uint256 amount) external {
        _burn(msg.sender, amount);
    }
}
// test/SimpleToken.t.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.25;

import "forge-std/Test.sol";
import "../src/SimpleToken.sol";

contract SimpleTokenTest is Test {
    SimpleToken token;
    address owner   = address(0xA11CE);
    address alice   = address(0xA1CE);
    address bob     = address(0xB0B);
    address carol   = address(0xCA401);

    uint256 constant INITIAL_SUPPLY = 1_000_000; // 1M tokens

    function setUp() public {
        vm.startPrank(owner);
        token = new SimpleToken("Simple Token", "SIMP", INITIAL_SUPPLY);
        vm.stopPrank();
    }

    // --- Базовые тесты ---

    function test_InitialSupply() public view {
        assertEq(token.totalSupply(), INITIAL_SUPPLY * 1e18);
        assertEq(token.balanceOf(owner), INITIAL_SUPPLY * 1e18);
    }

    function test_Transfer() public {
        uint256 amount = 100 * 1e18;
        vm.prank(owner);
        token.transfer(alice, amount);

        assertEq(token.balanceOf(alice), amount);
        assertEq(token.balanceOf(owner), (INITIAL_SUPPLY * 1e18) - amount);
    }

    function test_TransferFrom() public {
        uint256 amount = 50 * 1e18;
        // owner апрувит alice отправлять от его имени
        vm.prank(owner);
        token.approve(alice, amount);

        assertEq(token.allowance(owner, alice), amount);

        // alice отправляет средства owner → bob
        vm.prank(alice);
        token.transferFrom(owner, bob, amount);

        assertEq(token.balanceOf(bob), amount);
        assertEq(token.allowance(owner, alice), 0);
    }

    function test_RevertTransfer_InsufficientBalance() public {
        vm.prank(alice); // у alice нет токенов
        vm.expectRevert();
        token.transfer(bob, 1);
    }

    function test_RevertTransferFrom_NotApproved() public {
        vm.prank(alice); // alice не апрувнута
        vm.expectRevert();
        token.transferFrom(owner, bob, 1);
    }

    function test_Mint() public {
        uint256 mintAmount = 500 * 1e18;
        vm.prank(owner);
        token.mint(alice, mintAmount);

        assertEq(token.balanceOf(alice), mintAmount);
        assertEq(token.totalSupply(), (INITIAL_SUPPLY * 1e18) + mintAmount);
    }

    function test_RevertMint_NotOwner() public {
        vm.prank(alice);
        vm.expectRevert();
        token.mint(alice, 1);
    }

    function test_Burn() public {
        uint256 burnAmount = 200 * 1e18;
        vm.prank(owner);
        token.burn(burnAmount);

        assertEq(token.balanceOf(owner), (INITIAL_SUPPLY * 1e18) - burnAmount);
        assertEq(token.totalSupply(), (INITIAL_SUPPLY * 1e18) - burnAmount);
    }

    function test_Event_Transfer() public {
        uint256 amount = 100 * 1e18;
        // Ожидаем событие Transfer(owner, alice, amount)
        vm.expectEmit(true, true, false, true, address(token));
        emit Transfer(owner, alice, amount);

        vm.prank(owner);
        token.transfer(alice, amount);
    }

    // --- Fuzz-тесты ---

    // Инвариант: сумма балансов всегда = totalSupply
    function testFuzz_Transfer_PreservesTotalSupply(uint256 amount) public {
        // Ограничиваем amount доступным балансом owner
        amount = bound(amount, 0, token.balanceOf(owner));

        uint256 supplyBefore = token.totalSupply();
        vm.prank(owner);
        token.transfer(alice, amount);

        assertEq(token.totalSupply(), supplyBefore);
        assertEq(token.balanceOf(owner) + token.balanceOf(alice), supplyBefore);
    }

    function testFuzz_Burn_DecreasesSupply(uint256 amount) public {
        amount = bound(amount, 0, token.balanceOf(owner));

        uint256 supplyBefore = token.totalSupply();
        vm.prank(owner);
        token.burn(amount);

        assertEq(token.totalSupply(), supplyBefore - amount);
    }
}

Форм-сценарии, где --load-state особенно полезен: (1) CI/CD — запускаете integration-тесты против зафиксированного состояния, результат детерминирован; (2) командная разработка — один разработчик готовит стейт, остальные его скачивают и воспроизводят; (3) воспроизведение on-chain состояния на произвольном блоке — форкайте с --fork-block-number, настраивайте, дампируйте, и дальше работаете без RPC-зависимости.

9. Forge script: деплой в тестнет и mainnet

Для production-деплоев вместо forge create используют forge script: Solidity-скрипт, который можно симулировать локально и затем отправить broadcast в сеть. 

// script/Deploy.s.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.25;

import "forge-std/Script.sol";
import "../src/SimpleToken.sol";

contract DeployScript is Script {
    function run() external returns (SimpleToken token) {
        // Считать приватный ключ из env (никогда не хардкодить!):
        uint256 deployerKey = vm.envUint("PRIVATE_KEY");
        address deployer = vm.addr(deployerKey);

        console.log("Deployer:", deployer);
        console.log("Balance:", deployer.balance);

        // Всё внутри broadcast() отправляется в сеть:
        vm.startBroadcast(deployerKey);

        token = new SimpleToken("My Token", "MTK", 1_000_000);
        token.mint(deployer, 500_000 * 1e18);

        vm.stopBroadcast();

        console.log("Token deployed to:", address(token));
    }
}
# Симуляция (без реальной отправки):
forge script script/Deploy.s.sol:DeployScript \
  --rpc-url $SEPOLIA_RPC_URL -vv

# Деплой в Sepolia (broadcast):
forge script script/Deploy.s.sol:DeployScript \
  --rpc-url $SEPOLIA_RPC_URL \
  --private-key $PRIVATE_KEY \
  --broadcast \
  --verify \                    # автоматически верифицировать на Etherscan
  --etherscan-api-key $ETHERSCAN_KEY \
  -vvv
