Lab 05 · Gas Optimization

Каждая инструкция EVM стоит газ — а газ стоит денег. В этой лабораторной работе вы напишете «наивный» контракт, измерите его базовое потребление и применените семь классических техник оптимизации. После каждого шага будете измерять результат через forge gas-report и forge snapshot, чтобы чётко видеть, сколько газа сэкономила каждая техника. В финале вы поймёте, какие оптимизации дают наибольший эффект при наименьшей сложности кода.

Что вы сделаете:
  • Напишете наивный контракт с динамическим массивом и циклом.
  • Измерите базовый gas через forge test --gas-report и снимок forge snapshot.
  • Упакуете struct в один storage slot (uint128+uint128) и измерите улучшение.
  • Замените memory на calldata для read-only параметров.
  • Заменёте require(msg, string) на custom errors.
  • Используете immutable и constant вместо storage.
  • Примените unchecked {} для overflow-safe арифметики.
Что сдать: таблицу сравнения gas cost до и после каждой оптимизации (из forge snapshot --diff) с комментариями.

Задание 1

Напишите наивный контракт src/NaiveStorage.sol с динамическим массивом uint256[] public items и функцией sumAll(), суммирующей все элементы в цикле. Добавьте функцию addItem(uint256) и getItem(uint256 index). Используйте намеренно неэффективный подход: items.length вычисляется на каждой итерации. 

// src/NaiveStorage.sol — намеренно неэффективный
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract NaiveStorage {
    uint256[] public items;
    string    public name;
    address   public admin;
    uint256   public fee;        // Читается из storage при каждом вызове

    error Unauthorized();
    // (пока не используется — добавим в задании 5)

    constructor(string memory _name, address _admin, uint256 _fee) {
        name  = _name;
        admin = _admin;
        fee   = _fee;
    }

    function addItem(uint256 value) external {
        // ❌ Запись в storage без проверки — дорогостоящая операция
        items.push(value);
    }

    /// @notice Суммирует все элементы — намеренно неэффективно
    function sumAll(uint256[] memory input) external pure returns (uint256 total) {
        // ❌ memory вместо calldata (лишнее копирование)
        // ❌ items.length вычисляется на каждой итерации цикла
        for (uint256 i = 0; i < input.length; i++) {
            total += input[i];
        }
    }

    function requireAdmin() external view {
        // ❌ Строковые ошибки тратят больше газа
        require(msg.sender == admin, "NaiveStorage: caller is not admin");
    }

    struct UserData {
        uint256 balance;    // ❌ Занимает целый 32-байтный слот
        uint256 timestamp;  // ❌ Ещё один слот — итого 2 SSTORE
    }

    mapping(address => UserData) public userData;

    function setUserData(address user, uint256 balance, uint256 ts) external {
        userData[user] = UserData(balance, ts);
    }
}

Критерий приёмки: контракт компилируется; напишите тест test_NaiveGasBaseline, измеряющий gas для addItem, sumAll и setUserData.

Задание 3

Оптимизируйте struct-паттерн: упакуйте UserData в один storage slot, заменив два uint256 на uint128 + uint128. Один slot = 32 байта; два uint128 помещаются в один slot — одна операция SSTORE вместо двух. 

// src/OptimizedStorage.sol — с упакованным struct
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract OptimizedStorage {

    // ✅ ОПТИМИЗАЦИЯ 1: Storage packing — оба поля в одном 32-байтном слоте
    struct UserData {
        uint128 balance;    // 16 байт
        uint128 timestamp;  // 16 байт  ← вместе = 32 байта = 1 storage slot
    }

    mapping(address => UserData) public userData;

    function setUserData(address user, uint128 balance, uint128 ts) external {
        // ✅ Одна запись в storage вместо двух
        userData[user] = UserData(balance, ts);
    }

    function getUserBalance(address user) external view returns (uint128) {
        return userData[user].balance;   // ✅ Один SLOAD, достаём оба поля сразу
    }
}
Правило упаковки. Solidity упаковывает переменные в storage последовательно — если следующая переменная помещается в текущий слот (32 байта), она туда добавляется. Убедитесь, что uint128+uint128 стоят рядом в struct — если между ними вставить uint256, упаковка сломается.

Задание 4

Замените memory на calldata для read-only параметров функций, принимающих массивы или struct'ы. calldata — это read-only область, не требующая копирования данных в память. 

// В OptimizedStorage.sol замените:

// ❌ До: memory — данные копируются из calldata в memory
function sumAll(uint256[] memory input) external pure returns (uint256 total) {
    for (uint256 i = 0; i < input.length; i++) {
        total += input[i];
    }
}

// ✅ После: calldata — данные читаются напрямую, без копирования
function sumAll(uint256[] calldata input) external pure returns (uint256 total) {
    for (uint256 i = 0; i < input.length; i++) {
        total += input[i];
    }
}

// Аналогично для struct-параметров:

// ❌ До:
function processUser(UserData memory data) external pure returns (uint256) {
    return data.balance + data.timestamp;
}

// ✅ После:
function processUser(UserData calldata data) external pure returns (uint256) {
    return data.balance + data.timestamp;
}

Когда calldata нельзя использовать: если вы модифицируете параметр внутри функции (например, arr[0] = 42) — нужен memory, так как calldata read-only.

Критерий приёмки: forge snapshot --diff после замены показывает экономию ~200-500 gas на вызов для массива из 10 элементов; таблица обновлена.

Задание 5

Замените строковые require-ошибки на custom errors. Строки в Solidity кодируются как ABI-данные (минимум 64 байт на короткую строку); custom errors кодируются как 4-байтный selector + аргументы. 

// ❌ До: строковая ошибка — ~200+ газа за storage строки в revert
function requireAdmin() external view {
    require(msg.sender == admin, "NaiveStorage: caller is not admin");
}

// ✅ После: custom error — 4 байта selector
error Unauthorized(address caller);

function requireAdmin() external view {
    if (msg.sender != admin) revert Unauthorized(msg.sender);
}

// Ещё примеры custom errors с параметрами:
error InsufficientBalance(address account, uint256 required, uint256 available);
error DeadlineExpired(uint256 deadline, uint256 current);
error InvalidAmount(uint256 amount);

// Использование:
function withdraw(uint256 amount) external {
    uint256 bal = balances[msg.sender];
    if (amount > bal) revert InsufficientBalance(msg.sender, amount, bal);
    // ...
}

Измерьте разницу в gas для revert-кейса: создайте тест, который ожидает revert, и сравните gas до и после замены.

Задание 6

Перенесите фиксированные значения из storage в immutable и constant. constant — compile-time константы (вшиваются в байткод); immutable — задаются в конструкторе и тоже вшиваются в байткод, не занимая storage slot. 

// ❌ До: fee читается из storage при каждом вызове (SLOAD = 2100 gas cold)
contract NaiveStorage {
    uint256 public fee;    // storage slot

    constructor(uint256 _fee) {
        fee = _fee;
    }

    function getFeeTotal(uint256 amount) external view returns (uint256) {
        return amount * fee / 10_000;  // ❌ SLOAD здесь
    }
}

// ✅ После: immutable вшивается в байткод деплоя (3 gas вместо 2100)
contract OptimizedStorage {
    uint256 public immutable FEE;       // immutable — задаётся в constructor
    uint256 public constant MAX_ITEMS = 1000;  // constant — compile-time

    constructor(uint256 _fee) {
        FEE = _fee;
    }

    function getFeeTotal(uint256 amount) external view returns (uint256) {
        return amount * FEE / 10_000;  // ✅ Читает из байткода, не storage
    }

    function addItem(uint256[] storage items, uint256 value) external {
        require(items.length < MAX_ITEMS, "Max items reached");
        items.push(value);
    }
}
Ключевое слово Где хранится Когда задаётся Gas на чтение
storage Merkle Patricia Trie контракта В любое время 2100 (cold) / 100 (warm)
immutable Байткод контракта (CODECOPY) Только в конструкторе ~3 (как PUSH)
constant Вшивается компилятором inline Compile-time ~3 (как PUSH)

Критерий приёмки: forge snapshot --diff показывает экономию ~2000 gas на каждое чтение заменённой переменной.

Задание 7

Применените unchecked {} для арифметики, где overflow/underflow невозможен по логике программы. С Solidity 0.8+ все операции проверяются по умолчанию (~13 доп. opcodes); unchecked снимает это, возвращая поведение до 0.8. 

// ❌ До: каждое i++ содержит overflow-проверку
function sumAll(uint256[] calldata input) external pure returns (uint256 total) {
    for (uint256 i = 0; i < input.length; i++) {   // i++ — проверяемый increment
        total += input[i];                          // total += — проверяемое сложение
    }
}

// ✅ После: unchecked для счётчика цикла (никогда не overflow — length <= 2^256-1)
function sumAllOptimized(uint256[] calldata input)
    external
    pure
    returns (uint256 total)
{
    uint256 len = input.length;      // ✅ Кэшируем length в memory (избегаем повторный MLOAD)
    for (uint256 i = 0; i < len; ) {
        total += input[i];
        unchecked { ++i; }           // ✅ ++i дешевле i++; unchecked убирает проверку
    }
}

// Ещё пример: безопасный unchecked для downcast
function safePack(uint256 a, uint256 b)
    external
    pure
    returns (uint128 packedA, uint128 packedB)
{
    require(a <= type(uint128).max, "a overflow");
    require(b <= type(uint128).max, "b overflow");
    unchecked {
        packedA = uint128(a);   // Безопасно — проверено выше
        packedB = uint128(b);
    }
}
