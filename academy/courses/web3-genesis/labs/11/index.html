Lab 11 · GOSH: деплой DeFi-контракта в децентрализованное хранилище

В этом лабе вы пройдёте полный цикл: установите GOSH CLI, создадите DAO и репозиторий на блокчейне, запушите смарт-контракт курса on-chain, поднимете локальную ноду через Docker Compose и верифицируете Docker-образ через официальное расширение. К концу лаба у вас будет реальный on-chain репозиторий с DeFi-кодом, доступный через стандартный git clone.

Цели лаба. После выполнения всех заданий вы сможете: устанавливать и конфигурировать GOSH CLI; создавать DAO и репозиторий на Acki Nacki testnet; использовать GOSH как обычный Git remote; настраивать CI-зеркалирование; устанавливать Docker Extension и верифицировать образ; запустить локальную ноду и прочитать её статус.

Задание 1 — Установка GOSH CLI

Установите GOSH CLI и убедитесь, что он работает корректно. 

# Linux / macOS — официальный install-скрипт
wget -O - https://raw.githubusercontent.com/gosh-sh/gosh/dev/install.sh \
  | bash -s

# Добавить в PATH (bash)
echo 'export PATH=$PATH:$HOME/.gosh' >> ~/.bashrc && source ~/.bashrc

# Проверка
gosh --version
# ожидаемый вывод: gosh 6.x.x (или выше)

# Посмотреть доступные команды
gosh --help

После установки GOSH CLI создаёт конфиг в ~/.gosh/. Здесь хранятся ключи и настройки сети (testnet vs mainnet).

Задание 1.1

Выполните gosh --version и убедитесь, что версия ≥ 6.0.0. Выведите результат gosh --help и найдите команды: account, dao, repo, sbom.

Задание 2 — Создание аккаунта и DAO

GOSH не требует email или пароля — аутентификация через криптографический ключ. На testnet токены можно получить через faucet. 

# Создать новый аккаунт (генерирует seed phrase)
gosh account create --name my-defi-dao
# Сохраните seed phrase в надёжном месте!

# Получить testnet токены через faucet
gosh faucet --account my-defi-dao

# Проверить баланс
gosh account info --name my-defi-dao

# Создать DAO (Decentralized Autonomous Organization)
# DAO управляет репозиториями — кто может пушить, кто апрувит PR
gosh dao create \
  --name     web3-genesis-dao \
  --account  my-defi-dao

# Получить адрес DAO (понадобится при клонировании)
gosh dao info --name web3-genesis-dao

Задание 2.1

Создайте аккаунт и DAO. Скопируйте адрес DAO — он выглядит как 0:abcdef1234.../web3-genesis-dao. Этот адрес — смарт-контракт в блокчейне Acki Nacki.

Задание 3 — Репозиторий on-chain

Создайте репозиторий в GOSH и подключите его к локальному проекту как дополнительный remote. Используйте контракт из лаба 4 или 7. 

# Создать репозиторий в DAO
gosh repo create \
  --dao  web3-genesis-dao \
  --name secure-vault

# Репозиторий доступен по адресу:
# gosh://0:<dao-addr>/secure-vault

# --- Вариант A: клонировать пустой репо ---
git clone gosh://0:<dao-addr>/secure-vault
cd secure-vault

# Скопировать в него контракт из лаба 4
cp -r ~/web3-labs/lab04-secure-vault/src ./src
cp ~/web3-labs/lab04-secure-vault/foundry.toml .

git add .
git commit -m "feat: initial SecureVault contract"
git push gosh main

# --- Вариант B: добавить GOSH к существующему репо ---
cd ~/web3-labs/lab04-secure-vault
git remote add gosh gosh://0:<dao-addr>/secure-vault
git push gosh main
Что происходит при push. GOSH CLI разбивает каждый git-объект (commit, tree, blob) на транзакции Acki Nacki. Каждый blob — отдельный смарт-контракт. Commit-объект хранит хеши всех дочерних объектов — так обеспечивается иммутабельность и верифицируемость.

Задание 3.1

После успешного git push gosh main откройте браузер и перейдите на app.gosh.sh. Найдите свой DAO и репозиторий. Убедитесь, что коммит виден в веб-интерфейсе с правильным сообщением.

Задание 3.2

Клонируйте репозиторий в новую директорию как будто вы другой разработчик: 

cd /tmp
git clone gosh://0:<dao-addr>/secure-vault cloned-vault
ls cloned-vault/src/

Убедитесь, что файлы корректно получены. Это подтверждает, что контракт работает как полноценный Git-сервер.

Задание 4 — CI-зеркалирование

Настройте автоматическое зеркалирование: при каждом push в GitHub изменения дублируются в GOSH. Это даёт censorship-resistance без изменения привычного workflow команды. 

# .github/workflows/mirror-gosh.yml
name: mirror-to-gosh

on:
  push:
    branches: [main, develop]
  workflow_dispatch:

jobs:
  mirror:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0   # нужна полная история

      - name: Install GOSH CLI
        run: |
          wget -q -O - \
            https://raw.githubusercontent.com/gosh-sh/gosh/dev/install.sh \
            | bash -s
          echo "$HOME/.gosh" >> $GITHUB_PATH

      - name: Configure GOSH credentials
        run: gosh config set key "${{ secrets.GOSH_PRIVATE_KEY }}"

      - name: Push to GOSH
        run: |
          git remote add gosh \
            gosh://0:${{ vars.GOSH_DAO_ADDR }}/secure-vault
          git push gosh --mirror

      - name: Verify last commit on GOSH
        run: |
          GOSH_HEAD=$(gosh repo log \
            --dao web3-genesis-dao \
            --repo secure-vault \
            --limit 1 --format "%H")
          LOCAL_HEAD=$(git rev-parse HEAD)
          [ "$GOSH_HEAD" = "$LOCAL_HEAD" ] \
            && echo "Mirror OK" \
            || (echo "Mirror MISMATCH" && exit 1)

Задание 4.1

Добавьте секрет GOSH_PRIVATE_KEY и переменную GOSH_DAO_ADDR в Settings → Secrets/Variables вашего репозитория. Сделайте тестовый коммит и убедитесь, что workflow выполняется зелёным.

Задание 5 — Docker Extension: верификация образа

Установите GOSH-расширение в Docker Desktop и верифицируйте, что Docker-образ был собран из кода в вашем GOSH-репозитории. 

# Установка через Docker CLI (альтернатива GUI)
docker extension install teamgosh/docker-extension

# Или через Docker Desktop:
# Extensions → Browse → поиск "GOSH" → Install

После установки расширение появится в левой панели Docker Desktop.

Задание 5.1 — Собрать образ с GOSH-меткой

# Dockerfile для Foundry-тестов контракта
FROM ghcr.io/foundry-rs/foundry:latest
WORKDIR /app
COPY . .
RUN forge build

# Собрать образ с GOSH-меткой провенанса
docker build \
  --label "gosh.repo=0:<dao-addr>/secure-vault" \
  --label "gosh.commit=$(git rev-parse HEAD)" \
  -t secure-vault-tests:latest .

# Запустить тесты
docker run --rm secure-vault-tests:latest forge test -vv

Задание 5.2 — Верифицировать в расширении

В GOSH Docker Extension введите имя образа secure-vault-tests:latest. Расширение прочитает GOSH-метки, найдёт соответствующий коммит в блокчейне и покажет статус: ✓ GOSH-verified.

Производственный вариант. Для публичных образов (ghcr.io, Docker Hub) GOSH Extension верифицирует через on-chain Build Record — специальный контракт, который создаётся автоматически при сборке через GOSH CI. Детали: docs.gosh.sh/working-with-gosh/docker-extension.

Задание 6 — Локальная нода Acki Nacki

Запустите локальную ноду в devnet-режиме. Это бесплатно, не требует покупки лицензии и позволяет изучить экономику нод без реальных затрат. 

# Клонировать официальный репо
git clone https://github.com/gosh-sh/gosh
cd gosh/docker-compose

# Скопировать пример конфига
cp .env.example .env

# В .env указать режим devnet (без реального ключа ноды)
# NODE_MODE=devnet
# NODE_KEY=   (оставить пустым для devnet)

# Запустить
docker compose up -d

# Проверить статус
docker compose ps

# Посмотреть логи синхронизации
docker compose logs -f node --tail=50

# Запросить статус через RPC
curl -s http://localhost:3030/status | jq '{
  sync_info: .sync_info,
  validator_info: .validator_info
}'

Задание 6.1

Убедитесь, что нода запустилась и отвечает на RPC-запросы. Запишите значения latest_block_height и catching_up из /status.

Задание 6.2 — GOSH CLI через локальную ноду

# Переключить CLI на локальную ноду
gosh config set endpoint http://localhost:3030

# Создать тестовый аккаунт через локальную ноду
gosh account create --name local-test

# Получить баланс (devnet токены бесплатны)
gosh faucet --account local-test
gosh account info --name local-test

# Вернуться на testnet
gosh config set endpoint https://net.ton.dev

Задание 7 — On-chain SBOM

Сгенерируйте Software Bill of Materials для вашего DeFi-контракта и привяжите его к on-chain коммиту. 

# Установить Syft для генерации SBOM
curl -sSfL https://raw.githubusercontent.com/anchore/syft/main/install.sh \
  | sh -s -- -b /usr/local/bin

# Сгенерировать SBOM в формате SPDX
syft dir:./src -o spdx-json > sbom.json

# Добавить SBOM в репозиторий
git add sbom.json
git commit -m "chore: add SPDX SBOM v$(date +%Y%m%d)"
git push gosh main

# Через GOSH CLI можно запросить SBOM конкретного коммита
gosh sbom \
  --dao  web3-genesis-dao \
  --repo secure-vault \
  --commit $(git rev-parse HEAD)

Задание 7.1

Запушьте SBOM в GOSH-репозиторий. Откройте app.gosh.sh, найдите файл sbom.json в коммите и скопируйте его on-chain адрес (TX hash). Это и есть неизменяемая аудиторская запись.
