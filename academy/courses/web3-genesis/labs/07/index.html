Lab 07 · The Graph: Subgraph

On-chain данные — события, вызовы функций, состояние контрактов — практически невозможно эффективно читать напрямую через RPC для аналитики или UI с историей. The Graph — это децентрализованный протокол индексирования: вы описываете subgraph (какой контракт слушать, какие события обрабатывать, в какие сущности сохранять), а Graph Node строит GraphQL API поверх проиндексированных данных. В этом лабе вы напишете subgraph для ERC-20 токена на Sepolia — от схемы до запроса в React-компоненте.

Цели лаба. После выполнения всех заданий вы сможете: инициализировать subgraph через Graph CLI; проектировать GraphQL-схему с сущностями и связями; писать subgraph.yaml манифест с event handler'ами; кодировать AssemblyScript mapping для обработки Transfer события; деплоить в The Graph Studio и отслеживать статус синхронизации; писать сложные GraphQL-запросы с сортировкой и фильтрацией; интегрировать subgraph в React с urql.

Задание 2

Замените автосгенерированную схему на полноценную с тремя сущностями: Token, Transfer, Account.

schema.graphql

type Token @entity {
  id: ID!                      # адрес контракта (lowercase hex)
  name: String!
  symbol: String!
  decimals: Int!
  totalSupply: BigInt!
  transferCount: BigInt!
}

type Account @entity {
  id: ID!                      # адрес кошелька (lowercase hex)
  balance: BigInt!             # текущий баланс токена
  transfersFrom: [Transfer!]! @derivedFrom(field: "from")
  transfersTo:   [Transfer!]! @derivedFrom(field: "to")
  transferCount: BigInt!
}

type Transfer @entity(immutable: true) {
  id: ID!                      # txHash + "-" + logIndex
  token: Token!
  from: Account!
  to: Account!
  amount: BigInt!
  blockNumber: BigInt!
  blockTimestamp: BigInt!
  transactionHash: Bytes!
}

После изменения схемы регенерируйте типы: 

graph codegen   # создаст generated/schema.ts с классами Token, Account, Transfer
graph build     # проверит корректность всего subgraph

Задание 3

Обновите subgraph.yaml манифест: укажите правильный startBlock, добавьте все нужные event handler'ы и включите вызов callHandlers.

subgraph.yaml

specVersion: 1.0.0
indexerHints:
  prune: auto
schema:
  file: ./schema.graphql
dataSources:
  - kind: ethereum
    name: ERC20
    network: sepolia
    source:
      address: "0x1c7D4B196Cb0C7B01d743Fbc6116a902379C7238"
      abi: ERC20
      # startBlock: берём блок деплоя контракта для экономии времени синхронизации
      # Найти: https://sepolia.etherscan.io/address/0x1c7D... → "Contract Creation"
      startBlock: 4000000
    mapping:
      kind: ethereum/events
      apiVersion: 0.0.7
      language: wasm/assemblyscript
      entities:
        - Token
        - Account
        - Transfer
      abis:
        - name: ERC20
          file: ./abis/ERC20.json
      eventHandlers:
        - event: Transfer(indexed address,indexed address,uint256)
          handler: handleTransfer
        - event: Approval(indexed address,indexed address,uint256)
          handler: handleApproval
      file: ./src/erc-20.ts
startBlock важен. Если указать 0 — Graph Node будет сканировать всю историю сети с блока 0, что займёт часы или дни. Всегда указывайте блок деплоя контракта. Найдите его на Etherscan в разделе «Contract Creation» для вашего контракта.

Задание 4

Напишите AssemblyScript mapping для обработки события Transfer. Mapping должен создавать или обновлять сущности Account, Token и создавать неизменяемую запись Transfer.

src/erc-20.ts

import { BigInt, Address } from "@graphprotocol/graph-ts";
import { Transfer as TransferEvent, ERC20 } from "../generated/ERC20/ERC20";
import { Token, Account, Transfer } from "../generated/schema";

// Вспомогательная функция: загрузить или создать Account
function getOrCreateAccount(address: Address): Account {
  const id = address.toHexString();
  let account = Account.load(id);
  if (account == null) {
    account = new Account(id);
    account.balance = BigInt.fromI32(0);
    account.transferCount = BigInt.fromI32(0);
  }
  return account;
}

// Вспомогательная функция: загрузить или создать Token
function getOrCreateToken(address: Address): Token {
  const id = address.toHexString();
  let token = Token.load(id);
  if (token == null) {
    // Первый раз — читаем данные из контракта через contract call
    const contract = ERC20.bind(address);
    token = new Token(id);
    token.name = contract.name();
    token.symbol = contract.symbol();
    token.decimals = contract.decimals();
    token.totalSupply = contract.totalSupply();
    token.transferCount = BigInt.fromI32(0);
  }
  return token;
}

export function handleTransfer(event: TransferEvent): void {
  const tokenAddress = event.address;

  // 1. Обновляем Token
  const token = getOrCreateToken(tokenAddress);
  token.transferCount = token.transferCount.plus(BigInt.fromI32(1));
  token.save();

  // 2. Обновляем Account "from" (уменьшаем баланс)
  const fromAccount = getOrCreateAccount(event.params.from);
  fromAccount.balance = fromAccount.balance.minus(event.params.value);
  fromAccount.transferCount = fromAccount.transferCount.plus(BigInt.fromI32(1));
  fromAccount.save();

  // 3. Обновляем Account "to" (увеличиваем баланс)
  const toAccount = getOrCreateAccount(event.params.to);
  toAccount.balance = toAccount.balance.plus(event.params.value);
  toAccount.transferCount = toAccount.transferCount.plus(BigInt.fromI32(1));
  toAccount.save();

  // 4. Создаём запись Transfer (immutable — никогда не обновляется)
  const transferId =
    event.transaction.hash.toHexString() + "-" + event.logIndex.toString();
  const transfer = new Transfer(transferId);
  transfer.token = token.id;
  transfer.from = fromAccount.id;
  transfer.to = toAccount.id;
  transfer.amount = event.params.value;
  transfer.blockNumber = event.block.number;
  transfer.blockTimestamp = event.block.timestamp;
  transfer.transactionHash = event.transaction.hash;
  transfer.save();
}

export function handleApproval(event: TransferEvent): void {
  // Для данного лаба Approval можно пропустить или добавить Allowance entity
}

Статусы синхронизации в Studio:

СтатусЗначение
SyncingGraph Node активно обрабатывает блоки, индексирует события
SyncedИндексирование завершено, данные актуальны
FailedОшибка в mapping — смотрите логи в разделе Logs
PausedИндексирование приостановлено вручную
