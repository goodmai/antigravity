Running the Course

This page is the "control panel" for instructors who want to deliver Comprehensive Rust live. Students can skim it and skip ahead — the teaching content begins on Day 1 → Hello, World.

Cadence

The full curriculum is four teaching days. We recommend splitting them across two calendar weeks (two days a week) so that students have time to absorb ownership, borrowing and traits between sessions. A typical day:

  • 09:00 – 12:00 — morning block with short breaks every 45–60 min.
  • 12:00 – 13:00 — lunch.
  • 13:00 – 16:00 — afternoon block, ending with one larger exercise.

Inside each block reserve at least 30 – 45 minutes for hands-on work. The playground cells on every lesson page double as in-class exercises: students can edit the code, break the assertions on purpose, and ask "why does this compile / not compile?".

Room & tooling

  • 15 – 25 students keeps Q&A manageable for one instructor.
  • Everyone needs a laptop with a working browser; the playground runs in the cloud, no local toolchain required to follow along.
  • Students who want offline practice should install rustup and use cargo run on the same snippets.
  • Project a clean browser window — the speaker-notes block on each page is for the instructor; show it only when you want to drop into prepared talking points.

Why assertions on every page?

This adaptation adds assert! / assert_eq! calls to every playground cell. The reason is pedagogical:

  • Students get an immediate pass/fail signal, not just "some output appeared".
  • Editing the code to break an assertion teaches the difference between a compile error and a runtime panic.
  • Asserting on values forces the lesson to commit to a concrete claim — "let x = 1 + 2; assert_eq!(x, 3);" — which is harder to misread than a bare println!.

Feedback loop for instructors

  • Before the course: walk through every lesson once and run every playground cell.
  • During the course: when several students hit the same compiler error, stop and explain it to the whole room.
  • After the course: file an issue against this repo with anything that confused students — that's the highest-signal feedback we can get.
