Control Flow Basics

Most of Rust's control-flow constructs — if, match, loop, blocks — are expressions: they evaluate to a value you can bind, return or compare. That single design choice removes a lot of incidental complexity from idiomatic Rust.

Blocks and scopes

A { … } block is itself an expression. Its value is the value of its last expression — i.e. the one without a trailing semicolon. A semicolon discards the value and yields () (the unit type).

if is an expression

Because if returns a value, the ternary operator does not exist (and is not missed). Both branches must evaluate to the same type.

match — the workhorse

match compares a value against a sequence of patterns and runs the arm of the first match. Patterns can include literals, ranges, bindings and guards. The compiler enforces exhaustiveness: forgetting a case is a compile error.

Loops: for, while, loop

for iterates over anything that implements IntoIterator — ranges, arrays, vectors, hash maps, your own types. while runs while a condition is true. loop runs forever until you break; that break can carry a value, making loop a search expression.

Functions

A function is declared with fn, parameters carry explicit types, and the return type follows ->. The body is a block, so the last expression is the return value — but you can also use return for early exits.

Macros, briefly

A trailing ! means "this is a macro invocation". Macros are expanded before the compiler does normal type-checking, which is how println! can accept a variable number of typed arguments. You'll write your own much later; for now treat println!, format!, vec!, and the assert*! family as language primitives.

Exercise: Collatz length

Starting from a positive integer n, the Collatz iteration says: if n is even, divide by 2; if odd, replace by 3n+1. The conjecture (still unproven!) is that you always reach 1. Implement collatz_length, the number of steps to reach 1. collatz_length(1) is 0.
