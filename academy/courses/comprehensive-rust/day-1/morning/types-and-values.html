Types and Values

Rust is statically typed: every value has a type that is known at compile time, and the compiler refuses to mix incompatible types implicitly. In return, you get fast code and a strong safety net.

Variables and immutability

A let binding introduces a new name. By default the binding is immutable — once assigned, you cannot change the value behind it. Add mut to opt into mutation.

Primitive types

  • Signed integers: i8, i16, i32, i64, i128, isize.
  • Unsigned integers: u8 … u128, usize.
  • Floats: f32, f64.
  • Booleans: bool — exactly true or false.
  • Characters: char — a 4-byte Unicode scalar value.

Arithmetic, overflow and division

Rust does not perform implicit numeric conversions. 1u32 + 1u64 does not compile — you must cast with as or rewrite. In debug builds, integer overflow panics; in release builds it wraps. Use the explicit checked_*, wrapping_*, saturating_* or overflowing_* methods when you want a defined behaviour.

Type inference

You can almost always omit the type annotation on a let and let the compiler infer it from how the value is used. When you do need to help the compiler, the annotation goes after the name (let x: i32 = …) or on the literal (123_i64, 1.5_f32).
