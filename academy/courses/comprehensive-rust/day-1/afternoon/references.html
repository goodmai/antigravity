References & Slices

A reference is a non-owning pointer to a value somewhere else. Rust has two flavours: &T (a shared / read-only reference) and &mut T (an exclusive / mutable reference). The borrow checker enforces a simple but powerful rule: at any moment a value can have either any number of shared references or exactly one exclusive reference — never both.

Shared references — &T

Exclusive references — &mut T

Slices

A slice &[T] is a reference to a contiguous run of elements: a pair of (pointer, length). Slices are how you write generic code that works on arrays, vectors, or any contiguous storage. &str is the slice version of a UTF-8 string.

&str vs String

&str is a borrowed view of UTF-8 text — most string literals are &'static str. String is a heap-allocated, growable, owned UTF-8 buffer. Prefer &str in function parameters: it accepts both a literal and a borrow of a String.

Reference validity

The borrow checker statically rejects references that would outlive the value they point to. The example below compiles because the slice we return borrows from the input — and the input outlives the call.

(a: &''a str, b: &''a str) -> &''a str { let mut i = 0; let ab = a.as_bytes(); let bb = b.as_bytes(); while i < ab.len() && i < bb.len() && ab[i] == bb[i] { i += 1; } &a[..i] } fn main() { assert_eq!(longest_prefix("foobar", "foobaz"), "fooba"); assert_eq!(longest_prefix("rust", "ruby"), "ru"); assert_eq!(longest_prefix("xyz", "abc"), ""); }'>
