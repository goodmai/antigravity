Лаба 01: Полигон режимов агента

🔗 Практика к Уроку 1 — Режимы агента Antigravity

В этой лабе ты на практике почувствуешь разницу между Planning, Fast и Turbo режимами, научишься выбирать режим под задачу и закреплять правила проекта.

🎯 Цель

Закрепить материал Урока 1 через 8 практических задач в облачной песочнице GitHub. Каждая задача имеет явный критерий приёмки — лаба считается сданной, когда выполнен финальный чек-лист.

🧪 Песочница (мультиплатформа)

Рекомендуется для этой лабы: GitHub Codespaces — полноценный Linux + Docker + GitHub PR-флоу, универсальна для любой задачи.

Любую задачу можно выполнить в одной из песочниц (быстрый запуск):

  • GitHub Codespaces — https://github.com/goodmai/antigravity → Code ▾ → Codespaces → Create
  • Gitpod — https://gitpod.io/#https://github.com/goodmai/antigravity
  • github.dev — открой репозиторий и нажми клавишу .
  • Replit — Create Repl → Import from GitHub

Полная шпаргалка (bootstrap-скрипт, devcontainer, секреты, выбор платформы): ../SANDBOX_SETUP.md.

# единый вход в любой песочнице
bash scripts/sandbox-bootstrap.sh

📋 Задачи

Задача 1 — Карта режимов

Цель: Свести режимы агента в собственную таблицу решений.

Шаги:

  1. Создай notes/modes.md.
  2. Опиши Planning / Fast / Turbo: когда применять, риски, выигрыш.
  3. Добавь колонку «пример задачи из реальной работы».

Критерий приёмки: Файл содержит таблицу 3×4 с конкретными примерами для каждого режима.

Задача 2 — Planning в действии

Цель: Прогнать сложную задачу через Planning Mode.

Шаги:

  1. Попроси агента в Planning-режиме добавить REST-эндпоинт /health с тестом.
  2. Сохрани сгенерированный implementation_plan.md.
  3. Прокомментируй минимум 1 шаг плана и попроси переработать.

Критерий приёмки: В репозитории есть implementation_plan.md с твоей правкой и финальной реализацией.

Задача 3 — Fast против Planning

Цель: Замерить разницу подходов на простой задаче.

Шаги:

  1. Та же задача (переименование переменной) в Fast и в Planning.
  2. Зафиксируй число шагов и время в notes/compare.md.

Критерий приёмки: В compare.md обоснован вывод, когда Planning избыточен.

Задача 4 — Глобальные правила

Цель: Настроить правила уровня пользователя.

Шаги:

  1. Создай ~/.gemini/GEMINI.md с языком общения и стилем кода.
  2. Проверь, что новый ответ агента следует правилу.

Критерий приёмки: Ответ агента соблюдает заданный стиль/язык.

Задача 5 — Правила проекта

Цель: Закрепить контекст в репозитории.

Шаги:

  1. Создай .agent/rules/project.md с архитектурными ограничениями проекта.
  2. Задай задачу, нарушающую правило, и проверь реакцию агента.

Критерий приёмки: Агент ссылается на правило проекта при конфликте.

Задача 6 — Turbo с подстраховкой

Цель: Безопасно применить автономный режим.

Шаги:

  1. Убедись, что git-дерево чистое.
  2. В Turbo выполни массовое переименование в 3+ файлах.
  3. Сделай git diff, при ошибке — git reset --hard.

Критерий приёмки: Изменения проверены через diff; описан план отката.

Задача 7 — Деградация режима

Цель: Смоделировать неудачный выбор режима.

Шаги:

  1. Дай агенту архитектурную задачу в Fast-режиме.
  2. Опиши в notes/postmortem.md, что пошло не так и почему Planning был нужен.

Критерий приёмки: Постмортем содержит причинно-следственный анализ.

Задача 8 — Чеклист выбора режима

Цель: Сделать переиспользуемый артефакт.

Шаги:

  1. На основе задач 1–7 собери notes/mode-checklist.md — дерево решений из 5+ пунктов.

Критерий приёмки: Чеклист применим к новой незнакомой задаче без правок.
