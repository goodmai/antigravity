📋 Задачи

Задача 1 — Тестовое приложение

Цель: Поднять цель для визуальных проверок.

Шаги:

  1. Создай мини-страницу с формой регистрации (HTML+JS).
  2. Запусти python3 -m http.server 8080.
  3. Открой preview песочницы.

Критерий приёмки: Страница доступна по проброшенному порту.

Задача 2 — Визуальная навигация

Цель: Кликать по визуальным меткам.

Шаги:

  1. Попроси Browser Subagent открыть страницу и нажать «синюю кнопку Отправить».
  2. Без указания селектора — только по визуальному описанию.

Критерий приёмки: Агент выполнил клик по описанию, не по id.

Задача 3 — Эмуляция устройства

Цель: Проверить адаптивность.

Шаги:

  1. Переключи эмуляцию на мобильное разрешение.
  2. Сделай скриншот формы.

Критерий приёмки: Скриншот мобильной версии приложён к отчёту.

Задача 4 — Визуальная дефектовка

Цель: Найти баг вёрстки.

Шаги:

  1. Внеси CSS-дефект (наложение текста на кнопку).
  2. Попроси агента визуально найти проблему.

Критерий приёмки: Агент описал дефект по скриншоту, не по коду.

Задача 5 — DevTools Console

Цель: Диагностировать JS-ошибку.

Шаги:

  1. Добавь баг, бросающий ошибку в консоль.
  2. Агент читает Console через DevTools Protocol.

Критерий приёмки: Ошибка извлечена из консоли с точной строкой.

Задача 6 — DevTools Network

Цель: Поймать сбойный запрос.

Шаги:

  1. Сэмулируй запрос, возвращающий 404.
  2. Агент анализирует вкладку Network.

Критерий приёмки: Сбойный запрос идентифицирован (URL, статус).

Задача 7 — E2E без кода

Цель: Пройти пользовательский путь.

Шаги:

  1. Сценарий: открыть → заполнить форму → отправить → проверить успех.
  2. Сформулируй его агенту на естественном языке.

Критерий приёмки: Сценарий пройден агентом до конечного состояния.

Задача 8 — Авто-фикс фронтенда

Цель: Замкнуть цикл диагностика→правка.

Шаги:

  1. По найденной в Console ошибке попроси агента исправить JS.
  2. Повторно прогони E2E-сценарий.

Критерий приёмки: После фикса сценарий проходит без ошибок в консоли.

Задача 9 — Отчёт визуального QA

Цель: Собрать артефакт.

Шаги:

  1. Сведи скриншоты, найденные дефекты и фиксы в qa/visual-report.md.

Критерий приёмки: Отчёт воспроизводим: шаги→ожидание→факт→скриншот.
