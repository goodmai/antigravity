Лаба 15: CI/CD генерация пайплайнов

🔗 Практика к Уроку 15 — CI/CD Pipeline Generation

Генерируем безопасные пайплайны GitHub Actions с keyless-аутентификацией.

🎯 Цель

Закрепить материал Урока 15 через 7 практических задач в облачной песочнице GitHub. Каждая задача имеет явный критерий приёмки — лаба считается сданной, когда выполнен финальный чек-лист.

🧪 Песочница (мультиплатформа)

Рекомендуется для этой лабы: GitHub Codespaces — полноценный Linux + Docker + GitHub PR-флоу, универсальна для любой задачи.

Любую задачу можно выполнить в одной из песочниц (быстрый запуск):

  • GitHub Codespaces — https://github.com/goodmai/antigravity → Code ▾ → Codespaces → Create
  • Gitpod — https://gitpod.io/#https://github.com/goodmai/antigravity
  • Google Cloud Shell — https://shell.cloud.google.com → git clone
  • github.dev — открой репозиторий и нажми клавишу .

Полная шпаргалка (bootstrap-скрипт, devcontainer, секреты, выбор платформы): ../SANDBOX_SETUP.md.

# единый вход в любой песочнице
bash scripts/sandbox-bootstrap.sh

📋 Задачи

Задача 1 — PR-проверка

Цель: Сгенерировать базовый CI.

Шаги:

  1. Агент создаёт .github/workflows/pr.yml (checkout→setup→lint→test).

Критерий приёмки: Workflow синтаксически валиден.

Задача 2 — Кэш зависимостей

Цель: Ускорить пайплайн.

Шаги:

  1. Добавь cache для npm/pip.

Критерий приёмки: Кэш-ключ зависит от lock-файла.

Задача 3 — Матрица

Цель: Тест на нескольких версиях.

Шаги:

  1. Matrix по версиям Node/Python.

Критерий приёмки: Джоба гоняется в матрице.

Задача 4 — Покрытие

Цель: Отправлять coverage.

Шаги:

  1. Шаг репорта покрытия.

Критерий приёмки: Отчёт формируется как артефакт.

Задача 5 — Keyless деплой

Цель: Безопасная аутентификация.

Шаги:

  1. OIDC/Workload Identity вместо JSON-ключей.

Критерий приёмки: В секретах нет долгоживущих ключей.

Задача 6 — Гейты

Цель: Блокировать мердж при красном.

Шаги:

  1. Опиши required checks в notes/branch-protection.md.

Критерий приёмки: Описана политика защиты ветки.

Задача 7 — Релиз

Цель: Автоматизировать релиз.

Шаги:

  1. Workflow на тег: build+release notes.

Критерий приёмки: Тег запускает релизный пайплайн.
