Лаба 19: SDLC микросервисов с AI-агентами

🔗 Практика к Уроку 19 — Комплексный SDLC Микросервисов

Сквозной жизненный цикл сервиса: от спеки и прототипа до CI, наблюдаемости и DR. Это мост к капстоуну (CAPSTONE).

🎯 Цель

Закрепить материал Урока 19 через 9 практических задач в облачной песочнице GitHub. Каждая задача имеет явный критерий приёмки — лаба считается сданной, когда выполнен финальный чек-лист.

🧪 Песочница (мультиплатформа)

Рекомендуется для этой лабы: GitHub Codespaces — полноценный Linux + Docker + GitHub PR-флоу, универсальна для любой задачи.

Любую задачу можно выполнить в одной из песочниц (быстрый запуск):

  • GitHub Codespaces — https://github.com/goodmai/antigravity → Code ▾ → Codespaces → Create
  • Gitpod — https://gitpod.io/#https://github.com/goodmai/antigravity
  • Google Cloud Shell — https://shell.cloud.google.com → git clone
  • Replit — Create Repl → Import from GitHub

Полная шпаргалка (bootstrap-скрипт, devcontainer, секреты, выбор платформы): ../SANDBOX_SETUP.md.

# единый вход в любой песочнице
bash scripts/sandbox-bootstrap.sh

📋 Задачи

Задача 1 — Спецификация

Цель: Описать сервис и контракты.

Шаги:

  1. spec/service.md: API, данные, SLA, ошибки.
  2. Опиши паттерны устойчивости (Circuit Breaker, Retry).

Критерий приёмки: Спека покрывает happy-path и режимы отказа.

Задача 2 — Прототип Identity

Цель: Поднять auth-сервис.

Шаги:

  1. Минимальный auth с выдачей токена.

Критерий приёмки: Токен выдаётся и валидируется.

Задача 3 — Доменный сервис

Цель: Реализовать ядро.

Шаги:

  1. Сервис с бизнес-логикой и /health.

Критерий приёмки: Юнит-тесты ядра зелёные.

Задача 4 — Очередь и ETL

Цель: Асинхронный пайплайн.

Шаги:

  1. Producer→queue→worker, at-least-once.

Критерий приёмки: Сообщение обрабатывается ≥1 раз без потерь.

Задача 5 — Устойчивость

Цель: Backoff и DLQ.

Шаги:

  1. Экспоненциальный backoff, dead-letter после N.

Критерий приёмки: Сбойное сообщение уходит в DLQ, не зацикливается.

Задача 6 — Контейнеризация

Цель: Собрать и связать.

Шаги:

  1. Dockerfile + compose для всех сервисов.

Критерий приёмки: compose up поднимает систему целиком.

Задача 7 — CI пайплайн

Цель: Автоматизировать проверки.

Шаги:

  1. .github/workflows: lint+test+build образов.

Критерий приёмки: Пайплайн зелёный на чистой ветке.

Задача 8 — Наблюдаемость

Цель: Логи и метрики.

Шаги:

  1. Структурные логи + /metrics.

Критерий приёмки: Метрики снимаются, логи коррелируются по trace-id.

Задача 9 — Disaster Recovery

Цель: План восстановления.

Шаги:

  1. spec/dr.md: состояние в БД, идемпотентность, рестарт.

Критерий приёмки: Описан сценарий восстановления без потери данных.
