# Архитектурная оценка миграции Daskibo DRM с Lit Protocol на Threshold Network (T) и Secret Network (SCRT)

В данном документе представлена глубокая техническая оценка сложности, архитектурного оверхеда и пользовательского опыта (UX) при потенциальном переносе DRM-слоя (управления ключами) Daskibo с **Lit Protocol v3** на альтернативные децентрализованные криптографические решения:
1.  **Threshold Network (T) — технология TACo (Threshold Access Control)**.
2.  **Secret Network (SCRT) — TEE-based L1 на базе Cosmos SDK / CosmWasm**.

---

## 1. Технологическое сопоставление стеков

Ниже приведена сравнительная матрица трех архитектурных подходов при интеграции в кросс-чейн стек Daskibo (BSC + opBNB + Greenfield + Arweave):

| Параметр сравнения | Lit Protocol v3 (Текущий стек) | Threshold Network (TACo) | Secret Network (SCRT) |
| :--- | :--- | :--- | :--- |
| **Криптографический базис** | TEE-MPC (AMD SEV) + TSS / BLS | Proxy Re-Encryption (PRE) + Umbral | TEE-Smart Contracts (Intel SGX) + CosmWasm |
| **Доверие аппаратному слою** | **Да** (Требует TEE-ноды) | **Нет** (Чистая математика на `secp256k1`) | **Да** (Требует Intel SGX) |
| **Необходимость кросс-чейн мостов**| **Нет** (Опрашивает RPC любых сетей напрямую через Lit Actions) | **Нет** (TACo-ноды опрашивают RPC любых EVM-сетей напрямую) | **Да** (Требует мостов Axelar/IBC или Secret Path для EVM-связи) |
| **Поддержка кастомных JS-правил** | **✅ Да (Lit Actions)** — опрос любых web-API и RPC в рантайме | ✖ **Нет** (Поддерживает только жестко заданные EVM-правила) | ✖ **Нет** (Только ончейн Rust-логика смарт-контракта) |
| **UX / Скорость дешифрации** | **Сверхбыстро** (<0.5-1 сек, оффчейн-сборка долей ключа в TEE) | **Быстро** (1-2 сек, сборка `cfrags` клиентом) | *Медленно* (1-3 мин из-за кросс-чейн OPL/IBC мостов с EVM) |
| **Сложность миграции (Daskibo)**| *Базовая (Реализована)* | **Средняя** (Замена JS SDK фасадов на TACo Web SDK) | **Очень высокая** (Перезапуск экономики в Cosmos, OPL-мосты, Rust) |

---

## 2. Глубокий анализ варианта 1: Миграция на Threshold Network (T - TACo)

Технология **TACo (Threshold Access/Action Control)** построена на математически чистой схеме **Proxy Re-Encryption (PRE)** на базе криптографической библиотеки **Umbral**.

### Как бы выглядел Daskibo DRM на Threshold TACo:
1.  **Шифрование контента**: Автор шифрует видеокурс симметричным ключом $DEK$. Затем он зашифровывает сам $DEK$ под своим публичным ключом.
2.  **Гейтинг условий**: Автор создает фрагменты ключа перешифрования (*kfrags*), связывающие его публичный ключ с публичным ключом покупателя (Bob) при выполнении условий (например, владение SBT на opBNB). Эти фрагменты распределяются по узлам сети Threshold (ноды *Ursula*).
3.  **Дешифрация**: Ноды проверяют баланс SBT на opBNB через прямой RPC-запрос. Если условие выполнено, ноды трансформируют шифртекст $DEK$ (создают *cfrags*) без раскрытия приватных ключей и самого $DEK$. Bob собирает $M$ из $N$ долей *cfrags* и расшифровывает контент своим приватным ключом.

### Оценка сложности миграции: **Средняя (Medium)**
*   **Плюсы**:
    1.  **Математическая чистота (No-TEE)**: Отсутствие риска аппаратных бэкдоров процессоров Intel/AMD.
    2.  **Отсутствие мостов**: TACo поддерживает чтение EVM-условий из любых сетей напрямую. Состояние маркетплейса на BSC и токены SBT на opBNB проверяются нодами без отправки тяжелых транзакций через мосты.
*   **Минусы (Критический блокирующий фактор)**:
    1.  **Отсутствие эквивалента Lit Actions**: В TACo невозможно написать динамическую логику выполнения JavaScript. Мы ограничены базовыми условиями (владение токеном, баланс ERC-20, вызов `view`-функции Solidity). Мы **не можем** опрашивать внешние AI-оракулы, проверять подписи Web2 OAuth или динамически обфусцировать метаданные на лету.
    2.  **Сложность отзыва прав (Revocation)**: При отзыве прав (например, истечение срока действия аренды SBT) автору необходимо генерировать новые пары ключей и обновлять `kfrags` на нодах, что создает огромный вычислительный оверхед на клиенте. В Lit Protocol это решается тривиальным изменением возвращаемого значения Solidity-функции или проверкой времени в Lit Actions.

## 3. Глубокий анализ варианта 2: Миграция на Secret Network (SCRT)

**Secret Network** — это L1 блокчейн на базе Cosmos SDK, где все вычисления в смарт-контрактах происходят конфиденциально внутри TEE-анклавов Intel SGX.

### Как бы выглядел Daskibo DRM на Secret Network:
Для интеграции с нашей EVM-экосистемой (BSC + Greenfield + opBNB) Secret Network предлагает технологию **Secret Path** (децентрализованный кросс-чейн мост).
1.  Студент покупает курс на BSC / opBNB.
2.  BSC отправляет кросс-чейн сообщение (через Axelar/IBC) на Secret Network.
3.  Контракт на Secret Network (написанный на Rust/CosmWasm) регистрирует покупку, шифрует сессионный ключ под публичным ключом студента и отправляет его обратно через мост.

### Оценка сложности миграции: **Очень высокая / Оверхед (Very High / Overkill)**
*   **Плюсы**:
    1.  Полноценная ончейн-приватность в Cosmos-экосистеме.
*   **Минусы (Полностью дублируют проблемы Oasis ROSE)**:
    1.  **Кросс-чейн Latency**: Необходимость прохождения транзакций через Axelar/IBC мосты добавляет задержку в **1.5–3 минуты** при каждой покупке/авторизации контента. Это полностью убивает UX потокового воспроизведения видео.
    2.  **Двойной газ и управление токенами**: Авторам и пользователям придется держать балансы в токенах **SCRT** для оплаты газа на дешифрацию и транзитных токенах для мостов.
    3.  **Переход на Rust/CosmWasm**: Потребуется полностью переписать Solidity-смарт-контракты и сложную логику гейтинга на Rust.

## 4. Сводный архитектурный вердикт

> [!IMPORTANT]
> **Lit Protocol v3 (Chipotle) остается безальтернативным лидером** для DRM-архитектуры Daskibo:
> 
> 1.  **Secret Network (SCRT)** — имеет тот же колоссальный недостаток, что и **Oasis (ROSE)**: необходимость тяжелых кросс-чейн мостов между L2 (opBNB/BSC) и L1 (Cosmos/Secret), что делает систему медленной, сложной и дорогой.
> 2.  **Threshold Network (TACo / T)** — является прекрасной, математически чистой альтернативой без TEE, но **полное отсутствие аналога Lit Actions** (выполнения динамического JS в TEE-песочнице) лишает Daskibo возможности масштабирования в конфиденциальные ИИ-вычисления, интеграции с Web2-соцсетями и гибкого динамического отзыва прав доступа.
> 
> **Финальное решение**: Сохранить **Lit Protocol v3 в качестве центрального ядра управления ключами**, используя его уникальную песочницу **Lit Actions** для мультичейн-авторизации без мостов.
